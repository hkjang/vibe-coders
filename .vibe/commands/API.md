새 API 엔드포인트를 기존 프로젝트 스타일에 맞게 추가합니다.

사용자에게 물어보세요:
- **메서드 + 경로** (예: POST /api/orders)
- **요청/응답 스키마**
- **인증 방식** (이미 있다면 그것 사용)
- **권한** (어떤 역할이 호출 가능한지)

자동 추가 항목:
1. **라우터 등록** — 기존 라우터 파일에 한 줄 추가
2. **핸들러 함수** — try/catch + 표준 에러 응답 패턴
3. **입력 검증** — zod / joi / class-validator 등 프로젝트 사용 중인 것
4. **OpenAPI/Swagger 주석** — 있다면 자동 갱신
5. **단위 테스트** — happy path + 검증 실패 + 권한 실패 + 에러 케이스
6. **API 호출 예시** — README 또는 docs 폴더에 curl 예시

품질 체크:
- 응답 형식이 기존 엔드포인트와 일관되는지
- 에러 코드/메시지가 한국어로 잘 노출되는지
- N+1 쿼리 같은 명백한 성능 이슈 없는지
- rate limit / pagination 적용 여부 확인

응답은 한국어로. 결과 파일 목록과 테스트 실행 명령을 끝에 표시.
