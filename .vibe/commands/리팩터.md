---

다음 단계로 리팩터링을 진행합니다.

1. **현재 동작 파악** — 관련 테스트가 있는지 확인. 없으면 먼저 특성 테스트(characterization test) 작성 제안.

2. **리팩터 후보 식별**:
   - 긴 함수 분해
   - 중복 코드 추출
   - 매직 넘버/스트링 → 상수
   - 깊은 중첩 → guard clause
   - 명확한 이름으로 변경
   - 사이드 이펙트 격리

3. **안전 검증 순서**:
   - 매 변경마다 테스트 통과 확인
   - 동작 변화 없는지 (refactor는 behavior preserving)
   - 공개 API 변경 시 호출처 영향 분석

4. **변경 범위 제한**:
   - 한 번에 한 가지 종류의 리팩터만
   - 큰 리팩터는 작은 커밋으로 분할

응답에 포함:
- 적용한 리팩터 종류 (목록)
- 변경 전후 비교 (간단한 예시)
- 검증 결과 (테스트 통과 여부)
- 후속 리팩터 제안 (선택)

규칙:
- 사용자 동의 없이 공개 API 시그니처 변경 금지
- 테스트 비활성화 금지
- 한국어로 응답
