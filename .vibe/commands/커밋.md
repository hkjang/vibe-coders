description: 현재 변경사항을 보고 한국어 conventional commit 메시지를 작성합니다.
---

다음 절차를 따르세요.

1. `git status` 와 `git diff --staged` (스테이징된 변경) 또는 `git diff` (스테이징 안 된 변경) 실행.
2. 변경 내용을 분석해 다음 카테고리 중 하나 선택:
   - `feat:` 새 기능
   - `fix:` 버그 수정
   - `refactor:` 동작 변화 없는 구조 개선
   - `perf:` 성능 개선
   - `test:` 테스트 추가/수정
   - `docs:` 문서만 변경
   - `chore:` 빌드/설정/의존성
   - `style:` 포매팅만
3. 다음 형식으로 메시지 작성:

```
<type>: <한국어 한 줄 요약 50자 이내>

<왜 이 변경이 필요했는지 한국어 2-3줄 설명>

<관련 이슈가 있으면 끝에 #123 추가>
```

4. **사용자에게 메시지를 먼저 보여주고 확인을 받은 후**에 `git commit -m "..."` 실행.
5. 메시지는 절대 비밀 정보 (API 키, 주민번호 등) 를 포함하지 않도록 검토.

규칙:
- 제목은 동사로 끝내지 말고 명사형으로 (`사용자 인증 추가` O, `사용자 인증을 추가했다` X)
- "what" 보다 "why" 우선
- 여러 무관한 변경이 섞여 있으면 분리 커밋 제안
- 사용자 확인 전에는 절대 commit 실행하지 않음
