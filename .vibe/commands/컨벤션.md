description: 워크스페이스의 코딩 스타일을 분석해 .vibe/rules-code.md 자동 생성.
---

워크스페이스를 분석하여 이 프로젝트의 컨벤션을 추출하고 `.vibe/rules-code.md` 또는 `.vibe/rules-code/conventions.md` 로 저장합니다.

분석 단계:

1. **빌드/설정 파일 점검**:
   - `.editorconfig`, `.prettierrc*`, `.eslintrc*`, `tsconfig.json`, `pyproject.toml`, `.rustfmt.toml`, `gofmt` 사용 여부
   - 패키지 매니저 (`package-lock.json` / `yarn.lock` / `pnpm-lock.yaml` / `bun.lockb`)
   - Lock 파일로 Node.js 버전 (`.nvmrc`, `engines`)

2. **샘플 파일 검토 (각 주요 폴더에서 2-3개씩)**:
   - 들여쓰기 (탭/스페이스, 폭)
   - 따옴표 (작은/큰)
   - 세미콜론 사용 여부
   - 네이밍 (camelCase/snake_case/kebab-case)
   - 임포트 정렬 방식
   - 주석 스타일 (JSDoc/한국어/영어)
   - 에러 처리 패턴 (try/catch vs Result vs Either)
   - 비동기 (Promise.then vs async/await)
   - 폴더 구조 패턴 (feature-based vs layer-based)

3. **테스트 컨벤션**:
   - 테스트 위치 (`__tests__/`, `*.test.ts`, `_test.go`)
   - 어서션 라이브러리
   - mock 방식

4. **결과 파일 형식**:

```markdown
# 코드 컨벤션

(자동 생성: <KST 시각>)

## 들여쓰기
- 폭: <2 spaces / 4 spaces / tab>

## 네이밍
- 변수/함수: <camelCase>
- 상수: <UPPER_SNAKE>
- 파일: <kebab-case>
- 클래스: <PascalCase>

## 스타일
- 따옴표: <single>
- 세미콜론: <required>
- 줄 너비: <100>

## 임포트
- 정렬: <외부 → 절대 → 상대>
- 그룹 사이 빈 줄: <필수>

## 비동기
- <async/await 만 사용>

## 에러 처리
- <try/catch + 명시적 에러 클래스>

## 주석
- <한국어 JSDoc>

## 테스트
- 위치: <co-located *.test.ts>
- 어서션: <vitest expect>
- mock: <vi.mock>

## 폴더 구조
- 패턴: <feature-based>
- 핵심 폴더:
  - <src/features/...>
  - <src/shared/...>
```

5. 생성 후 사용자에게 검토를 요청. 마음에 들면 그대로 두고, 수정이 필요하면 알려달라고 안내.

이 파일은 시스템 프롬프트의 "Rules" 섹션에 자동 주입되어 모든 후속 작업이 이 컨벤션을 따르게 합니다.

한국어로 응답.
