# 신규 콘솔 인수 검증표

이 문서는 사용자 요구사항의 최종 인수 기준과 필수 브라우저 시나리오를 실제 구현·검사 근거에 연결한다.
기준선은 `v0.86.8` 개발 헤드이며, 새 기능은 관련 검사를 통과한 뒤 표를 갱신한다.
기능 등록 36개, API 선언 격차 0, 전체 테스트 통과만으로 기능 동등성이나 Stable 승격을 선언하지 않는다.

## 근거 해석

- **회귀 근거 있음**: 해당 구현과 자동 검사가 있다. 특정 릴리즈의 CI 통과 여부는 그 릴리즈 커밋으로 별도 확인한다.
- **부분 검증**: 일부 구현·검사는 있으나 전체 인수 조건을 입증하지 못한다.
- **잔여 작업**: 실제 누락된 기능 또는 보호 절차를 확인했다.
- Playwright의 기존 `web/tests/e2e` 검사는 API 응답을 가로채는 UI 흐름 검사다. 별도의 Go 단위·통합 검사가
  통과하더라도 실제 브라우저부터 Go 인증·DB까지 이어진 동일 실행의 증거로 합치지 않는다.
- `web/tests/auth-live`는 내장 React 애셋과 실제 Go 서버·임시 SQLite·로컬 OIDC 공급자를 연결한다.
  인증 응답을 합성하지 않으며, 늦은 응답 검사는 실제 응답 한 건을 지연 후 그대로 전달한다.
  실행 방법과 범위는 [실제 인증 브라우저 검증](APP_UI_AUTH_BROWSER_TESTING.md)에 기록한다.
- 기능별 운영 Preview 사용자 검증, 안정성 관측 기간·목표, 허용 복귀율과 Stable 승격은 별도 운영 의사결정이다.
  테스트 개수나 선택적 방문 집계만으로 자동 승인하지 않는다.

## 다음 구현·검증 순서

1. 미저장 변경 보호 확대: 공통 `FormDialog`는 `v0.86.4`, 콘솔 전환·개별 설정은 `v0.86.5`에서
   단위·브라우저 검증을 추가했다. SSO·알림은 `v0.86.6`에서 조회 갱신·저장 결과·비밀 폐기 보호를
   검증했다. 이미 발급된 API 키의 별도 스코프 수정창 등 남은 자체 편집창과 인라인 저장 폼을
   구분해 적용한다. 역할 편집·API 키 신규 발급의 스코프는 공통 폼 보호에 포함한다.
   입력값·Secret을 브라우저 영속 저장소로 복구하지 않으며, 검색/필터·시뮬레이션 입력을
   모두 저장 폼으로 간주하지 않는다.
2. 실제 인증 브라우저 검증 확대: `v0.86.7`에 격리 DB/로컬 IdP와 로그인·SSO·단일 갱신,
   다른 탭 로그아웃·새 계정·늦은 실제 응답 격리와 실제 갱신 거부 후 로그인 복귀 검사를 추가했다.
   다른 Query Cache 데이터, HTTPS 교차 사이트와 실제 Keycloak 호환성을 추가 확인한다.
   운영 인증 설정이나 계정은 변경하지 않는다.
3. 공급자 삭제와 라우팅·정책 변경 검토: `v0.86.8`에서 공급자 대상 재입력·공개 설정 비교·
   검토 요청 고정·다시 편집 시 검토 무효화를 추가한다. 비밀값·마스킹된 식별자를 보존하는
   실제 참조 영향 조회와 동시 변경 검사는 잔여다. 기존 서버 권한·감사는 유지한다.
   `provider-review.spec.ts`는 검토 요청·재편집·정수 검증·오류/재시도·대상 재입력·뒤로가기·
   390px 다크/키보드/axe와 사용자 정의 비밀키 접두어·비공개 URL 유지를 확인하는 API fixture 기반
   공급자 시나리오이며 실제 서버 변경 증거는 아니다.
4. 정책 일괄 가져오기·게이트웨이 키 회전: 일부 항목만 반영되지 않는 서버 계약과 백업·복구·다중
   pod 전환 검증을 먼저 설계한다. 개인 API Key 회전을 서버 비밀키 회전 완료로 세지 않는다.
5. 데이터 정합성·대규모 목록·실제 성능 및 운영 Preview 근거를 모은 뒤 기능별 승격을 검토한다.

### 편집 보호의 다음 적용 경계

- `ConsoleFeatureDialog`와 `SettingDetailSheet` 및 복구 사유창은 `v0.86.5` 보호 대상이다.
  값·사유·되돌리기 전환, 열린 초안의 버전 고정, 409 초안 유지, 503 저장 완료 후 재전송 금지와
  롤백 이력 검사를 별도로 검증한다. 이 근거를 아직 보호하지 않은 폼에 확대 적용해 해석하지 않는다.
- 단건 설정 저장·기본값 되돌리기는 기존 버전 검사를 사용한다. 롤백에 추가한 시각·이력 세대
  검사가 이 두 API의 삭제·재생성 충돌까지 해결한 것은 아니므로 별도 계약 보강 대상으로 추적한다.
- SSO·알림 폼의 `key=dataUpdatedAt` 재생성을 제거하고 수정·확인·저장 중 스냅샷 고정, 비밀 입력
  폐기, 늦은 조회·저장 응답 격리를 `v0.86.6`에서 검증했다. SSO 값·버전은 같은 DB 레코드에서
  조회하고 알림 저장은 한 트랜잭션으로 묶는다. UI 흐름 검사와 별도의 SQLite/PostgreSQL 검사는
  실제 인증 서버 브라우저 E2E가 아니다. SSO DB 조회는 로그인 런타임·모든 파드 활성 증거가 아니며,
  알림 설정에는 관리자 간 동시 편집을 감지하는 버전 검사가 없다.
- 비용 보호, 앱 접근 권한, 스킬 평가 근거, 요청 메모, 레드팀 일정 및 기존 API 키 스코프 수정도
  영속 저장 초안이다. 런타임 설정의 검색 폼, 필터, 시뮬레이션과 실행 확인창은 별도 분류한다.

이 순서는 위험을 줄이는 개발 계획이며 앞 단계 검사가 실패한 상태에서 운영 변경이나 다음 단계
Stable 승격을 진행해도 된다는 허가가 아니다. `/admin`은 계속 유지한다.
