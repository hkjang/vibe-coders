# 신규 콘솔 인수 검증표

이 문서는 사용자 요구사항의 최종 인수 기준과 필수 브라우저 시나리오를 실제 구현·검사 근거에 연결한다.
출고 기준선은 [`v0.86.44`](https://github.com/hkjang/vibe-coders/releases/tag/v0.86.44)다.
v42의 최초 인증 CI 실패·보류·후속 보완과 v43 검토 상태 기록의 출고 전 보완 이력을 보존한다.
현재 `v0.86.45` XView 개발 후보의 예비 집중 검사·최종 버전 로컬 검사와 아직 완료하지 않은 원격/출고 게이트를 구분한다.
공개 게시만으로 개별 검사나 운영 인수를 추정하지 않는다.
기능 등록 36개, API 선언 격차 0, 전체 테스트 통과만으로 기능 동등성이나 Stable 승격을 선언하지 않는다.

## 근거 해석

- **회귀 근거 있음**: 해당 구현과 자동 검사가 있다. 특정 릴리즈의 CI 통과 여부는 그 릴리즈 커밋으로 별도 확인한다.
- **부분 검증**: 일부 구현·검사는 있으나 전체 인수 조건을 입증하지 못한다.
- **잔여 작업**: 실제 누락된 기능 또는 보호 절차를 확인했다.
- Playwright의 기존 `web/tests/e2e` 검사는 API 응답을 가로채는 UI 흐름 검사다. 별도의 Go 단위·통합 검사가
  통과하더라도 실제 브라우저부터 Go 인증·DB까지 이어진 동일 실행의 증거로 합치지 않는다.
- `web/tests/auth-live`는 내장 React 애셋과 실제 Go 서버·임시 SQLite·로컬 OIDC 공급자를 연결한다.
  키 권한 검사에는 로컬 합성 모델 응답기를 사용하지만 인증·관리 API 응답은 합성하지 않는다.
  늦은 응답 검사는 실제 응답 한 건을 지연 후 그대로 전달한다.
  실행 방법과 범위는 [실제 인증 브라우저 검증](APP_UI_AUTH_BROWSER_TESTING.md)에 기록한다.
- 기능별 운영 Preview 사용자 검증, 안정성 관측 기간·목표, 허용 복귀율과 Stable 승격은 별도 운영 의사결정이다.
  테스트 개수나 선택적 방문 집계만으로 자동 승인하지 않는다.

## 확인된 공통 전환 제한 누락

`v0.86.17`까지는 기능별 `readonly=true` 또는 `status=preview_read_only`를 Bootstrap·메뉴에
전달하지만 계산한 읽기 전용 상태를 개별 편집창에 연결하지 않는 누락이 있었다. 이 누락은 요청 메모
개선 이전 버전에도 존재한다. 기본 읽기 전용 요청·추적 화면에는 해당 메모 편집창이 없으며 이를
모든 조회 화면의 변경 허용으로 확대 해석하지 않는다.

`v0.86.18`은 기능 상태 컨텍스트를 **스킬(`agents.skills`)·LLM(`observability.llm`)·
XView(`observability.xview`)**에 먼저 적용하는 단계다. 버튼·중첩 편집창과 실제 API 호출 직전에
기능 소유자·읽기 전용·현재 권한·세션을 함께 확인한다. 열린 초안은 지우지 않고 잠그며 다시 쓰기
가능해져도 자동 전송하지 않는다. 이미 보낸 요청의 서버 저장 취소·롤백을 뜻하지 않는다.

| 시범 작업 | 읽기 전용에서의 의도 |
| --- | --- |
| 스킬 조회·검색·검사·내보내기, 평가 시뮬레이션·적용 없는 추천 | 허용: 기존 조회·로컬 계산이며 POST 여부만으로 차단하지 않음 |
| 스킬 생성·수정·삭제·승격·가져오기·기본 추천 추가·추천 적용·후보 채택·적합성 근거 기록 | 차단: 영속 변경 |
| 요청 메모·태그 편집·삭제, LLM 피드백 등록, XView 저장 필터 생성·덮어쓰기·삭제 | 차단: 영속 변경 |
| 요청 재실행·모델 원인 분석 | 차단: 실제 외부 모델 실행 |
| LLM/XView 조회·필터 적용·링크 복사 | 허용: 조회·브라우저 탐색 |

초기 상태와 열린 초안의 상태 전환, 비동기 파일 읽기 뒤 실제 전송 전 차단 및 이미 보낸 요청의
응답 경계를 구성요소·`feature-readonly.spec.ts`의 API fixture 브라우저로 검증한다. 실제 다른 탭
로그아웃 뒤 같은 문서의 새 계정에서 이전 파일 읽기 완료가 전송·알림을 만들지 않는 경계도 검사한다.
파일 읽기의 늦은 실패 알림은 별도 구성요소 검사로 보완한다. 실제 업무 UI와 Go 서버를 연결한 동일
실행의 E2E, 다른 등록 기능 전체 적용이나 운영 기본화 완료는 아니다.
인증 Bootstrap의 마지막 정상 설정 유지와 빈 Registry의 기존 정적 기본값은 변경하지 않는다.
반영은 브라우저가 확인한 설정 기준이지 모든 파드·열린 탭의 즉시 강제를 보장하지 않는다.
서버 역할·scope·팀 범위 검사는 별도로 유지하며 `X-Vibe-Route` 같은 클라이언트 메타데이터를
새로운 서버 권한 증명으로 신뢰하지 않는다. 나머지 기능의 작업별 연결은 후속 적용 대상이다.

`v0.86.19`의 추가 대상은 **공급자(`gateway.providers`)·게이트웨이 상태(`gateway.health`)**다.
공급자 저장·삭제·서비스 수준 목표 변경과 회로 차단기·세션 고정 해제의 전송 직전에도 기존 권한과
기능 상태를 함께 확인한다. 열린 편집·변경 검토·삭제 확인의 기준과 입력을 유지하고 조회·영향 재조회와
취소는 허용한다. 개별 공급자 식별자가 없는 상황을 전체 대상의 빈 문자열로 대체하지 않는다.
두 기능은 구성요소·Hook과 `gateway-readonly.spec.ts`의 39개 API fixture 브라우저 검사로 검증한다.
두 전환 설정·기존 scope·고정 입력과 대상·수동 복구·조회 재시도·새 영향 결과의 재동의·이미 보낸
요청의 완료와 새 세션의 늦은 응답 격리를 구분한다. 실제 변경 콜백 검사는 구성요소에서 수행하며,
브라우저에서 disabled 속성을 해제한 클릭만으로 React 콜백의 실제 진입을 증명하지 않는다.
390px 다크·키보드·접근성·엄격한 넘침도 검사한다. 긴 공급자 화면은 잠금 전환 시 스크롤 위치를
유지하므로 상단 사유가 현재 시야 밖일 수 있다. 안내를 스크롤해 확인한 이미지와 전환 직후 이미지를
구분하며, 하단에서 항상 보이는 사유 안내는 후속 개선 대상이다. 실제 업무 UI+Go E2E·운영 승격이나
모델·채팅·다른 등록 기능의 제한 적용까지 검증한 것은 아니다.

신규 UI의 모델 계약 편집은 저장할 때 계약 ID를 보내지 않아 수정이 별도 계약 추가로 처리되는
결함이 있었다. `v0.86.20`은 원래 ID·기준값·검토할 요청을 고정해 같은 계약을 수정한다.
`gateway.models`의 계약·지원 종료 저장/삭제 네 작업은 전송 직전 기능 상태·기존 권한·현재
세션·확정된 목록을 다시 확인한다. 순수 관측 지표 비교는 읽기 전용에서도 기존 `admin:write`를
요구한다. 기능 제한과 식별자·실제 저장 계약의 증거를 구분하며 채팅 등 다른 기능으로 확대하지 않는다.

`v0.86.25`에서는 **라우팅 규칙의 사용·중지 확인만** 현재 `routing.rules` 기능과 조회/변경
권한·세션·확정 목록에 연결한다. 원본 ID와 변경 의도를 고정하고 한글 전후 비교·최신 기준
재확인을 제공하며 이미 보낸 성공과 후속 조회 실패를 구분한다. 집중 82개 구성요소/Hook 검사
(기존 17개 포함)가 통과했다. 합성 브라우저와 실제 Go 인증 회귀는 별도 실행 근거로 관리한다.
기존 생성·수정·삭제, 학습·미리보기까지 보호 완료로 확대하지 않는다. 서버 동시 변경 차단·
변경 초안 영향 시뮬레이션·원자적 감사·전체 인스턴스 즉시 반영 및 운영 정식 승격은 잔여다.

`v0.86.26`의 **라우팅 미리보기 첫 카드**는 실행 시점 입력을 고정하고 변경된 입력과 결과를
구분한다. 기존 `routing:read`와 기능 소유 화면·세션을 확인하되 기능 읽기 전용에서도 순수 계산은
허용한다. 의심 키 ID 전송·중복 실행·이전 세션의 늦은 결과를 제한하고, 새 결과 표시만 현재
접두사로 가린다. 신규 34개와 기존 95개 관련 회귀, 타입·린트·형식 검사가 통과했다. 예비 소스
`ff7bacd6`의 빌드와 브라우저 20개도 첫 실행에 통과했다. 최종 버전 빌드·전체 회귀·인증·CI는
별도 게이트로 확인한다. 실제 서버의 느슨한 응답 계약, 비용 예측, 다른 규칙 작업, 원자적 감사와
실행 취소는 변경하지 않으며 모든 민감정보 비노출·서버 비저장·운영 정식 승격을 뜻하지 않는다.

### 공급자 저장 전 연결 확인 (`v0.86.29`)

새 공급자와 기존 공급자의 편집 초안에 별도 연결 검사를 제공한다. 새 이름 충돌, 저장 키의
주소 변경 전송, 숨겨진 URL 검사, 키 없이 확인하는 모호한 요청을 차단한다. 검사 성공이
저장·검토·활성화로 이어지지 않으며 입력 변경과 이전 결과를 구분한다. 검증 중 입력이
바뀌면 이전 초안으로 저장·검토하지 않고 다시 명시적으로 실행하도록 안내한다.

- 신규 UI 검사 73개와 기존 공급자 회귀 176개, 전체 타입·관련 린트·형식 검사를 통과했다.
  저장/검토 검증 중 초안 변경은 실제 RHF 비동기 검증에서 먼저 실패를 재현한 뒤 보완했다.
- 검증 오류 직후 입력이 잠깐 잠겨 초점을 잃는 문제를 브라우저와 제어된 제출 가드 검사에서
  재현해 수정했다. 같은 훅의 권한 소유자 전환 후 진행 표시도 복구한다. 최종 v0.86.29 빌드의
  합성 브라우저 13개는 390px 다크·첫 오류 초점·키보드 스크롤·하단 버튼·axe를 포함해 통과했다.
  기존 생성 저장의 `저장 중` 표시도 복원했으며 신규 13개와 기존 미저장 변경 11개를 함께 통과했다.
- `PROVIDER-LIVE-001`의 최종 v0.86.29 실행은 실제 Go API·임시 SQLite·로컬 공급자에서 신규 검사 후
  DB 미생성, 명시적 저장 1회, 빈 키의 기존 공급자 검사와 미저장 제한 시간을 확인했다.
  서버의 두 모델 목록 호출과 두 감사 기록을 대조한다. 합성 API 브라우저 검사와 별도 근거다.
- 서버 권한·기능 설정은 공유 DB에서 다시 확인한다. 권한 조회 중 시간 초과는 실제 인증
  실패 401과 구분하여 자동 인증 갱신·재전송을 유발하지 않도록 한다. 외부 공급자의 401도
  HTTP 200의 인증 거부 결과로 구분한다. 비밀·원문 응답·모델 목록은 결과나 감사에 넣지 않는다.

최초 예비 화면의 버전 표시는 v0.86.28이며 이후 최종 v0.86.29 빌드로 별도 검증했다.
전체 회귀·CI·릴리즈는 각각 별도 게이트로 확인한다. 외부 공급자 호환성, 실제 추론, 추후 저장과 동시 변경의 안전성, 운영 Preview 평가와
Stable 승격은 이 한 시나리오의 통과로 완료 처리하지 않는다.

### 정책 시뮬레이션의 실행 기준과 한글 결과 (`v0.86.30` 후보)

정책 어드바이저의 `섀도우 영향`만 대상으로 기존 `POST /admin/policies/simulate`를 사용한다.
추천 이름·전송 규칙·선택 기간은 실제 실행 시점에 고정한다. 실행 권한(`admin:write`·`security:read`)을
확인할 수 없게 되거나 기간·사용자·역할·팀·기능 소유자·세션/탭 수명이 바뀌면 이전 응답을 새 결과로
게시하지 않는다. 실패 시 요청 ID와
수동 재시도를 제공하며, 재시도는 표시한 원래 규칙·기간을 쓰되 새 표본을 읽을 수 있음을 안내한다.
기능 읽기 전용에서도 순수 계산은 허용하지만 기존 `admin:write`와 정책 화면의 조회 권한은 필요하다.
추천 조회의 `admin:read`는 계산 POST 권한을 대신하지 않는다. 초안 생성·정책 저장·캐너리 변경의
기존 본문과 동작은 변경하지 않는다.

- 신규 단위·구성요소 48개, 기존 정책 화면·공유 API Client를 포함한 관련 87개가 통과했다.
  전체 Vitest는 2,538개/186파일이 통과했다. 실제 캡처 콜백·동기 중복·사용자 변경·새 작업 B가
  진행 중일 때 이전 A 완료·고정 실행 기준을 검사한다. 하네스의 기존 API epoch 모사와 실제
  공유 Client 검사를 구분하며 실제 Go 인증 브라우저 증거로 합치지 않는다.
- 전용 합성 HTTP 브라우저 13개와 전체 합성 브라우저 660개가 재시도 없이 통과했다.
  fixture가 UI 대신 권한이나 입력을 차단하지 않는다. 390px 다크에서 키보드로 이름 있는 읽기
  영역에 진입하고 PageDown으로 본문을 스크롤한 뒤 닫기·원래 버튼 초점을 확인했다.
  넘침·axe 위반 0과 관련 ARIA 이름 규칙의 미확정 결과 0도 확인했다. 모든 내용을 한 화면에
  동시에 표시하거나 모든 도메인의 접근성을 보장한 것은 아니다.
- 첫 모바일 실행의 `scrollable-region-focusable` 실패와 뒤이은 문단 이름 지정의 수동 검토
  지적을 보존했다. 단순 `axe violations=[]`만으로 이름 의미가 올바르다고 간주하지 않고,
  최종 `role=region`에 이름을 붙여 단위·브라우저를 다시 검증했다.
- `policy_simulation_http_test.go`는 실제 Go Routes·임시 SQLite의 별도 HTTP 검사다.
  4개 최상위 검사와 하위 사례 8개를 normal/race에서 통과했고, 권한·분기·집계 분모·현재 팀
  조인·복원되지 않는 조건과 검사한 정책·설정·이력의 불변, 로컬 업스트림 호출 0을 확인했다.
  권한 거부 감사까지 포함한 DB 전체 무변경, PostgreSQL·운영 데이터·5,001행 검사는 주장하지 않는다.

새 결과 상태에는 허용한 집계값만 넣고 원문 차단/오탐 후보 표본을 새 Query/Mutation 캐시나
결과 DOM에 넣지 않는다. 현재 접두사는 표시만 보호하며 전송 규칙은 바꾸지 않는다. 기존 원시 API
응답 전체의 투영·모든 개인정보 제거를 추가한 것은 아니다. 누락·잘못된 수치와 응답의 0을 구분하되
원기록의 결측값이 서버에서 0으로 집계됐는지는 알 수 없다. 표본은 기본 최대 5,000개의 조인 기록이며
고유 요청 전체가 아니다. 서버 `since`는 시작 기준만 제공하고 정확한 종료 시각·고정 표본을 제공하지 않는다.
일부 조건은 당시 값 없이 빈값·기본값으로 평가되며, 팀은 현재 API 키 정보다. 차단 대상의 과거 추정 비용은

### 추천에서 비활성 정책 초안 생성 (`v0.86.31` 후보)

  사용자/역할/팀·세션·화면 수명과 추천 조회 기준을 확인한다. 기존 서버 POST의 `admin:write`
  권한 계약은 바꾸지 않으며 UI의 기능 읽기 전용 제한을 새 서버 권한 정책으로 설명하지 않는다.

  허용, 정책 CRUD와 캐너리 변경 본문은 이 범위에서 변경하지 않는다.
- 조회 중·오류·무효화·기간/목록 변경 또는 쓰기 권한 회수 시 원래 규칙을 유지하고 검토 승인을

- 비어 있지 않은 `policy_id`와 `enabled:false`를 받아야 생성 사실을 확인한다. 응답 오류·누락은

  Client의 401 인증 갱신 후 재전송은 유지한다. 서버의 멱등성·중복 방지·동시 변경 CAS는 없다.

### 비활성 정책의 메타데이터·복수 규칙 편집 (`v0.86.32` 후보)

기존 정책 목록에서 **비활성 상태가 확인된 정책 한 건**의 이름·설명·우선순위와 복수 규칙을
편집한다. 규칙 수정·추가·삭제와 전체 비우기를 제공하며, 적용 비율과 비활성 상태는 유지한다.
새 생성·사용/중지·캐너리 변경·시뮬레이션의 업무 로직을 바꾸거나 정책 전체 이전을 완료한 것은 아니다.

- 열 때 원래 정책 ID·전체 기준을 고정하고 실제 전송할 메타데이터와 규칙 목록 전체를 한글로
  비교한다. 미편집 규칙의 ID·중첩된 알 수 없는 JSON 값은 보존한다. 새 규칙 ID는 서버가 부여하며
  모든 규칙을 비우는 변경은 별도 명시 확인을 요구한다. 빈 규칙의 실제 GET/ACK는 `rules`를
  생략하므로 이 생략만 빈 목록으로 해석하고 `null`·잘못된 원본을 빈 값으로 추정하지 않는다.
- 저장 시 달라지는 정책 ID는 편집 진입을 막는다. 유지할 수 없는 규칙 ID나 서버에서 정리되는
  비정규 최상위 JSON 키는 암묵적으로 바꾸지 않고 규칙/해당 JSON 전체 교체 또는 규칙 삭제를
  요구한다. 0이 아닌 안전한 정수 우선순위는 음수도 허용하며 서버 기본값으로의 우발적 변환을 막는다.
- 현재 비밀값 접두사로 보호된 기존 문자열·JSON은 원문을 DOM에 표시하지 않고 유지하거나
  명시적으로 전체 교체·삭제한다. 새 민감정보로 보이는 입력은 저장하지 않는다. 표시 보호 문구를
  원문 대신 전송하지 않으며 기존 원문 GET·조회 캐시·서버 저장·감사를 제거하거나 모든 개인정보를
  가리는 기능은 아니다. 초안은 이 경로에서 URL·영속 저장소·Query/Mutation Cache에 추가하지 않는다.
- 진입과 저장 직전 현재 `governance.policies` 소유 화면·읽기 전용·`security:read`/`admin:write`·
  사용자/역할/팀·세션·수명을 확인한다. 조회 실패·진행·무효화 또는 원본 변경은 저장을 막는다.
  실제 POST 직전 새 GET으로 같은 비활성 원본을 확인하지만 GET과 POST 사이 서버 CAS는 없다.
  계정 왕복은 이전 편집을 폐기하고, 권한 회수 후 복구해도 과거 검토 콜백을 다시 승인하지 않는다.
- 정책 ID·비활성 상태·검토한 값과 기존/새 규칙 ID를 확인한 ACK만 저장 완료로 인정한다.
  확인된 저장을 후속 GET 실패나 쓰기 권한만의 회수 때문에 저장 실패로 바꾸지 않는다.
  후속 조회·캐시 갱신은 현재 읽기 허가·소유자·수명 안에서만 수행한다. 불명확한 응답은 미저장을
  뜻하지 않아 명시적 목록 재조회로 원본 전체가 동일함을 확인하기 전에는 재저장을 잠근다.
  변경·삭제·조회 실패에서는 잠금을 유지하며, 기존 공유 Client의 401 갱신 후 재전송은 유지한다.
- 서버는 한 정책과 규칙 목록을 트랜잭션으로 전체 교체하지만 감사·설정에 따른 후속 `dry-run`은
  별도 작업이다. 다른 정책·전체 DB 무변경, 원자적 감사, 멱등성·동시 편집 차단·저장 취소나
  운영 비용 없음을 보장하지 않는다. 후속 모의 검사와 최초 초기 설정 부작용은 기존 계약을 따른다.

### 선택한 요청의 제한된 단계 기록 (`v0.86.33`)

추적 탐색기의 기존 목록·선택·상세 요약을 유지하고 읽기 전용 단계 조회를 추가한다. 기존
불투명 요청 참조와 정확한 UTC 나노초 시각으로 선택된 한 요청을 확인하며 원문 ID를 요구하지
않는다. 루트·도구·텍스트 SQL의 직접 하위 관계, 상태, 기록 시각·상대 위치·지연과 소스별
상한·생략을 표시한다. 도구 시간·잘못된 시각을 0으로 만들거나 빈 목록을 전체 부재로 단정하지 않는다.

검증 범위는 다음처럼 분리한다.

- Go 저장소: SQLite와 격리 PostgreSQL의 실제 제한 쿼리, 원문 열이 없는 최소 스키마,
  정확한 시각·팀/키 관계·삭제·잘못된 숫자·취소와 소스별 상한. 대규모 자연 실행 계획은
  인덱스 사용을 강제한 실행과 구분하고, 상한 전 전체 정렬이나 범위 밖 자식 스캔을 확인한다.
- Go HTTP: 실제 Routes·임시 DB에서 인증·읽기 권한·원래 v2 목록의 참조/시각·엄격한 매개변수·
  메타데이터 투영·OpenAPI 계약 확인. 회전·세션·팀 변경의 특정 시점 검사는 별도 제어된 읽기
  경계로 재현하며 모든 요청의 원자적 권한 취소나 DB 스냅샷을 보장하는 것으로 확대하지 않는다.
- React: 생성 타입·엄격한 응답 계약·현재 계정/권한/목록/선택 수명·늦은 결과 폐기·부모 갱신
  중 표와 초점 유지·현재 접두사 표시 보호. 브라우저는 합성 API를 쓰며 실제 UI→Go의 동일

### XView 실시간 구간·표시 정합성과 메모 복구 (`v0.86.45` 개발 후보)

v44 출고 뒤의 별도 후보다. 기존 `/app/observability/xview`의 조회·산점도·요약·상세 수명을
개선하며 Go 핸들러·DB 조회·인증·API 스키마나 공유 ApiClient의 기본 정책은 변경하지 않는다.
아래 최초 집중 근거의 빌드 표시는 v0.86.44였다. 이후 최종 v45 생성물·내장 빌드에 결속한
전체 UI/Go·실제 로컬 인증 검사를 별도로 통과했다. 정확한 원격 CI·태그와 공개 출고는 아직 미완료다.

- 기존 snapshot GET과 delta GET을 구분한다. 정상 delta는 약 1,500ms 간격의 단일 진행
  요청이고 약 15초마다 `reconcile`, 약 300초마다 `refresh`를 기존 GET 조건으로 보낸다.
  따라잡기 중에는 두 보완 조건을 섞지 않는다. 숨겨진 탭의 조회 중지, 실패 후 지수형 대기,
  제한된 연속 조회와 정체·순환·역행 커서의 빠른 재조회 중지를 구분해 안내한다.
- 커서는 서버의 적재 시각과 불투명 요청 ID의 조합이다. ID를 브라우저 문자열 정렬로
  비교하거나 화면의 마지막 점에서 커서를 만들지 않는다. 팀/원문 권한에 따른 기존 투영과
  제한된 최근 보완 조회를 유지한다. `server_time`은 트랜잭션 스냅샷 시각이 아니며 주기적
  보완·200 응답·`has_more=false`는 원자성·누락 없는 수집·전체 건수의 보장이 아니다.
- 상대 구간은 확인한 서버 시각과 단조 경과 시간으로 오래된 표시점을 제거한다. 빈 delta의
  성공도 마지막 응답 확인 시각을 갱신한다. 시각 미확인·역행은 명시하고 확인한 기준이 없으면
  브라우저 벽시계만으로 점을 삭제하지 않는다. 명시적 from/to 구간과 해석 불가능한 점 시각을
  임의로 만료시키지 않는다. 점은 최대 6,000개이며 6,001번째의 상한 안내를 유지한다.
- 요약은 현재 표시점만 센다. P95는 서버와 같은 nearest-rank
  `ceil(n × 0.95) - 1` 인덱스이고 1–20ms의 20개 점에서는 19ms다. 전체 요청 통계가 아니다.
  동일/빈 delta의 점 참조를 유지해 불필요한 산점도 재작성을 줄이되 성능 SLA를 주장하지 않는다.
- 현재 조회 소유자·계정/팀·세션·권한·Query 객체와 성공 세대를 확인한다. 외부 무효화·
  재조회가 시작된 뒤 예전 delta를 섞지 않는다. 일반 delta 503은 허용된 이전 점과 대기 후
  재시도를 유지하고 snapshot 503은 이전 점을 유지하되 자동 delta를 중지하고 수동 조회를 안내한다.
  최종 401/403·권한 거부는 점·캐시·취소 복귀 사본과 이전 선택/흐름/원인 설명을 폐기한다.
  같은 조회 수명은 새 수동 200 뒤에도 자동 조회를 재개하지 않고 이전 창도 자동으로 열지 않는다.

설정 검사에 도달하기 전에 5분 제한시간을 넘었다. 기존 CI의 순차 실행 우회와 구분해 기록하고,
실제 세션의 잠금 대기가 부분 인덱스 생성을 막는 짧은 인과 검사로 재현했다. 비대기 잠금 확인,
호출자 취소·배타성·해제 뒤 재획득과 두 전체 마이그레이션의 동시 시작을 검증 대상으로 추가한다.
잠금 획득·해제 결과가 불명확한 연결은 풀에 재사용하지 않는다. 네트워크 실패 뒤 서버의 즉시
잠금 해제나 현재 시작 경로의 전체 시간 제한까지 새로 보장하는 것은 아니다.
수정 후 PostgreSQL 마이그레이션 3개는 통과했다. 이후 병렬 설정 검사는 작은 임시 DB의
저장 공간 부족(`SQLSTATE 53100`)으로 실패해, 원본을 보존하고 용량을 확보한 새 격리 DB에서
같은 검사를 다시 수행했다. 새 DB의 병렬 PostgreSQL 설정 검사와 후속 SQLite 검사 모두
44개 최상위 검사가 통과했다. 부분 성공과 환경 실패는 보존하며 최종 릴리즈 검증은 별도다.

이 순서는 위험을 줄이는 개발 계획이며 앞 단계 검사가 실패한 상태에서 운영 변경이나 다음 단계
Stable 승격을 진행해도 된다는 허가가 아니다. `/admin`은 계속 유지한다.
