# 콘솔 작업 결과 관측

v0.86.181 개발 후보는 원 요구사항 36의 Action Success 관측을 추가합니다. 기존 ‘콘솔 사용 관측’ 설정을 켠 환경에서만 수집하며 기본값은 꺼짐입니다. **시스템 설정 → 콘솔 전환 → 작업 결과 열기**에서 최근 7일 또는 30일의 결과를 확인합니다. v0.86.181 미만 백엔드에는 작업 관측 요청을 보내지 않습니다.

## 결과를 읽는 방법

| 표시 | 의미 |
| --- | --- |
| 완료 | 해당 작업의 응답과 기존 화면의 계약 검증이 완료됨 |
| 거부 | HTTP 4xx로 명시적으로 거부됨. 408은 제외 |
| 확인 불가 | 통신 중단, 시간 초과, 5xx, 응답 계약 불일치 등으로 처리 결과를 확정할 수 없음 |
| 완료율 | 완료 / (완료 + 거부). 확인된 결과가 없으면 백분율을 표시하지 않음 |

저장 이후 목록 갱신이 실패해도 이미 확인된 저장은 완료로 유지합니다. 비동기 작업의 ‘실행 요청’ 완료는 접수 응답을 확인했다는 뜻이며, 실제 작업 종료나 평가 통과를 뜻하지 않습니다. 연결 ‘테스트’ 완료도 진단 응답을 받은 결과이며 연결 대상의 정상 여부와 구분합니다. 스트리밍은 종료 사유가 없는 응답 종료를 확인 불가로 분류합니다.

브라우저 관측은 감사 기록이나 서비스 전체 성공률을 대체하지 않습니다. 탭 종료, 취소, 화면·세션 변경, 전송 실패, 수집 제한 때문에 누락될 수 있습니다. 중단된 요청을 재시도하거나 미전송 기록을 브라우저에 보관하지 않습니다. 기능별 Preview 사용률의 분모와 직접 주소 접근 거부 관측은 별도 후속 범위입니다.

## 수집 범위와 보호

- 저장·삭제·승인·거절·회수·교체·롤백·사용·중지·가져오기·내보내기·실행 요청·테스트·피드백의 고정 분류만 사용합니다.
- 공통 Mutation 및 명시적으로 연결한 직접 제출 경로에서 수집합니다. API의 POST 여부만으로 쓰기 작업을 추론하지 않습니다. 로그인·로그아웃·검색·계획·비용 예상·검토용 dry run과 관측 전송 자체는 제외합니다.
- 작업을 시작한 기능을 고정하고 한 제출에서 한 결과만 기록합니다. 종료된 세션·화면 소유자의 늦은 완료는 버립니다. 관측 오류가 원래 작업을 실패시키지 않습니다.
- 입력값, 응답, 이름, 사용자·팀 ID, 리소스 ID, 비밀값, SQL·프롬프트·사유 원문은 관측 데이터에 넣지 않습니다. 기능 ID, 고정 작업 분류, 결과, 정규화한 숫자 릴리즈 버전과 서버 수신 시각만 저장합니다.
- 중복 방지용 128비트 무작위 이벤트 ID는 서버에 해시로 저장합니다. 같은 ID를 다른 내용으로 덮어쓸 수 없으며 중복 전송으로 보존 기간을 늘릴 수 없습니다.
- 브라우저는 메모리에서 분당 최대 20건을 전송합니다. 서버는 기존 관측 수집의 프로세스·사용자 상한을 함께 적용하고, 매번 현재 DB 설정과 인증·기능 권한을 확인합니다. 전송과 조회 응답은 `no-store`입니다.
- 본문은 1,024바이트와 2초로 제한합니다. 중복·대소문자 변형·추가 필드·null을 거부합니다. 관측 전송은 인증 재시도나 오류 관측을 재귀적으로 만들지 않습니다.
- SQLite와 PostgreSQL에서 최근 30일 최대 10,000건을 공유 잠금·원자적 용량 예약으로 보존합니다. 조회는 현재 허용 기능만 포함하고 상위 100개 그룹 및 생략된 그룹 합계를 제공합니다.

## 화면과 배포

작업 결과 창은 열 때만 로드합니다. 기능명과 작업명은 한글로 표시하고, 좁은 화면에서는 표 영역만 가로 스크롤합니다. 키보드로 표를 이동하고 창을 닫으면 원래 버튼으로 초점이 돌아갑니다. 같은 변경에서 시스템 설정의 상세 편집기도 명시적 선택·직접 상세 주소로 열 때만 불러오도록 분리했습니다.

기존 `/admin`과 업무 API는 유지합니다. `/admin/ui-actions/events`와 `/admin/ui-actions/summary`는 관측 메타데이터만 수집·집계하며 업무 변경을 대신 수행하지 않습니다. 기존 Go embed·단일 바이너리·폐쇄망 에셋 배포를 유지합니다.

## 검증 범위

서버의 입력·권한·설정·동시성·용량·보존·중복 계약, 공통 Mutation·직접 제출의 소유권과 결과 분류, 저장 후 조회 실패, 설정 편집기 지연 로딩·초점 복원을 검증합니다. 실제 Go embed 브라우저 검증은 저장 응답 fixture의 완료·거부·확인 불가를 실제 관측 API로 전송하고, UI 버전·비활성 상태·민감 데이터 배제·조회 집계를 확인합니다. 업무 저장 자체의 기존 Go/브라우저 회귀는 별도로 유지합니다. 390px·1440px 밝은/어두운 화면에서 긴 버전 값, 표 경계, 키보드·axe와 시각 기준을 확인합니다.

CI의 실제 Go 브라우저 단계는 완료·충돌·응답 불명·저장 후 반영 대기의 네 시나리오가 재시도나 건너뛰기 없이 통과하고, DB의 완료 2건·거부 1건·확인 불가 1건과 일치해야 성공합니다. 일반 API 인증 검사와 별도로 활성 수집의 인증·기능 권한 및 비활성 수집의 무저장을 검증합니다.

후보·메인 CI와 선행 릴리즈 검증을 거쳐 순차 출고합니다. 이 문서는 전체 Phase 0–6 인수 완료나 모든 기능의 Stable 승격을 선언하지 않습니다.
