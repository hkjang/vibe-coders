# API 키 이름 검색과 읽기 전용 상세

v0.86.101 후보 마일스톤. 기존 `/admin`과 키 발급·수정·폐기 흐름을 유지한다.

## 사용자 동작

- 명령 팔레트의 **자원 검색 → API 키**에서 등록된 키 이름을 검색한다. 이름과 데이터베이스 식별자만 결과에 표시하며, 비밀값·해시·소유자·권한은 검색 대상에 포함하지 않는다.
- 검색 결과나 사용자·팀 화면의 API 키 이름을 누르면 **API 키 상세**가 열린다. `/app/access/users?tab=keys&api_key_id=<ID>` 주소로 직접 조회하거나 새로고침할 수 있다.
- 상태, 소유자, 팀, 역할, 권한 범위, IP·모델·공급자 제한, 예산, 생성·만료·폐기·교체 유예 정보를 읽기 전용으로 제공한다. 키 비밀값은 재조회하지 않는다.
- 상세를 닫으면 기존 URL 매개변수를 보존하고 가능한 경우 원래 링크로 초점을 복원한다. 존재하지 않거나 현재 팀 범위 밖인 키는 빈 상태를 표시한다.
- v0.86.101 미만 서버에서는 새 검색 종류를 요청하지 않고 목록과 기존 화면을 제공한다. 이전 서버가 전체 목록을 반환하는 혼합 배포에서도 상세 ID·개수 계약을 검증한다.

## API와 권한

기존 `GET /admin/api-keys`에 선택적인 정확한 `id` 필터를 추가한다. ID가 없으면 이전 목록 동작을 유지하고, 있으면 같은 공개 필드·검토 리비전을 0~1건 반환한다. 빈 값, 중복 ID, 512자 초과, 허용되지 않은 식별자는 400이며 전체 목록으로 대체하지 않는다. 키 수정용 역할 비교를 조회 권한에 적용하지 않는다.

검색 `api_key` 종류는 `admin:read`와 사용 가능한 `access.users` 기능이 필요하다. 팀 관리자는 인증된 팀 ID와 정확히 일치하는 키만 조회한다. 미소속 팀도 별도의 정확한 범위다. 검색은 이름만 제한적으로 조회하고, 서버가 보호 대상 이름·ID를 제외한 뒤 최대 10건을 반환한다. 기존 범위·시간 제한과 SQL 매개변수 바인딩을 재사용한다.

목록과 상세는 같은 조회 수명을 공유한다. 계정·팀·역할·권한·세션 변경 또는 401/403 이후 이전 요청을 취소하고 캐시와 열린 작업을 폐기한다. 키 수정·권한 수정·폐기는 해당 조회 수명의 정확한 목록 리비전으로 계속 검토한다. 쓰기 허용 여부만 바뀌면 기존 초안을 보존한다.

## 검증

SQLite와 PostgreSQL에서 이름 검색의 한글·대소문자·리터럴 검색, 범위, 제한, 기존 공개 리비전 정합성, 정확한 ID 조회와 비밀값 제외를 확인한다. React에서는 URL·닫기 초점·없는 키·잘못된 응답·재시도·이전 서버·권한 거부·팀 전환의 늦은 응답과 기존 키 관리 회귀를 검증한다. 실제 Go 인증 브라우저 시나리오의 자원 검색 대상에도 API 키를 포함한다.

데스크톱과 모바일, 밝은·어두운 테마에서 상세 패널의 접근성 및 시각 회귀를 검증한다. 상세는 변경 작업을 추가하지 않으며, 전역 모델 검색 등 나머지 Phase 0–6 요구사항은 후속 마일스톤으로 남는다. 이 문서는 전체 목표 완료 또는 Stable 승격을 의미하지 않는다.

### 후보 버전 로컬 검증 결과

- 전체 React 5,844개 / 392개 파일과 도구 54개 통과. 선택 환경 검사 15개는 로컬에서 건너뛰었다. 이후 실제 클라이언트 쿼리 등록과 즉시 권한 회수 보완을 포함한 최종 관련 검사 152개 / 16개 파일이 통과했다.
- SQLite·PostgreSQL 17 검색 및 공개 키 리비전 race 검사와 기존 API 키 발급·수정·폐기 회귀가 통과했다.
- 최종 내장 Go·운영 CSP·외부 네트워크 차단 브라우저 70개와 실제 Go/OIDC/SQLite 인증 46개가 실패·재시도·건너뛰기 없이 통과했다. 새 시각 기준 4개를 직접 확인하고 읽기 전용 비교 실행을 통과했다. 186개 정적 에셋, 해시·캐시·MIME·CSP·직접 주소와 기존 관리자 경로도 확인했다.
- 초기 261,329/350,000바이트, 화면 47개와 선택 도구 6개 모두 예산을 충족한다. 새 의존성 없이 Go 19개·npm 389개의 통합 SBOM과 라이선스를 갱신했다.
- 첫 브라우저 실행에서 쿼리 검증 등록 누락을 발견해 실제 클라이언트 계약 검사 6개로 보완했다. 해당 이전 빌드의 인증 실행은 취소했으며 최종 인증 결과로 대체했다. 기존 수정·폐기 검토의 조회 키 회귀와 상세 닫기 초점도 최종 관련 검사에 포함한다.

원격 최종 CI, 실제 메인 CI, 정식 이미지·공개 배포 파일 검증은 별도 출고 단계에서 확인한다.
