# JSON·SQL·프롬프트 편집

v0.86.81 후보는 기존 입력창에 선택형 코드 편집기를 추가한다. 기능의 Preview 상태와
기존 관리 API를 유지하며, 편집기에서 값을 고치는 것만으로 서버 설정을 저장하거나 SQL을 실행하지 않는다.

## 사용 범위

| 화면 | 입력 | 제공 도구 |
| --- | --- | --- |
| 비활성 정책 편집 | 조건·동작 JSON | 문법 표시, 찾기, 되돌리기, 명시적 JSON 정렬 |
| 회귀 검증 세트 | 기준 프롬프트·기대 내용 | 줄 번호, 찾기, 되돌리기, 자동 줄 바꿈 |
| 회귀 검증 세트 | 태그 JSON | 문법 표시, 명시적 JSON 정렬 |
| 자연어 SQL의 기준 SQL 등록 | 질문·기대 SQL | 질문 편집과 SQL 구문 강조 |

처음에는 기존 기본 입력창을 표시한다. `코드 편집기 열기`를 선택하면 편집 도구를 불러온다.
`기본 입력으로 전환`을 누르면 초안을 유지하고 입력창으로 초점을 돌린다. 다운로드에 실패해도
기본 입력을 계속 사용할 수 있다. 100만 문자를 넘는 값은 잘라내지 않고 기본 입력으로 제공한다.

Tab은 다음 항목으로 이동한다. 편집기 안의 Esc는 찾기 도구를 닫고 상위 편집창을 닫지 않는다.
편집창을 닫으려면 닫기·취소 버튼을 사용하거나 편집기 밖에서 Esc를 누른다. 기존 미저장 변경
확인, 오류 필드 초점, 저장 전 검토와 변경 비교는 유지한다.

자동 들여쓰기·자동 따옴표 완성·붙여넣기 자동 정렬은 사용하지 않는다. JSON 정렬은 사용자가
선택할 때만 실행하고 숫자를 JavaScript 값으로 파싱해 다시 쓰지 않는다. 따라서 큰 정수의
원문 자릿수도 유지한다. SQL 도구는 구문 강조이며 실행 계획·실행 권한·DB 문법 검증을 대신하지 않는다.
문법 표시와 기존 폼의 업무 검증은 별개이며 실제 저장은 기존 폼 검증과 서버 권한을 거친다.

## 권한과 초안

저장 중인 필드와 읽기 전용 필드는 편집할 수 없다. 기준 SQL의 등록·삭제·회귀 실행은 공통
기능 전환 권한을 사용하고, 창이 열린 뒤 읽기 전용으로 전환되어도 전송 직전에 다시 검사한다.
기존 정책의 보호된 원문은 편집기에 전달하지 않는다. 모델과 되돌리기 상태는 편집기를 닫을 때
폐기하고, 찾기·바꾸기 기록은 다른 편집창과 공유하지 않는다. 입력 내용을 브라우저 저장소,
주소, 프런트엔드 로그에 저장하는 기능은 추가하지 않는다.

## 오프라인 구성과 용량

Monaco, 한글 메시지, SQL·JSON 언어 자산, 작업자와 아이콘 폰트를 빌드 산출물에 포함한다.
외부 CDN을 사용하지 않으며 JSON의 외부 `$schema` 주소도 요청하지 않는다. Go의 기존 CSP를
유지하고 `unsafe-eval`을 추가하지 않는다. 운영 중 Node.js 프로세스는 필요하지 않다.

초기 화면 350,000바이트 전송 상한과 일반 화면 250,000바이트 압축 전 상한은 유지한다.
명시적 활성화 뒤 내려받는 편집기 전체에 6,000,000바이트 압축 전·1,500,000바이트 전송 상한을
따로 적용한다. 중첩 언어 청크, CSS, 폰트, Vite manifest에 없는 작업자도 합산한다. 일반 화면의
정적 import로 편집기를 당겨오면 검사에 실패한다. 이 값은 파일별 압축 계산이며 네트워크 속도나
화면 표시 시간을 뜻하지 않는다. 외부·누락·페이지 주소에 따라 달라지는 작업자 URL도 거부한다.

## 검증 범위

브라우저 검사는 명시적 로딩, 한글 조합 중 전환, JSON 큰 정수·문자열 보존, 로컬 작업자,
기본 입력 복구, 검색 이력 폐기, SQL 저장 중 잠금·읽기 전용 전환을 포함한다. 정책 편집에서는
오류 초점, 원본 복원 뒤 되돌리기 경계, 기존 검토·저장 흐름을 확인한다. 밝은/어두운
390px·1440px 화면은 키보드·axe·시각 회귀 대상으로 관리한다. 기존 API 회귀와 실제 인증·
내장 자산·컨테이너·릴리즈 파일 검사는 별도로 통과해야 출고할 수 있다.
