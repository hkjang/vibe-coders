# 데이터 웨어하우스 추이와 기간별 집계

데이터 인사이트의 비용 추이에서 일별·주별 막대를 선택하면 바로 아래 **차원별 상위 10개**와 **CSV 내보내기**에 같은 기간이 적용됩니다. 선택 범위는 UTC 날짜로 표시하고 주소에 보관합니다. **전체 기간으로 돌아가기**로 선택을 해제하며, 조회 구간·집계 단위를 바꾸면 선택을 초기화합니다. 분석 차원·정렬 변경은 선택 기간을 유지합니다.

막대는 방향키·Home·End로 이동하고 Enter 또는 Space로 선택합니다. **추이 데이터 표로 보기**에서 날짜별 요청·토큰·비용·오류를 읽을 수 있습니다. 좁은 화면의 추이는 영역 안에서 가로로 스크롤됩니다. 요약과 하단 성능·품질·라우팅·Text2SQL·절감·모델 전환 분석은 전체 조회 구간을 유지하며 각 영역의 마지막 정상 갱신과 갱신 중·실패 상태를 별도로 표시합니다.

CSV는 선택한 분석 차원·정렬·날짜 조건의 상위 100개 항목을 내보냅니다. 표는 상위 10개입니다. 서버·브라우저 모두 잘못된 날짜, 시작·종료일 누락·중복, 역순과 90일 초과 범위를 거부합니다. 주소의 잘못된 값은 원문을 남기지 않는 빈 거부 표시로 바꾸며 전체 기간으로 조용히 확장하지 않습니다.

## 기존 API와 호환성

기존 `GET /admin/dw/dashboard/dimensions`와 `export.csv`에 선택적 `since_day`(포함)·`until_day`(미포함)를 추가합니다. 둘 다 없으면 기존 `window` 동작을 그대로 사용합니다. 명시한 날짜는 상대 기간과 독립적으로 복원됩니다. 주간의 첫 구간은 실제 조회 시작일에서 잘라 계산합니다.

`timeseries` 응답의 `date_bounds_supported`가 확인되어야 선택 기간 집계를 요청합니다. 지원하지 않는 서버에서는 선택을 적용한 것처럼 표시하지 않습니다. 집계 응답의 시작·종료일이 요청과 다르면 표·CSV를 거부합니다. 권한 거부 시 이전 값은 감추며 해당 영역만 수동으로 다시 확인할 수 있습니다. 서버의 기존 인증·권한 검사는 유지합니다.

실제 ClickHouse에서 확인한 기존 주간 집계의 컬럼·별칭 충돌도 수정했습니다. `toMonday`는 결과 문자열 별칭 대신 원본 Date 컬럼을 사용합니다. 원본 요청이나 새로운 비즈니스 API를 만들지 않습니다.

## 검증과 전환

`bash scripts/test-dw-date-selection.sh`는 자격 증명과 외부 URL을 받지 않는 새 ClickHouse 컨테이너에서 실행합니다. 컨테이너 네트워크를 차단하고 윤일·종료 경계·최소/최대 Date·기간별 캐시 분리·첫 부분 주간·JSON/CSV 집계 일치를 확인합니다. 같은 검사를 기존 CI 작업에 포함합니다.

React 검사에서는 선택·주소 복원·무효 조건 거부·구형 서버·응답 불일치·권한 거부와 독립 재시도를 확인합니다. 브라우저에서는 실제 키보드·CSV·새로고침, 390/1440px 밝은·어두운 테마, 표 경계·axe와 기준 이미지를 확인합니다. 운영 Stable 승격과 전체 Phase 0–6 인수는 별도 검증을 계속합니다.
