# 콘솔 오류 관측

v0.86.180 개발 후보는 원 요구사항 36의 API Error·JS Error 관측을 추가합니다. 기존 ‘콘솔 사용 관측’ 설정을 켠 환경에서만 수집하며 기본값은 꺼짐입니다. 시스템 설정 → 콘솔 전환 → **오류 관측 열기**에서 최근 7일 또는 30일의 유형별 집계와 최근 20건을 확인합니다. 구버전 백엔드에는 수집 요청을 보내지 않고 메뉴를 표시하지 않습니다.

## 수집 의미

- API 오류: 공통 API 클라이언트의 최종 실패를 기능 ID, 등록된 API 경로 형식, 메서드, HTTP 상태, 고정 오류 분류로 기록합니다. `/admin/requests/{id}/io`처럼 식별자가 치환되기 전 형식만 사용합니다. 성공한 토큰 갱신, 취소된 요청, 인증 및 관측 API 자체는 대상에서 제외합니다. 자동 조회 재시도 실패는 각각 기록되므로 장애 건수나 성공률과 다릅니다.
- 화면 오류: React 루트 또는 라우터 오류 경계에서 잡힌 오류의 종류와 경계만 기록합니다. 첫 직접 접근에서 인증 확인보다 먼저 화면이 실패해도, 인증과 수집 동의를 확인한 뒤 같은 오류가 화면에 남아 있을 때 한 번 관측합니다. 이전 화면이나 이미 처리한 오류를 재전송하지 않습니다. 인증 초기화 자체나 경계 밖 오류를 모두 수집하는 기능은 아닙니다.
- UI 버전은 숫자 릴리즈 형식만 보존합니다. 요청 ID는 `trace_` 뒤 32자리 소문자 16진수 형식만 허용하며 임의 요청 ID는 버립니다. 이 형식 검사는 요청 ID의 실제 출처를 증명하지는 않습니다.

## 개인정보·권한·상한

프롬프트, 응답, SQL 결과, 오류 원문, 스택, 사용자·팀·IP, 실제 리소스 주소, 검색어, 호출 인자, 비밀키는 전송·보존하지 않습니다. React의 잡힌 오류 콘솔 로그도 고정된 식별자만 출력합니다. 수집 요청은 Referer를 보내지 않고 오류 재수집·인증 재시도·큐·재전송을 하지 않습니다. 로그아웃·계정 변경·수집 해제 뒤 도착한 기존 API 오류는 버립니다.

서버는 매 요청마다 현재 설정·인증·기능 권한을 다시 검사합니다. 집계도 현재 사용자에게 허용된 기능만 포함합니다. 알 수 없는 필드·중복 JSON 키·실제 주소·허용되지 않은 API 조합은 거부합니다. 관측 화면은 수집을 꺼도 권한이 있는 기존 기록을 읽을 수 있습니다.

브라우저는 분당 20건으로 제한하며 서버는 기존 관측의 프로세스·사용자 제한을 공유합니다. DB에는 방문 집계와 별도로 최대 10,000건을 보존하며 30일 후 삭제합니다. 난수 이벤트 ID는 해시만 저장하고 같은 ID의 내용 변경이나 보존 기간 연장을 허용하지 않습니다. 여러 서버의 동시 기록도 같은 DB 용량 예약을 사용합니다. 집계는 상위 100개 조합과 나머지 건수를 표시하고 최근 오류는 최대 20건입니다. 전송 실패·구버전·상한 등으로 누락될 수 있으므로 완전한 감사 기록으로 사용하지 않습니다.

## 배포와 검증

SQLite·PostgreSQL 자동 마이그레이션은 기존 방문·첫 표시 시간·이동 기록을 유지합니다. 단일 Go 바이너리·기존 관리자·폐쇄망 제공 방식은 그대로입니다. 운영 Node.js나 외부 관측 서비스가 필요하지 않습니다.

검증 범위는 실제 저장소의 동시 용량·중복·보존·권한, 엄격한 HTTP 계약과 OpenAPI, 세션 변경·수집 해제·재귀 차단, 오류 경계, 실제 Go 내장 서버에서의 전송과 조회, 모바일·데스크톱 밝은/어두운 테마·키보드·접근성입니다. 원 요구사항의 변경 성공률, 직접 경로 권한 거부, 전체 Preview 채택률 분모와 운영 안정성 인수는 잔여입니다. 이 후보는 기능 Stable 승격이나 전체 Phase 0–6 완료를 의미하지 않습니다.
