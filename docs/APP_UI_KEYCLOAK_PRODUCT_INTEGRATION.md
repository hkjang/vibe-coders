# Keycloak 제품 연동과 자동 로그인 복귀 — v0.86.121 개발 후보

## 사용자 동작

실제 Keycloak에서 로그인 세션이 없어 자동 로그인이 거절되면 `/app/login?sso=none`으로 복귀한다.
로그인 화면과 초기 URL 정리 단계에서 서버가 만든 `none`·`error` 두 결과를 보존하고,
중복·임의 값과 비밀정보는 제거한다. 원래 화면 주소와 조회 조건을 유지하며 새로고침으로
자동 로그인 요청을 반복하지 않는다. 인증·권한·기존 `/admin` 동작은 유지한다.

## 실제 제품 검증

기존 모사 OIDC 서버 검사를 유지하고, 고정 다이제스트의 Keycloak 26.8.2 제품을 사용하는
별도 CI 검사를 추가한다. Go 내장 React 화면·실제 인증 API·SQLite와 Chromium을 연결한다.
다음 다섯 흐름과 데이터베이스의 사용자·권한 영속성을 확인한다.

1. 세션 없는 자동 로그인 거절, 원래 주소 보존, 탭 저장소를 지운 뒤 재시도 억제
2. 같은 이메일의 보호된 로컬 계정을 변경하지 않고 별도의 SSO 사용자로 로그인
3. 신규 SSO 사용자 생성과 새 탭에서 기존 Keycloak 세션으로 자동 복귀
4. Keycloak의 로그아웃 확인·세션 종료·콘솔 복귀와 이전 갱신 토큰 거부
5. 읽기 전용 역할 매핑과 실제 공급자 쓰기 API 거부

실행 방법은 잠금 파일로 프런트엔드 의존성을 설치하고 `web`을 빌드해
`internal/appui/dist`에 복사한 뒤 다음 명령을 사용하는 것이다.

```sh
python3 scripts/test-keycloak-browser.py --pull --report-dir /tmp/vibe-keycloak-check
```

Go 1.26.11, Docker, OpenSSL이 필요하다. `--pull`은 고정 이미지 다운로드에만 사용한다.
실행 컨테이너는 외부 네트워크가 없는 전용 네임스페이스를 공유하며 호스트 포트를 공개하지 않는다.
게이트웨이와 Keycloak은 서로 다른 HTTPS 출처를 사용한다. 자격증명·인증서·계정은 매 실행 임시 생성한다.
출력은 허용된 시나리오 ID·상태·숫자만 보관한다. 비밀번호·토큰·URL 원문·스크린샷·추적 파일은
결과물로 남기지 않으며 실행 종료 시 소유 컨테이너와 비공개 임시 파일을 정리한다.

이 검사는 제품 버전 한 종의 격리된 개발 모드 구성이다. 브라우저는 임시 인증서 오류를 허용하므로
운영 인증서 신뢰·실제 Keycloak 배포·프록시·사용자 디렉터리·PostgreSQL 운영 인수를 대신하지 않는다.
게이트웨이의 OIDC 서버 통신은 별도로 임시 CA를 신뢰하도록 설정한다. 운영 이미지에 Keycloak이나
Node 런타임을 추가하지 않는다. 기존 로컬 계정을 이메일만으로 자동 합치는 보호 정책도 완화하지 않는다.

## 검증 진행

수정 전 실제 Keycloak 브라우저에서 5개 중 4개가 통과했고, 자동 로그인 요청 1회 뒤
복귀 표식이 사라지는 실패를 확인했다. 초기 URL 정리와 경로 보호 검사에서도 4건을 재현했다.
최종 관련 React 1,112개(57개 파일), 실제 Keycloak HTTPS 5개와 데이터베이스 검증, 기존 Go/OIDC/SQLite 인증 46개를 통과했다.
보고서·실패 산출물 검사 29개도 건너뜀 없이 통과했다. 타입·린트·포맷·실제 Go OpenAPI 계약·통합 SBOM·Go Keycloak/기존 관리자 회귀·내장 UI 전체·vet·번들 예산을 통과했다. 초기 압축 번들은 262,461바이트다.
기존 제품 UI의 시각 기준과 런타임 의존성은 변경하지 않았다. 후보 CI·리뷰·메인·정식 배포 검증은 별도 단계이며 전체 Phase 0–6 완료를 뜻하지 않는다.
