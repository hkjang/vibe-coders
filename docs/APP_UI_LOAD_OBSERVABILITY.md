# 콘솔 첫 화면 표시 시간과 UI 버전

**시스템 설정 → 콘솔 전환 → 신규 콘솔 사용 관측**에서 기능별 방문·기존 화면 이동과 함께 첫 화면 표시 시간을 확인합니다. 조회 기간은 최근 7일 또는 30일이며 주소에 유지됩니다. 기존 `ui.app.telemetry_enabled` 설정을 켠 환경에서만 수집합니다. 기본값은 계속 꺼짐입니다.

## 표시 시간의 의미

- 최초 진입은 브라우저 탐색 시작부터, 앱 안에서 이동할 때는 라우터의 이동 시작부터 측정합니다. 지연 로딩한 화면 코드의 대기 시간을 포함합니다.
- 해당 기능이 화면에 반영된 뒤 두 번째 애니메이션 프레임에서 측정합니다. **첫 화면을 그릴 기회까지의 시간이며 모든 데이터 조회 완료·LCP·사용자 체감 전체 대기 시간은 아닙니다.**
- 동일 기능의 필터·탭 변경은 새 방문이나 추가 표본을 만들지 않습니다. 다른 기능을 다녀오면 새 방문입니다.
- 탭이 숨겨졌거나 이동이 중단된 경우, 계정이 바뀐 경우, 2분을 넘는 경우에는 해당 측정을 폐기합니다. 비활성화 중 버퍼링하거나 뒤늦게 재전송하지 않습니다.
- 평균은 **측정된 방문**으로 나눕니다. 측정이 없는 방문과 실제 `0 ms`를 구분하며, 표본 수/전체 방문 수·최대 시간을 함께 표시합니다. 전체 사용자·전체 트래픽을 대표하는 지표는 아닙니다.

## 저장 범위와 호환성

기존 방문 해시·기능 ID·최초 수신 시각·기존 화면 이동 여부에 정수 밀리초와 숫자 릴리즈 버전만 추가합니다. `X-Vibe-UI-Version`의 `v0.86.179`와 같은 버전만 정규화하며 브랜치명·사용자 정의 문자열·누락값은 빈 값으로 저장하고 ‘버전 확인 불가’로 표시합니다. 사용자·팀·IP·주소·검색어·프롬프트·응답 내용은 새로 저장하지 않습니다. 난수 방문 ID는 메모리에만 두고 서버에는 해시만 보존합니다.

최초 수신 시각과 최초 유효 측정값은 재전송으로 바뀌지 않습니다. 방문·표시 완료·기존 화면 이동의 수신 순서가 달라도 방문 수는 증가하지 않습니다. 수집 상한은 10만 방문, 보존은 30일이며 기존 주기적 정리·프로세스/호출자 수집 제한·2초 요청 예산을 유지합니다. 전송 실패 시 재시도하거나 인증 갱신을 유발하지 않습니다.

버전별 합계도 현재 조회자에게 허용된 기능만 대상으로 합니다. 동일 DB 스냅샷에서 기능별/버전별 통계를 읽으며, 방문 수 상위 20개 버전과 나머지 버전의 방문 수를 제공합니다. 구버전 기록의 측정 시간은 `NULL`로 유지합니다. 자동 마이그레이션이 기존 방문·이동 수·만료 시각을 보존합니다. 새 UI는 v0.86.179 미만 백엔드에 기존 이벤트만 전송하고, 구형 집계 응답에는 미지원 안내를 표시합니다.

## 검증과 남은 범위

SQLite와 PostgreSQL의 업그레이드·동시 수집·상한·중복·보존·권한 범위, HTTP의 엄격한 페이로드·옵트아웃·비밀값 비노출, 생성 OpenAPI 타입, React 라우터의 대기·중단·숨김·StrictMode, 내장 Go와 실제 브라우저의 수집/집계·한글·모바일 표·키보드·접근성·밝고 어두운 테마를 검증 대상으로 둡니다.

이 변경은 원 요구사항 36의 Page Load와 UI Version을 한정된 의미로 보완합니다. API 오류·JavaScript 오류는 후속 [v0.86.180 개발 후보](APP_UI_ERROR_OBSERVABILITY.md)에서 보완합니다. 변경 작업 성공률·권한 거부·전체 Preview 채택률 분모의 관측과 운영 안정성 인수는 별도 잔여입니다. 조회·변경 권한이나 기능의 Stable 승격, 전체 Phase 0–6 완료를 의미하지 않습니다.
