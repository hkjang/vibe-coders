# 입출력 모니터와 XView의 모델 목록 조회 표시

신규 콘솔의 입출력 모니터와 XView는 모델 목록을 확인하는 요청을 기본적으로 제외합니다. 반복되는 모델 탐색 요청이 실제 추론 요청을 가리지 않도록 합니다. 화면 상단의 **모델 목록 조회 포함**을 켜면 다시 볼 수 있으며, 주소 새로고침·공유와 XView 저장된 뷰에 선택이 유지됩니다.

제외 대상은 정확히 `/v1/models`인 엔드포인트와 `models_aggregate` 또는 `model_aggregate` 라우팅 사유입니다. 모델 이름이 비슷하다는 이유로 실제 추론을 숨기지 않습니다. 서버 조회 단계에서 페이지·표본 상한보다 먼저 제외하며, XView의 최초 조회·실시간 증분·모델별 요약·시계열·이상치에 같은 조건을 사용합니다. 모델 목록 요청만 새로 들어와도 실시간 전송 커서는 앞으로 진행하여 같은 구간을 반복해서 읽지 않습니다.

입출력 모니터에서 옵션을 바꾸면 이전 스크롤 보류 목록과 자동 선택 상세를 정리하고 조작한 스위치로 초점을 돌려줍니다. 페이지 커서는 표시 조건에 묶여 다른 조건에 재사용할 수 없습니다. 명시적으로 지정한 요청 상세는 기존 조회 권한에 따라 계속 열 수 있습니다.

기존 `/admin`과 일반 요청 목록의 기본 조회, 원본 로그 저장, 인증·팀 격리와 게이트웨이 전체 통계는 유지합니다. 기존 화면으로 이동하면 해당 화면의 조회 조건을 따릅니다. 로그를 삭제하거나 수집을 중단하지 않습니다. API의 선택 매개변수 `exclude_models=true`를 신규 두 화면이 기본으로 전달하며, 생략하거나 `false`를 지정한 기존 호출은 전체 요청을 반환합니다.

## 검증

SQLite race 158개(선택 검사 2개 제외)와 격리된 PostgreSQL race 18개를 통과했습니다. 실제 API에서 필터 없는 로그 보존·필터된 페이지와 커서 조건·잘못된 입력 거부·최초 산점도와 모델 집계를 확인했습니다. 저장소 검사에서 페이지 상한 전에 적용되는지, 모델 이름 오탐이 없는지, 모델 목록만 유입된 뒤 다음 추론과 보완 조회가 정상인지 검증했습니다.

관련 React·주소 검사는 194개가 통과한 뒤 새 검사 한 건의 잘못된 초점 matcher를 고쳐 해당 파일 2개를 통과했습니다. 최초 검사에서 빠진 URL 허용 키를 발견해 명시적인 참·거짓 검증과 함께 연결했으며, 기존 쿼리 기대값에 새 조건을 반영했습니다. 전체 회귀 재통과로 표현하지 않습니다.

생산 빌드 브라우저 33개를 재시도·제외·이미지 갱신 없이 통과했습니다. 1440px 밝은 화면과 390px 어두운 화면, 키보드 조작·초점·접근성, 포함 선택·새로고침, 실시간 증분 조건을 확인했습니다. 첫 실행의 32개 통과·1개 실패는 브라우저 시간을 진행한 직후 비동기 네트워크 관측을 기다리지 않은 검사였으며, 실제 요청과 새 응답 확인 뒤 판단하도록 고쳤습니다.

OpenAPI·린트·포맷·엄격한 타입·생산 빌드·실제 Go 내장 정적 경로·기존 관리자·통합 SBOM을 검증했습니다. 초기 전송은 284,177바이트이며 화면 48개와 선택 도구 9개가 기존 예산을 충족합니다. OpenAPI의 기존 선택 헤더 검사도 배열 위치가 아닌 이름으로 찾아 동일 계약을 검증하도록 보완했습니다. 원격 후보 리뷰·CI·실제 메인·공개 출고와 운영 Stable 승격 및 전체 Phase 0–6 인수는 별도입니다.
