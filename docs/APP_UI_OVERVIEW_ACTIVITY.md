# 운영 개요의 장애 신호·알림·관리 작업

v0.86.129 후보는 `/app/overview` 운영 상태 탭에 주의 신호와 최근 작업을 추가한다.
세 영역은 기존 관리자 권한과 저장 기록을 사용하고 독립적으로 갱신한다.
기간은 상단의 1시간·24시간·7일·30일 선택과 주소의 `range`를 따른다.

## 표시 범위

- 장애 신호는 기존 `Incidents`의 공급자별 시간대 집계를 공유한다. 대체 경로 전환 또는
  서버 오류가 각각 시간당 5건 이상인 인접 시간대를 묶으며, 두 건수는 중복될 수 있다.
  현재 UTC 시간대에 걸친 묶음을 먼저, 이후 시작 시각순으로 최대 5개 표시한다.
  전체 묶음 수와 현재 시간대 수는 표시 행에 한정하지 않는다. 표시 시각은 시간대 경계라
  선택 기간 밖까지 걸칠 수 있지만 집계 대상은 선택 기간 안의 요청이다.
- 현재 시간대 신호는 실제 장애 확정, 활성 사고 관리 상태, 실시간 연결 검사 또는 복구
  판정이 아니다. 신호가 없더라도 정상 상태라고 단정하지 않는다. 영향 사용자 집계는
  이 요약에서 제외하므로 사용자별 추가 쿼리를 실행하지 않는다.
- 최근 알림은 최신 5건의 지표·관측값·기준값·시각과 전송 상태를 보여준다. 전송 오류
  텍스트는 조회하지 않고 존재 여부만 확인한다. `delivered=false`이고 오류가 없는
  기록은 전송 대상 미설정 등을 포함하므로 실패로 단정하지 않는다.
- 최근 관리 작업은 최신 5건의 분류·작업 종류·시각을 보여준다. 알려지지 않은 작업은
  ‘기타 관리/작업 기록’으로 표시한다. 전체 변경 이력으로 이동해 상세 내용을 확인한다.
- 알림과 관리 작업의 ‘추가 기록’은 여섯 번째 행의 존재 여부이며 전체 건수가 아니다.

## 기존 API와 권한

`GET /admin/incidents/summary`, `/admin/alerts/summary`, `/admin/audit-logs/summary`는
기존 업무 로직과 저장 기록에 대한 메타데이터 투영이다. 모두 기존 `admin:read` 권한의
전체 운영 범위를 사용한다. 팀 전용 조회로 표시하지 않는다. 요청은 GET만 허용하며
`Cache-Control: no-store`, 엄격한 단일 `window` 파라미터를 적용한다.

기간은 `since` 이상, `generated_at` 미만이다. SQLite와 PostgreSQL에서 기존 공통
나노초 정렬식을 사용해 소수점 자릿수에 관계없이 같은 경계·정렬을 적용한다.
기존 `/admin/incidents`의 응답과 영향 사용자 조회는 유지한다.

알림 이름·웹훅·전송 오류 원문·관리자 식별자·변경 전후 값은 요약 SQL에서 선택하지 않는다.
작업 문자열은 서버의 제한된 분류로 변환하며 공급자 표시는 기존 외부 노출 검사를 거친다.
엄격한 OpenAPI/Zod 계약은 추가 필드를 허용하지 않는다. 기존 관리자 화면은 변경하지 않는다.

메뉴와 같은 기능 전환·역할·점진 배포 설정을 따른다. 정책·알림은 거버넌스의 조회 권한,
관리 작업은 시스템 설정 기능의 접근 권한도 필요하다. 숨긴 기능은 조회하지 않는다.
기존 화면 단계나 v0.86.129 미만 백엔드에서는 지원 안내와 허용된 상세 링크를 제공한다.
지원하지 않는 요약을 원문 API로 대체 조회하지 않는다.

## 갱신과 오류

현재 계정·팀·세션·조회 권한의 화면 수명에 조회를 연결한다. 조회 거부는 해당 영역의
기록과 캐시를 폐기하며 명시적 재시도로 복구한다. 일시 오류는 마지막 정상 데이터와
갱신 실패를 함께 표시한다. 다른 정상 영역은 계속 사용할 수 있다.
자동 갱신은 기존 설정을 따르며 숨겨진 브라우저 탭에서는 중지한다.

## 검증과 남은 인수

SQLite·PostgreSQL 계약 검사로 기간 경계, 나노초 순서, 최대 행 수, 권한, 저장소 실패,
원문 제외와 기존 사고 집계 정합성을 확인한다. React와 브라우저에서 기간 복원,
부분 실패·조회 거부·수동 재시도·기존 화면 이동·모바일·두 테마·키보드·접근성을 검사한다.
실제 Go 로그인에서는 관리자와 읽기 전용 관리자의 응답 필드와 화면 건수를 대조한다.

React 1,210개(83개 파일)·내장 Go 브라우저 102개·실제 Go/OIDC/SQLite 인증 50개·실제 Keycloak HTTPS 5개와 사용자 DB 검증·보고서와 실패 산출물 29개를 통과했다.
SQLite와 PostgreSQL 17 race 검사로 기간 경계·나노초 정렬·행 제한·권한·기존 집계 정합성·민감 원문 제외·실패 응답을 확인했다. 실제 관리자와 읽기 전용 관리자에서 API 필드 허용 목록과 화면 건수를 대조했다.
두 테마·1440/390px 시각 기준 4장을 직접 검토하고 키보드·axe·가로 넘침과 고정 비교를 통과했다. 초기 검사에서 상세 이동 대상의 모의 API 두 개가 누락된 것을 수정했다. 긴 집계 설명을 접고 기존 핵심 요약 아래에 활동 목록을 배치한 최종 코드로 소스·브라우저·실제 인증을 다시 검사했다. 기존 시각 기준과 비교 허용치는 유지했다.
타입·린트·포맷·실제 OpenAPI·통합 SBOM·기존 관리자와 도메인 Go 회귀·vet·번들 예산을 통과했다. 초기 압축 번들은 263,121바이트다. 최종 소스와 내장 산출물의 해시 일치를 확인했다.
후보 CI·리뷰·메인·정식 출고는 별도 진행하며 상태는 [인수 검증표](APP_UI_ACCEPTANCE.md)에 기록한다.
관리형 사고 수명주기, 알림 심각도·확인 처리, 대규모 운영 데이터의 응답 시간 실측,
운영 Preview 승인과 Stable 승격은 별도 인수로 남아 있다.
