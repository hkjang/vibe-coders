# 정책 상세의 기존 화면 연결

정책 검색 상세의 `기존 화면에서 열기`는 선택한 정책 ID를 보존해 기존 관리자에서
저장된 정책을 읽기 전용으로 엽니다. 같은 이름의 정책을 대신 선택하지 않으며,
로컬 로그인과 Keycloak SSO를 거친 뒤에도 같은 정책으로 돌아옵니다.

정책 ID, 이름, 상태, 우선순위, 적용 비율, 규칙 수와 생성·수정 시각을 표시합니다.
설명과 규칙의 조건·동작은 전체 내용을 페이지로 나누어 확인할 수 있습니다.
저장값이 0인 적용 비율은 기존 서버의 의미에 따라 전체 적용(100%)으로 표시합니다.
다시 조회와 내용 페이지 이동은 키보드로 사용할 수 있습니다.

기존 `GET /admin/policies`의 조회 권한을 그대로 사용합니다. 새 정책 조회 API나
업무 로직을 추가하지 않으며, 저장·시뮬레이션·승인·가져오기·긴급 중지를 실행하지
않습니다. 기존 화면 전체가 필요하면 `정책 전체 화면 열기`로 이동합니다.

`legacy_policy_detail` 기능 지원 여부와 운영자가 설정한 기존 화면 주소를 따릅니다.
이 기능을 지원하지 않는 서버와 사용자 지정 주소에는 정책 ID를 추가하지 않고,
기존 화면에서 정책을 다시 선택하도록 안내합니다. 전환 설정이나 현재 권한으로
기존 화면을 열 수 없으면 연결을 표시하지 않습니다.

잘못되거나 중복된 정책 ID는 조회하지 않습니다. 없는 정책과 조회 실패는 구분하며,
실패 응답 원문은 화면에 출력하지 않습니다. 화면 이동·로그아웃·인증 변경 후 도착한
이전 응답은 표시하지 않고 이미 표시한 정책 내용도 제거합니다. 기존 전체 정책
화면의 늦은 응답도 선택한 정책 상세를 덮어쓰지 못합니다.

검증 범위는 주소·권한·기능 지원 조합, 실제 기존 JavaScript 동작, 기존 정책 HTTP
계약, React 검색 상세 회귀, 모바일·데스크톱 접근성, 실제 Keycloak SSO 복귀와
SQLite의 조회 전후 정책·규칙 보존입니다. 운영 Preview 검증과 전체 Phase 0–6
인수 완료는 별도로 판단합니다.

SSO 복귀 주소의 경로와 쿼리는 따로 검증합니다. 정책 ID의 `/`가 쿼리에서 `%2F`로
인코딩되어도 로그인을 막지 않습니다. 외부 주소, 경로의 인코딩된 구분자, 경로 탈출,
역슬래시와 NUL 거부는 유지합니다. 이 문제는 실제 브라우저와 수정 전 Go 회귀
테스트로 재현했고, 수정 후 실제 Keycloak 로그인·복귀를 확인했습니다.
