# 프롬프트 제품 조회

v0.86.131 개발 후보는 `/app/prompts/library?tab=products`에 재사용 프롬프트 제품의 읽기 전용 목록을 추가한다. 기존 제품 등록·삭제, 템플릿 편집·활용과 `/admin` 화면은 유지한다. 로컬 검증을 마친 후보이며 원격 CI·메인·정식 출고와 운영 Stable 인수는 별도로 진행한다.

## 화면과 지표

- 제품 이름·분류, 원본 템플릿 상태, 등록 당시 요청·API 키 수, 현재 템플릿 누적 활용과 시각을 한글로 표시한다.
- 원본 상태를 전체·사용 중·사용 안 함·원본 없음으로 서버에서 필터링한다. 등록 시각과 ID의 기존 저장 순서를 사용하며 페이지당 25/50/100건을 조회한다. 조건·페이지·크기는 주소·뒤로 가기·새로고침에서 복원한다.
- 등록 시 요청·키 수는 기존 제품 생성 시 저장한 원본 지문 묶음의 스냅샷이다. 저장 필드 `distinct_users`의 실제 집계 대상은 API 키이므로 사람 수로 표시하지 않는다. 원본 지문을 연결하지 않은 제품의 기본 저장값 0은 미확인으로 표시한다. 이 화면은 원본 요청을 다시 집계하거나 등록 당시 기간을 추정하지 않는다.
- 현재 누적 활용은 연결된 템플릿의 확장 횟수다. 모델 호출 성공 건수·고유 요청 수·과금량과 구분한다. 템플릿이 없으면 저장된 제품 기록은 남되 현재 활용 횟수와 시각은 원본 없음으로 표시한다.
- 열 표시·순서·너비를 조정할 수 있으며 제품 이름과 원본 상태는 유지한다. 좁은 화면의 표는 키보드로 가로 이동한다.
- 일시적인 조회 실패에는 마지막 정상 자료와 재시도를 제공한다. 조회 거부에는 기존 보관함의 계정·권한 경계와 명시 재조회 절차를 적용한다. 빈 페이지에는 첫 페이지 이동을 제공한다.
- v0.86.131 미만 백엔드에는 안내만 표시한다. 원문 API로 우회하지 않으며, 대응하는 기존 등록 목록 화면이 없어 부정확한 상세 링크를 만들지 않는다. 공통 기존 관리자 홈 이동은 유지한다.

## 기존 API의 조회 방식

`GET /admin/prompt-products?view=metadata&state=all&limit=25&offset=0`은 기존 전체 운영 범위의 `admin:read` 권한 검사를 공유한다. 읽기 전용 관리자도 조회한다. 기본 GET·등록 POST·삭제 DELETE의 기존 업무 의미와 응답은 유지한다.

메타데이터 조회는 본문·설명·작성자·원본 지문·변경용 ID를 SQL에서 선택하지 않는다. 이름과 분류는 기존 표시 검사를 적용한다. 브라우저 계약도 추가 필드를 거부하고 캐시 전에 표시 검사를 거친다. 모든 자연어 개인정보 탐지를 보장하는 기능은 아니다.

총 건수와 페이지는 같은 읽기 트랜잭션에서 가져온다. 별도 페이지 요청 사이에 데이터는 바뀔 수 있다. 서버는 페이지 크기 100건·offset 1,000,000을 상한으로 두고 중복·미지원·잘못된 인자를 거부한다. 조회 오류를 정상 0건으로 바꾸지 않으며 음수·안전한 정수 범위를 넘는 저장값·잘못된 시각은 미확인으로 표시한다. 누락된 템플릿의 활용 횟수도 임의로 0으로 바꾸지 않는다.

## 검증 계획과 남은 범위

SQLite·PostgreSQL의 원본 상태·페이지·기존 목록 정합성, 권한·민감 필드 제외·조회 오류와 계약을 검증한다. React와 브라우저는 페이지·주소 복원, 조회 거부·재시도·오류, 원본 없음·키 수 의미, 두 테마·모바일·키보드·접근성을 확인한다. 실제 Go 인증에서 관리자·읽기 전용 관리자의 31건 페이지와 원본 없음 필터를 대조한다.

초기 단위 검사에서는 템플릿 등록이 전달받은 활용 횟수 대신 0으로 생성한다는 기존 계약에 맞게 fixture를 수정했다. 활용 기록은 기존 `TouchPromptTemplate`으로 만든다. UI 오류 문구 검사의 기대값 두 곳도 제품 화면의 문구에 맞춰 수정했다. 최종 검증·출고 결과는 확인 뒤 갱신한다.

초기 PostgreSQL 검사의 테스트 데이터 하나가 기존 정수 열의 범위를 넘었다. 저장소 검사는 저장 가능한 음수 값을 사용하고 브라우저의 안전한 정수 상한은 별도 표시 함수 검사로 분리했다. 초기 실패를 최종 통과로 계산하지 않으며 실제 두 DB 검사를 다시 확인한다.

제품 생성·삭제와 원본 변경 영향 검토, 프롬프트 단계별 승격, 전체 Phase 0–6 및 운영 Stable 인수는 계속 진행한다.
