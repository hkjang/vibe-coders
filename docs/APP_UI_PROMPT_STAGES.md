# 프롬프트 단계 관리

`/app/prompts/library?tab=promotions`에 v0.86.132부터 단계 관리 미리보기를 제공한다. 로컬 검증을 마친 후보이며 원격 CI·메인·정식 출고와 운영 Stable 인수는 별도로 진행한다. 기존 `/admin`과 기본 `/admin/prompts/promotions` 계약을 유지한다.

## 조회와 집계 의미

기존 API의 `view=workspace`를 사용한다. 실험·검증·운영 단계, 최근 1시간·24시간·7일·30일, 25·50·100개 페이지를 주소에 보존한다. 단계가 등록된 버전은 선택 기간의 호출이 0건이어도 표시한다. 미등록 버전은 기간 내 이름·버전이 함께 기록된 호출이 있을 때 기본 실험 단계로 표시한다.

전체 건수·페이지·등록 상태·관측 기록은 같은 DB 읽기 스냅샷으로 구한다. 저장 시각은 UTC이며 기간은 시작 이상·종료 미만이다. UTC 나노초 경계를 비교하기 전에 원본 시각 인덱스로 범위를 줄인다. 여러 사용량·평가 레코드가 하나의 요청에 연결돼도 호출 수를 중복 집계하지 않는다. 기존 승격 기준과 조회 API도 같은 집계 함수를 사용한다. 평가 실패는 실패 평가 레코드 수이며 한 요청당 여러 건일 수 있다. 기준 충족은 참고 정보이며 수동 변경을 제한하거나 품질을 보증하지 않는다.

본문·응답·과거 사유·작업자 정보는 화면 응답에 포함하지 않는다. 안전하게 표시할 수 없는 이름·버전은 숨기고 변경을 막는다. 알려지지 않은 과거 단계도 미확인으로 표시하고 덮어쓰지 않는다. 401/403에서 이전 조회를 폐기하며 계정/권한 전환 간 캐시를 공유하지 않는다. 일시 오류에서는 마지막 정상 자료와 실패를 함께 표시한다.

## 수동 변경

`admin:write`와 화면의 편집 허용이 필요하다. 현재 단계와 다른 대상을 선택하고 한 줄 사유(최대 500자)를 입력한다. 전후 단계·대상 버전을 확인한 뒤 확인란을 선택해야 저장할 수 있다. 단계나 사유를 다시 수정하면 확인이 해제된다. 저장하지 않은 입력은 이동·닫기 전에 경고한다. 비밀정보 형태의 이름·사유는 서버와 클라이언트에서 검사한다.

`POST /admin/prompts/promotions?view=workspace`는 조회한 상태의 HMAC 리비전을 요구한다. 리비전은 이름·버전·등록 여부·단계·기존 사유·작업자·갱신 시각을 포함하며 원문을 노출하지 않는다. 먼저 리비전을 확인한 뒤 조건부 UPDATE 또는 충돌 없는 INSERT와 `prompt.promotion.set` 감사를 같은 트랜잭션으로 커밋한다. 기존 API 쓰기와 경쟁해도 같은 행 조건/고유 키가 충돌을 감지한다. 감사 삽입이 실패하면 단계도 되돌린다. 409는 재검토를 요구하며 성공 확인이 불확실하면 자동 재시도하지 않는다.

단계는 관리 기록이다. 모델 배포·라우팅·실제 트래픽을 변경하지 않는다. 기존 자동 승격 API의 기준은 그대로 사용하며 신규 화면은 수동 변경만 제공한다. 자동 일괄 승격의 전체 변경 비교와 일괄 감사 개선은 후속 범위다. 기존 조회가 DB 오류를 빈 자료로 숨기던 부분은 오류로 반환하도록 수정한다.

## 검증 범위

SQLite/PostgreSQL의 페이지·기간 경계·다중 기록 집계, 동시 생성/수정과 오래된 리비전, 감사 실패 롤백을 검사한다. React 폼의 필수 확인·사유·권한 회수·충돌·불확실 응답과 조회 수명주기를 검사한다. 실제 로그인 브라우저에서 관리자의 단일 변경·충돌과 읽기 전용 사용자의 직접 API 거부를 확인하고 DB에서 정확히 한 번 저장된 사유/작업자 감사를 검증한다. 화면은 두 테마·데스크톱/모바일 시각 기준, 키보드와 axe 접근성을 검사한다. 소스 검사·실제 인증·원격 CI·릴리스 결과는 완료 후 기록한다.

## 로컬 검증 결과

관련 React 1,311개(68개 파일)·내장 Go 브라우저 104개·실제 Go/OIDC/SQLite 인증 56개·실제 Keycloak HTTPS 5개와 사용자 DB 검증·보고서와 실패 산출물 29개를 통과했다. 전체 store/proxy/appui Go 테스트·vet, SQLite·PostgreSQL 17 race와 자연 실행 계획, 실제 서버 OpenAPI·생성 계약·SBOM·타입·린트·포맷·번들 검사를 통과했다. 두 테마·1440/390px의 목록과 폼 시각 기준 8장, 키보드 복귀·필수 확인·미저장 경고·axe를 검토했다. 변경 버튼은 첫 번째 열에서 바로 이용하며 기존 시각 기준과 비교 허용치는 유지했다. 초기 압축 번들은 264,449바이트다.

전체 API 문서가 1MiB를 넘어 기존 정책 계약 테스트의 읽기 한도에 잘리던 문제는 문서 GET에만 2MiB 한도와 명시적 초과 실패를 적용했다. 정책 응답 한도와 운영 API 동작은 바꾸지 않았다. SQL 평가 집계는 요청 ID 인덱스를 사용하며 두 DB의 자연 실행 계획으로 확인한다.
