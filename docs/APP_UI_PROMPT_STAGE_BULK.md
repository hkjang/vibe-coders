# 프롬프트 일괄 승격 검토

v0.86.133 개발 후보는 `/app/prompts/library?tab=promotions`의 **일괄 승격 검토**에서 기존 호출·평가 기준으로 버전을 한 단계 승격한다. 기존 `/admin`과 기본 자동 승격 API를 유지한다. 모델 배포·라우팅·실제 트래픽은 변경하지 않는 관리 단계 기록이다.

## 검토 범위와 사용자 흐름

선택한 1시간·24시간·7일·30일의 모든 관측 버전이 대상이며 목록의 현재 페이지와 단계 필터는 적용하지 않는다. 전체 변경 대상, 기준 미충족 또는 승격 불가 수, 버전별 현재/다음 단계와 호출·오류·평가 실패를 표시한다. 긴 목록은 검토 창 안에서 25개씩 확인하며 전체 대상 수는 계속 표시한다. 평가 실패는 실패한 평가 레코드 수여서 한 호출당 여러 건일 수 있다.

등록된 단계가 있어도 기간 내 호출이 없으면 자동 승격 대상이 아니다. 알 수 없는 단계는 승격하지 않는다. 기준을 충족한 버전 중 안전하게 표시하거나 변경할 수 없는 이름·버전이 있으면 전체 적용을 차단한다. 동기 검토는 관측 버전 1,000개까지 지원한다. 이를 넘으면 기간을 줄이라는 오류를 반환하며 일부 대상만 적용하지 않는다. 더 큰 작업의 비동기 처리는 후속 범위다.

검토는 원래 시작·종료 시각과 데이터를 고정한다. 전역 새로고침·탭 포커스 복귀가 검토 내용을 바꾸지 않는다. 변경 사유와 전체 대상 수를 입력하고 확인란을 선택한 뒤 적용한다. 사유나 대상 수 입력을 수정하면 확인을 해제한다. 미저장 닫기 경고, 키보드 초점 복귀, 좁은 화면의 표 가로 이동과 고정 하단 버튼을 제공한다. 읽기 전용 관리자는 검토할 수 있지만 적용할 수 없다.

## 서버 정합성과 감사

기존 `/admin/prompts/promotions`의 `view=promotion-review` GET/POST를 사용한다. 기존 `eligibleNextStage`, 승격 기준, 요청별 집계를 공유한다. GET은 관측 기록과 등록 단계를 하나의 SQL 스냅샷에서 읽고 작업자·기간·전체 관측 상태·승격 기준에 묶인 HMAC 검토 리비전을 발급한다. 본문·기존 사유·작업자 원문은 브라우저에 반환하지 않는다. 검토 유효 시간은 5분이다.

POST는 같은 절대 관측 범위를 트랜잭션에서 다시 조회하고 HMAC을 비교한다. 늦게 추가된 요청·평가나 단계·기존 사유·작업자·갱신 시각이 다르면 409로 전체 적용을 거부한다. 다른 작업자의 리비전, 만료된 리비전과 적용 후 재전송도 거부한다. 검토 조회 이후 다른 관리자가 단계를 변경하면 행별 조건부 쓰기가 충돌을 감지한다. 요청·평가는 적용 트랜잭션의 재조회 시점을 기준으로 판정한다.

모든 단계 변경과 대상별 이전/이후 단계·불투명 참조·사유를 담은 `prompt.promotion.auto` 감사 한 건을 함께 커밋한다. 어느 행이나 감사 삽입에 실패해도 전부 롤백한다. 외부 호출과 자동 재시도는 트랜잭션에 포함하지 않는다. 응답을 확인하지 못하면 자동 재전송을 막고 새 조회로 상태를 확인하게 한다. 기존 공통 인증과 서버의 읽기/쓰기 권한 검사를 유지한다.

## 검증과 인수

SQLite·PostgreSQL의 기간 경계, 전체 적용, 중간 항목/감사 실패 롤백, 동시 검토를 검증한다. 서버의 만료·위조·다른 작업자·늦은 요청/평가·재전송·읽기 권한, React의 필수 사유/대상 수/확인·초안 유지·전역 갱신·권한 회수·불확실 응답을 검사한다. 실제 Go/OIDC 브라우저와 DB에서 두 대상의 단계와 단일 감사를 확인하고, 두 테마와 데스크톱/모바일에서 키보드·axe·시각 기준을 확인한다.

관련 React 1,336개(70개 파일)·내장 Go 브라우저 113개·실제 Go/OIDC/SQLite 인증 58개·실제 Keycloak HTTPS 5개와 사용자 DB 검증·보고서와 실패 산출물 29개를 통과했다. 전체 store/proxy/appui Go 테스트·vet, SQLite·PostgreSQL 17 race, API 표면·실제 서버 OpenAPI·생성 계약·SBOM·타입·린트·포맷·번들 검사를 통과했다. 두 테마·1440/390px 검토/확인 화면 8장을 검토하고 키보드·고정 버튼·가로 넘침·axe를 확인했다. 초기 압축 번들은 264,554바이트다. 기존 시각 기준과 비교 허용치를 유지했다. 초기 시각 검토에서 모바일 검토 창 내부의 가로 넘침을 발견해 표 컨테이너의 최소 너비를 제한했다. 창 내부 넘침·표의 키보드 좌우 이동 검사를 추가한 뒤 React·빌드·실제 인증을 다시 검증했다. 이후 브라우저 검사만 기본 키보드 스크롤 완료 이벤트를 기다리도록 보완하고 고정 시각 기준으로 전체 브라우저를 재검증했다. 운영 소스와 에셋은 실제 인증 검증본과 동일하다. 원격 후보 CI·리뷰·메인·정식 배포 검증과 운영 Stable 인수는 별도로 진행한다.
