# 진행 중 요청의 할당량 표시

사용자 관리의 `할당량` 표는 완료된 요청의 사용량과 진행 중 요청이 확보한 사용량을 함께 표시합니다. 예를 들어 완료된 사용량이 12토큰이고 진행 중 요청이 26토큰을 확보했다면 `38 / 1,000`과 `진행 중 26 토큰 포함`을 표시합니다. 비용도 같은 방식으로 표시하며, 요청 완료 후 재조회하면 실제 사용량으로 갱신됩니다.

진행 중 사용량은 최종 청구액이 아닙니다. 요청 완료·실패에 따라 확보한 양이 해제되고 서버가 기록한 실제 사용량으로 바뀝니다. 사용률과 한도 없음 표시는 기존 서버 값을 따릅니다. 예산 지출은 기존 확정 비용을 유지합니다. 조회 화면은 사용량이나 한도를 변경하지 않습니다.

좁은 화면에서는 표 안에서 가로로 이동해 토큰·비용을 확인합니다. 진행 중 안내도 표의 글자 크기와 사용자 글자 확대 설정을 따릅니다. 예약량이 없거나 이전 서버에서 필드를 제공하지 않으면 기존 확정 사용량만 표시합니다.

## 검증 범위

현재 선행 후보의 실제 Go 바이너리와 격리된 SQLite에서 요청 한 건을 진행 중으로 유지했습니다. 서버와 기존 관리자 화면은 25토큰·25원을 표시하고 후속 요청을 429로 거부했지만 신규 화면은 0을 표시하는 차이를 재현했습니다. 보완 후 같은 조건에서 두 화면 모두 25토큰·25원을 표시합니다. 요청 완료 후에는 확보량이 0으로 해제되고 두 화면이 실제 6토큰·6원을 표시합니다. 예산 지출은 6원이며 브라우저의 변경 API 호출은 없습니다. 외부 네트워크 없이 로컬 합성 공급자 한 건만 사용했습니다.

관련 React 63개와 브라우저 43개를 통과했습니다. 합산·완료 후 갱신·구형 응답·무제한·소수점 비용, 읽기 전용, 1440px 밝은 화면과 390px 어두운 화면의 글자 확대·접근성·열 경계를 확인했습니다. 모바일 토큰·비용 열로 이동하는 후속 브라우저 2개도 통과하고 실제 화면을 검토했습니다. 최초 테스트 준비 데이터의 누락 필드와 조회 옵션·타입 오류는 기록하고 수정했으며 제품 합산 방식이나 검사 기준을 완화하지 않았습니다.

OpenAPI 계약, 린트, 포맷, 엄격한 타입, 생산 빌드, 성능 예산과 통합 SBOM을 확인했습니다. 실제 단일 Go 바이너리의 직접 주소·캐시·누락 에셋·메서드·기존 관리자·OpenAPI도 검증했습니다. 후보 리뷰·CI, 메인 병합·CI와 정식 배포 파일 검증은 [인수 검증표](APP_UI_ACCEPTANCE.md)에 구분합니다. 운영 Stable와 전체 Phase 0–6 인수는 계속 진행합니다.
