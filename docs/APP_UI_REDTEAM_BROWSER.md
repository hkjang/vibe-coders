# 레드팀 실행 업무의 실제 브라우저 검증

v0.86.141 후보는 새 콘솔의 검토·실행 업무를 브라우저부터 기존 Go API, 제공자 호출, 결과 저장과 감사까지 연결해 검증한다. 화면의 범위·실행 방식·호출 오류와 증적 항목을 한글로 표시한다.

## 권한 안내

조회 전용 계정은 캠페인의 실행 버튼을 사용할 수 없다. 유효한 계정이 직접 캠페인 상세 작업 API에 접근하면 `X-Vibe-UI: app` 요청은 403과 `redteam_permission_denied`를 반환한다. 공통 인증 검사를 재사용하며 이 헤더가 권한을 부여하지 않는다. 인증 정보가 없거나 유효하지 않으면 401을 유지한다. 현재 권한을 확인하는 도중 요청이 취소되면 503을 반환하고 변경하지 않는다. 기존 관리자 요청의 401 응답은 유지한다.

## 업무 시나리오

| 흐름 | 확인 내용 |
| --- | --- |
| 시뮬레이션 | 검토 취소 후 호출 없음, 새 검토로 결과 저장 |
| 실제 모델 호출 | 캠페인 이름 확인, 호출·출력 토큰 상한, 저장과 실행 이력 |
| DB 저장 실패 | 실제 DB 오류 뒤 추가 호출 중단, 완료 표시·자동 재전송 금지 |
| 제공자 주소 변경 | 검토하지 않은 주소로 이동하지 않고 호출 오류로 표시·저장 |
| 조회 전용 계정 | 버튼 차단 및 실제 API의 403 응답 |
| 검토 후 캠페인 변경 | 기존 검토의 실행 거부, 자동 재전송 금지 |

후속 한 건 재실행 검증은 다음 두 업무를 추가한다. 검토 뒤 단일 제공자 호출과 별도 실행·증적 저장, 원본 복귀를 확인하고, 실제 DB 기록 오류 시 미확정 안내와 자동 재전송 금지를 확인한다. 저장된 원본 실행·결과·증적, 캠페인과 해당 대상 기준선의 동일성 및 새 실행의 원본 결과 ID·검토 ID·감사 이력은 Go에서 독립적으로 검사한다. 실행 이력 탐색 후보는 읽기 전용 계정으로 127개 이력의 마지막 페이지·상세 주소·새로고침·뒤로 가기를 추가 검사한다. 현재 실행 묶음은 9개 모두 첫 시도 통과해야 보고서가 성공으로 판정한다.

격리된 SQLite와 실제 로그인·JWT, 내장 React 자산, 로컬 HTTP 제공자를 사용한다. 브라우저 요청의 API 응답을 모의 응답으로 대체하지 않는다. 실제 제공자 호출 수, 검사 결과·증적과 감사 기록도 서버 측에서 확인한다. 운영 계정·운영 데이터·외부 모델은 사용하지 않는다.

실패 보고서는 성공 여부·검사 수·소스 행 번호만 기록한다. 자격 증명, 실행 키, 오류 원문, 브라우저 스냅샷·추적·동영상은 남기지 않는다. 기존 제공자 연결 검사의 보고서 구현을 공유하며 해당 검사도 함께 검증한다.

## 검증 결과 및 한계

관련 React 1,161개(55개 파일), 내장 화면·시각·키보드·접근성 회귀 94개, 실제 Go/OIDC 인증 60개, 실제 Keycloak HTTPS 5개와 사용자 DB 검증, 실제 제공자 연결 업무 1개, 새 레드팀 실제 업무 6개 및 보고서·실패 산출물 35개를 통과했다. Go proxy/store/appui 전체 회귀·vet, SQLite·PostgreSQL 17 race, 실제 Go OpenAPI·생성 타입·API 표면, 린트·포맷·빌드·통합 SBOM을 검증했다. 초기 전송 번들은 265,434바이트다. 후보 CI·리뷰·메인·공개 출고 검증은 순차 진행한다. 실제 업무 브라우저 검증은 SQLite 기준이며 PostgreSQL의 저장·동시성은 별도의 Go race 검증으로 확인한다. 운영 Preview, 서버 간 작업 잠금·프로세스 복구와 Stable 승격은 후속 인수 항목이다. 전체 Phase 0–6 목표는 계속 진행한다.
