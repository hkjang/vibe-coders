# 레드팀 검토별 실행 추적

v0.86.174 후보의 수동 캠페인 실행은 [영속 작업 접수와 상태 조회](APP_UI_REDTEAM_EXECUTION_JOBS.md)를 추가합니다. 아래는 v0.86.148의 검토별 이력 추적 구현 당시 범위와 검증 기록입니다. 이전 서버와 기존 동기 실행은 계속 지원합니다.

v0.86.148 개발 후보는 캠페인 실행 검토와 실행 이력을 연결한다. 검토를 마친 실제 호출과 시뮬레이션은 각 실행 행을 만들 때 검토 ID를 함께 저장한다. 실행 중, 완료 후 또는 응답을 받지 못한 경우 같은 검토로 정확히 조회할 수 있다.

- 실행을 전송한 뒤 최종 확인 패널에서 `이 검토의 실행 이력`을 연다. 실행 중에도 사용할 수 있다.
- 이전 상태·날짜·재실행·페이지·상세 필터를 초기화하고 캠페인 ID, 검토 ID, 캠페인 실행 유형만 적용한다. 주소 공유와 새로고침을 지원한다.
- 화면 이동은 실행 재전송이나 취소 요청을 하지 않는다. 늦게 받은 응답이 이력 화면을 실행 결과 패널로 바꾸지 않는다.
- 이력에 행이 없다고 외부 호출이 없었다고 판단하지 않는다. 등록 전이거나 저장·응답 확인이 필요할 수 있다. 새로고침으로 확인하며 자동 재실행하지 않는다.
- 주소에는 검토 토큰·실행 키·사유·프롬프트를 넣지 않는다. 잘못된 ID와 알려진 자격 증명 형식은 링크에 사용하지 않는다.
- v0.86.147 이하에서는 캠페인 실행에 검토 ID가 저장되지 않으므로 바로가기 버튼을 표시하지 않는다. 과거 실행의 ID를 추정하거나 소급 생성하지 않는다.

기존 `/admin`·API·권한·실행 계획·저장 로직을 재사용한다. 기존 `review_id` 열과 이력 조회를 사용하므로 DB 마이그레이션은 없다. 한 건 재실행은 기존 원본 결과 ID와 검토 ID를 유지한다. 기존 예약·Legacy 실행에는 검토 ID를 새로 부여하지 않는다. 응답의 실행별 검토 ID는 이전 서버 호환을 위해 선택 항목이며, 있으면 상위 검토와 일치하는지 검사한다.

수정 전에는 실행 중·완료 후 두 경우 모두 검토 ID 검색이 0건이 되는 문제를 재현했다. 실행 중 기록, 실제 호출·시뮬레이션 완료, 검토 간 분리, 기존 재실행과 구분, 응답 지연·오류 후 이력 이동, 필터 초기화·새로고침·이전 서버 호환을 검증한다. 전체 React 6,526개(462개 파일)와 기본 Node 검사 57개를 통과했다. 외부 산출물 선택 검사 15개는 기본 Node 명령의 제외 항목이며 이번에 별도 실행했다고 주장하지 않는다. 이후 모바일 오류 안내 가시성을 보완한 최종 소스에서 관련 React 30개, 내장 브라우저·시각·키보드·접근성 회귀 150개(건너뜀·재시도·불안정 결과 없음), 실제 Go·SQLite·로컬 제공자·저장·감사 업무 11개를 통과했다. 전체 Go 테스트·vet·API 표면(423경로/482 OpenAPI/369 React 연결), SQLite·PostgreSQL 관련 race 218개, 실제 Go OpenAPI 생성 계약과 타입·린트·포맷·빌드·번들 예산을 검증했다. 최종 초기 전송 크기는 267,901바이트이며 통합 SBOM은 19 Go/389 npm 패키지다. 두 테마·1440/390px 기준 이미지 8장을 직접 확인했다. 모바일 오류 가림을 두 실패로 재현하고 스크롤 여백을 보완한 뒤, 전체 안내의 가시성 조건을 유지한 채 이미지 갱신 없이 최종 회귀를 통과했다. 후보 CI·독립 리뷰·선행 공개 릴리즈와 실제 메인·공개 출고는 별도 검증한다.

실행은 기존 최대 120초의 동기 호출이다. 전역 비동기 작업, 다중 서버 실행 소유권, 프로세스 장애 복구, 운영 Preview 검증 및 Stable 승격은 후속 항목이며 이 변경으로 완료되지 않는다.
