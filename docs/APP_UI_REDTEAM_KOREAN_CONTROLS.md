# 레드팀 검사 설정의 한글 안내

v0.86.142 후보는 `/app/redteam`의 대상·검사 묶음, 캠페인 설정과 검사 편집에서 기존 API 식별자와 화면 표시를 분리한다. 정책·평가 방식·심각도·대상 유형을 한글로 선택하며 원래 API 값으로 저장한다. 기존 관리자와 백엔드 실행·권한·저장 계약은 유지한다.

## 설정과 적용 범위

- 검사 편집에서 제공자·모델·AI 앱·MCP 도구·자연어 SQL·워크플로를 체크박스로 선택한다.
- 선택한 유형이 있으면 해당 유형에만 적용한다. 마지막 선택을 해제하면 **선택 없음 — 모든 대상 유형에 적용합니다**를 즉시 표시한다. 이는 기존 빈 `target_types` 계약과 같다.
- 사용자 정의 유형은 알려진 유형을 선택·해제해도 보존한다. 고급 입력에서 식별자를 직접 확인·수정할 수 있다.
- UI가 아직 알지 못하는 정책·평가 방식·심각도는 **등록된 값**으로 표시한다. 기존 값을 임의의 기본값으로 바꾸지 않는다.
- 대상 목록·상세·개요·검사 결과에서 위험도와 알려진 유형을 한글로 표시한다.
- 원래 리소스 이름, 유형 식별자와 CSV의 기계 판독 값은 보존한다. 새 선택 UI가 실행 권한이나 실제 호출 대상 지원 범위를 넓히지 않는다.

긴 편집창은 본문만 스크롤하며 저장·취소 버튼을 화면 안에 유지한다. 검사 묶음과 검사라는 명칭을 사용하고, 캠페인 설정의 설명을 **제한된 실제 실행** 선택 항목과 맞춘다. 변경 내용 경고와 저장 중 중복 제출 방지는 기존 공통 폼을 사용한다. 검사 묶음 상세 안에서 편집·삭제 확인을 닫으면 해당 작업 버튼으로 포커스를 복원하며, 바깥 상세 창의 복귀 위치와 구분한다.

## 검증 결과

최종 수정에서 관련 React 1,184개(57개 파일), 내장 화면·시각·키보드·접근성 회귀 101개와 실제 레드팀 업무 6개를 통과했다. 두 테마·1440/390px의 승인된 시각 기준 8장은 변경 없이 통과했다. `__proto__`·`constructor` 같은 사용자 정의 값은 사전에 직접 정의한 항목만 조회해 안전한 문자열로 표시하며 기존 API 값으로 저장한다. 수정 전 실패 재현과 20개 표시 회귀, 브라우저 편집·저장으로 확인했다. 최종 타입·린트·포맷·OpenAPI 생성 계약·빌드·번들 예산을 검증했고 초기 전송 번들은 265,409바이트다. 이전 빌드에서 Go proxy/store/appui 전체 회귀·vet, SQLite·PostgreSQL 17 race, 실제 Go OpenAPI·API 표면·통합 SBOM, 실제 Go/OIDC 인증 60개, Keycloak HTTPS 5개와 사용자 DB, 실제 제공자 연결 업무 1개 및 보고서·실패 산출물 35개를 검증했다. 이번 표시 보완은 해당 Go·인증·제공자·보고서 소스를 변경하지 않았으며, 수정한 자산의 화면 및 실제 레드팀 흐름을 다시 검증했다. 설정 브라우저의 API 응답은 공개 합성 fixture이며 실제 실행 업무의 Go·SQLite·로컬 제공자 검증과 구분한다. 한글 선택이 기존 식별자로 저장되는지, 사용자 정의 값 보존, 빈 선택의 전체 적용, 편집창의 저장·취소 버튼 표시와 포커스 복귀를 확인했다. 후보 CI·리뷰·메인·공개 출고와 운영 Preview·Stable 및 전체 Phase 0–6 인수는 계속 진행한다.
