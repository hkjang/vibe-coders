# 레드팀 사전 점검

`/app/redteam?tab=campaigns`의 **사전 점검**에서 실제 모델 호출 없이 대상과 예상 비용을 확인한다. v0.86.137은 기존 API의 응답을 사용하며 실행·승인·예산 계산 규칙은 바꾸지 않는다. 기존 API는 점검에 앞서 등록 대상 목록을 동기화하므로 쓰기 권한 요구를 유지한다.

## 읽는 순서

- 상단에서 예산 초과와 추가 승인 필요 여부를 먼저 확인한다.
- **대상과 예상 규모**에는 대상·검사 묶음·검사 횟수·지정 모델과 비용 추정치를 표시한다. 빈 검사와 지정 모델 없음도 안내한다.
- **승인과 실제 호출 조건**에는 저장된 승인 상태, 모드별 승인 조건, 호출 가능한 유형·외부 공급자·위험 MCP 대상 수를 분리한다.
- **실행 한도**에는 예산 비교, 호출 속도와 저장된 동시 실행 수·제한 시간을 표시한다. 저장된 동시 실행 수와 제한 시간의 전체 호출 적용을 보장하지 않는다.
- **점검 식별자와 서버 안내**에서 캠페인 식별자와 서버 안내 원문을 확인할 수 있다.

`can_run`은 승인 조건만 뜻한다. 호출 없는 모드는 고위험 검사라도 미승인 상태에서 이 조건을 충족할 수 있고, 예산 초과·긴급 중지·키 권한·연결 실패는 별도로 실행을 막을 수 있다. 화면은 이를 전체 실행 가능 여부나 실제 호출 완료로 표시하지 않는다. 점검 창은 실행이나 승인 작업을 제공하지 않는다.

실제 API 클라이언트에서 필수 상태·수치·한도와 요청한 캠페인 식별자를 확인한다. 누락·문자열 불리언·음수·잘못된 개수를 정상 또는 0으로 바꾸지 않는다. 잘못된 응답은 창을 열지 않고 기존 공통 오류 안내를 제공하며 사용자가 다시 점검한다. 한 캠페인 점검 중에는 다른 행의 점검 버튼도 잠근다. 요청의 인증 자동 재전송도 하지 않는다.

결과는 점검 당시의 값이며 확정 실행 검토 토큰이 아니다. 운영 Stable 인수, 실제 실행 전 검토와 예산·토큰 상한 강화, 다중 서버 긴급 제어는 후속 범위다.

## 검증

관련 React 1,125개(52개 파일), 최종 내장 브라우저 72개, 두 테마·1440/390px 시각 기준 8장과 키보드·axe·반응형 검사를 통과했다. Go proxy/appui 회귀·vet, SQLite·PostgreSQL 17 race, 실제 Go OpenAPI·생성 타입·API 표면·린트·포맷·빌드·SBOM을 검증했다. 초기 압축 번들은 264,733바이트다. 실제 인증 60개·Keycloak HTTPS 5개와 사용자 DB·보고서 29개는 초기 화면 빌드에서 통과했다. 이후 캠페인 화면과 포커스 Hook 두 파일만 수정했고 백엔드·인증 소스 불변을 확인했다. 최종 내장 자산으로 브라우저 72개를 다시 통과했으며 시각 기준은 바꾸지 않았다.
