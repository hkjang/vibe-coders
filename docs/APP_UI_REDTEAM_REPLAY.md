# 레드팀 결과 한 건 재실행

새 콘솔의 실행 이력에서 결과 증적을 열고 **조건 검토 후 한 건 재실행**을 선택한다. 재실행 사유, 정확한 모델 이름, 출력 토큰 요청 상한과 비용 중단 기준을 입력한다. 이 단계에서는 모델을 호출하지 않는다.

최종 확인 화면에서 원본 결과 ID, 현재 검사와 묶음, 제공자·모델, 한 건의 호출, 예상 비용과 검토 만료를 확인한다. 원본 결과 ID를 입력한 뒤 **검토한 한 건만 실제 재실행**으로 전송한다. 기본값은 마스킹 보관이며 원문 보관은 매번 명시적으로 선택한다. 실행 키는 화면 메모리에서만 유지한다.

결과는 새 실행·검사·증적으로 기록한다. 새 실행에는 원본 결과 ID와 검토 ID가 저장된다. 원본 실행·판정·증적, 캠페인 상태와 검사 묶음의 기준선은 갱신하지 않는다. 저장 확인 후 **새 실행 결과 보기**로 이동할 수 있다. 응답 또는 저장이 불확실하면 완료로 표시하거나 자동 재전송하지 않는다. 실제 호출이 이미 발생했을 수 있으므로 새 이력과 감사를 먼저 확인한다.

## 적용 범위

기존 인증과 `admin:write`, 공통 실행 계획·제공자 호출·결과 저장 로직을 사용한다. 검토는 5분 동안 응답 서버와 사용자·캠페인·원본 결과에 결합하며 한 번 소비한다. 원본과 현재 검사·묶음·대상·제공자·설정이 달라지거나 검토가 만료되면 다시 검토한다. 캠페인 실행용 검토와 한 건 재실행 검토를 서로 사용할 수 없다. 실행 전 감사 기록이 실패하면 호출하지 않는다.

현재 단일 LLM 검사만 지원한다. Text2SQL·MCP·앱·워크플로와 다단계 가상 모델은 지원하지 않는다. 출력 토큰은 제공자 요청 상한이며 비용은 호출 후 확인하므로 실제 청구 한도를 보장하지 않는다. 서버별 캠페인 중복 실행 보호는 기존 관리자·예약 실행·다른 서버에 걸친 전역 잠금이 아니다. 프로세스 장애 후 자동 복구나 정확히 한 번 호출을 보장하지 않는다. 기존 `/admin` 재실행 API와 화면은 유지한다.

## 화면 및 배포

한글 조건 폼과 최종 검토, 고정 하단 작업 버튼, 모바일 본문 스크롤, 키보드 초점 복귀를 제공한다. 기존 Go 바이너리 안에 모든 자산을 포함하며 런타임 Node.js나 외부 CDN을 요구하지 않는다. SQLite·PostgreSQL의 실행 이력에 출처 열 두 개를 추가하고 기존 행은 빈 출처로 유지한다.

기능 구현 상태에서 전체 React 6,452개(455개 파일), 내장 화면·키보드·접근성·시각 회귀 117개, 실제 레드팀 업무 8개, 제공자 연결 업무 1개, 인증 60개와 Keycloak HTTPS 5개 및 사용자 DB·보고서 산출물 검사를 통과했다. Go 전체 테스트·vet와 SQLite·PostgreSQL 17 race에서 원본 보존, 출처 마이그레이션, 검토 교차 사용·정의 변경·권한·감사·저장 오류를 확인했다. 새 기능의 화면 검사는 공개 합성 응답을 사용하고, 실제 실행 업무는 모의 API 없이 별도 검사했다. 최종 v0.86.144 버전과 통합 SBOM·OpenAPI 계약을 반영한 자산에서도 화면 117개와 실제 레드팀 업무 8개를 통과했다. 초기 전송 번들은 265,823바이트다. 버전 적용 전후 인증·업무 소스의 동일성을 확인했다. 후보 CI·리뷰·메인·공개 출고 검증은 별도로 진행한다. 운영 Preview·Stable 승격과 전체 Phase 0–6 인수는 계속 진행한다.
