# 레드팀 실행 조건 검토

v0.86.139 후보는 `/app/redteam`의 수동 캠페인 실행을 준비 → 조건 검토 → 이름 확인 → 일회 실행으로 나눈다. 기존 `/admin`, 예약 실행과 기존 `/run` API는 유지한다. 기존 실행기를 재사용하며 고위험 팩 승인은 별도로 수행한다. 이 후보는 운영 Stable이나 전체 Phase 0–6 인수 완료를 의미하지 않는다.

## 운영 흐름

1. 캠페인을 저장하고 필요한 승인을 받는다. 실제 호출은 캠페인이 실제 실행 모드여야 하며 상단에 전용 실행 키를 입력해야 한다.
2. 실행을 열어 실제 호출 또는 시뮬레이션을 명시적으로 선택한다. 사유, 호출 수, 호출당 출력 토큰 요청 한도, 양수 비용 중단 기준을 입력한다. 필요하면 정확한 모델 이름을 한 줄씩 입력한다. 저장된 모델이 별표 패턴이면 구체적인 이름을 지정해야 한다.
3. 서버의 검토 응답에서 실제 호출과 시뮬레이션 대상, 모델, 검사 수, 등록된 입력 크기, 비용 추정치, 원문 증적 보관 여부와 만료 시각을 확인한다. 검토 중에는 모델 호출이나 모델 목록 자동 검색을 하지 않는다.
4. 캠페인 이름을 다시 입력한 뒤 한 번 실행한다. 승인 후 자동 실행하지 않는다. 실행 키를 바꾸거나 계정·권한·화면 전환 상태가 바뀌면 기존 검토를 이어 쓰지 않는다.
5. 중단·부분 완료·불확실한 응답은 실행 이력에서 확인한다. 인증 오류도 자동 재전송하지 않는다. 다른 서버나 재시작 후에는 새 검토가 필요하며 기존 `/run`으로 자동 우회하지 않는다.

## 서버 계약

- `POST /admin/redteam/campaigns/{id}/run-review`: 기존 관리자 쓰기 권한을 검증하고 캠페인·팩·검사·대상·모델·한도를 집계한다. 등록 목록이 1,000개 한도에 닿아 완전성을 확인할 수 없거나, 검사 수가 1,000회를 넘으면 검토를 거부한다.
- `POST /admin/redteam/campaigns/{id}/run-reviewed`: 사용자와 캠페인에 결합된 서버 로컬 검토 토큰을 소비한다. 토큰은 5분 만료이며 최대 4,096개까지만 보유한다. 실행 키와 입력 원문은 토큰 저장소에 보관하지 않는다. 같은 서버의 검토 실행끼리는 동일 캠페인의 동시 실행을 막는다.
- 검토 정의를 다시 읽어 해시를 비교하고, 실행 의도를 감사 DB에 기록한 다음 기존 실행기에 전달한다. 감사 결과를 확인하지 못하면 실행하지 않으며 토큰은 재사용할 수 없다. 모델 목록 자동 검색과 다른 모델로의 조용한 전환을 하지 않는다.
- 실제 제공자 설정으로 외부 호출 허용을 판단한다. 제공자·실행 설정과 Text2SQL 프로필의 해시는 실행 직전과 다음 호출 진입 때 확인한다. 해시에 쓰인 인증정보와 연결 문자열은 검토 응답에 포함하지 않는다.
- Text2SQL·MCP·앱·워크플로 대상은 이 검토에서 시뮬레이션만 수행한다. 실제 호출할 모델 이름에 Text2SQL·MCP 탐색·활성 에이전트 경로를 입력하면 검토를 거부한다. 검토 후 경로가 바뀌어도 가상 실행기에 진입할 때 다시 차단한다. Text2SQL의 생성·재검토·요약·백그라운드 비교 호출 전체를 묶는 한도는 후속 구현 대상이다. 일반 요청과 기존 실행 경로에는 이 제한을 적용하지 않는다.
- 검토한 실제 호출은 라우팅·정책 처리 후 제공자 전송 직전에도 출력 요청 한도와 단일·비스트리밍 응답 조건을 적용한다.
- 한 실행은 순차 처리하며 실제 모델 검사 최대 200회, 호출당 출력 토큰 요청 최대 4,096개, 전체 제한 시간 최대 120초다. 캠페인의 더 짧은 제한 시간이 있으면 그것을 사용한다. 등록된 검사 입력은 건당 최대 64KiB다.

## 한계와 인수 잔여 범위

비용은 실제 응답 사용량과 가격 설정 또는 기존 추정치로 계산한다. 비용 중단 기준은 다음 호출의 진입 조건이며 마지막 호출, 내부 재시도, 공급자 실제 과금의 상한이 아니다. 출력 토큰 요청은 공급자의 준수나 추론 토큰 사용량을 보장하지 않는다. 등록된 입력 크기는 실행 중 확장되는 전체 입력 크기를 보장하지 않는다.

현재 게이트웨이의 라우팅·권한·정책은 실행 때 적용된다. 설정 해시 비교는 다른 관리자나 다른 프로세스의 변경을 잠그는 트랜잭션이 아니다. 기존·예약·다른 서버의 실행을 전역 직렬화하지 않으며, 이미 전송한 호출의 즉시 취소도 보장하지 않는다. 호출 제한 시간이 끝난 뒤 결과 기록은 각 묶음별 별도의 최대 5초 정리를 시도한다. 다중 서버 환경에서는 동일 서버로 연결되는 구성 없이 검토가 거부될 수 있다. 결과·증적·완료 상태 기록은 기존 실행기의 최선 노력 방식이며 `complete`는 검토한 검사의 수행 여부를 뜻한다. 결과 저장의 원자성·내구성, 전역 작업 식별과 운영 Preview 평가를 후속 인수 항목으로 남긴다.

## 검증 상태

SQLite 및 PostgreSQL 17에서 실제 로컬 HTTP 제공자를 이용한 출력 토큰 요청, 모델 고정, 재실행 차단, 설정 변경 중단, JWT 조회·쓰기 권한, 감사 DB 실패와 토큰 만료·용량·동시 실행을 검증했다. 관련 React 1,151개(54개 파일), 최종 내장 브라우저 90개, 두 테마·1440/390px 시각 기준 4장과 키보드·axe·반응형 검사를 통과했다. 최종 내장 자산에서 실제 Go/OIDC/SQLite 인증 60개, Keycloak HTTPS 5개와 사용자 DB, 보고서·실패 산출물 29개를 검증했다. Go proxy/appui 전체 회귀·vet, SQLite·PostgreSQL 17 race, 실제 Go OpenAPI·생성 타입·API 표면·린트·포맷·빌드·통합 SBOM을 검증했다. 초기 전송 번들은 265,290바이트다. 내장 브라우저의 레드팀 응답은 공개 합성 fixture이며, 실제 모델 제공자 호출은 Go의 로컬 HTTP 제공자 검사로 검증한다. 후보 CI·리뷰와 실제 메인·공개 출고 검증은 별도 게이트로 유지한다.
