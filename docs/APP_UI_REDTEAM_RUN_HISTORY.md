# 레드팀 실행 이력 탐색

v0.86.145 후보는 `/app/redteam?tab=runs`에서 전체 실행 이력을 페이지 단위로 조회한다. 기존 `/admin`과 매개변수 없는 `GET /admin/redteam/runs`의 최근 100건 응답은 유지한다.

## 화면 사용

- 실행 상태·방식·이력 종류를 고르고 **조건 적용**을 누른다. 식별자 상세 조건은 실행·캠페인·원본 결과·검토 ID가 정확히 일치하는 이력을 찾는다.
- 기간은 시간대를 포함한 ISO 8601로 시작과 종료를 함께 입력한다. 시작은 포함하고 종료는 제외한다. 나노초 단위 경계도 보존한다.
- 정렬은 최대 세 항목의 우선순위로 지정한다. 기본은 최신 실행 순이며 같은 값에서는 실행 ID로 순서를 고정한다. 표 머리글을 누르면 해당 항목 하나의 정렬로 바뀐다.
- 페이지당 25·50·100건을 선택한다. 필터나 정렬을 바꾸면 첫 페이지로 이동한다. 페이지·조건·선택한 실행이 주소에 남아 새로고침·공유·뒤로 가기로 복원된다.
- 상세에는 실행·캠페인·원본 결과·검토 ID를 표시한다. 재실행의 응답을 받지 못했거나 저장이 미확정이면 **원본 관련 재실행 이력**에서 새 기록을 먼저 확인한다. 이 이동은 다시 실행하는 작업이 아니다.

비밀 키나 요청 원문을 검색하지 않는다. 잘못된 주소와 민감한 조건은 명시 초기화 전까지 조회를 중단하며, 필터를 버리고 전체 조회로 바꾸지 않는다. 서버가 v0.86.145보다 이전이면 기존 최근 이력 화면을 제공하고 새 주소 조건은 지원 버전을 안내한다.

## 조회 계약

기존 API의 `view=page`만 새 응답을 선택한다. `limit`은 1–100, `offset`은 0–1,000,000이며 상태·방식·종류·식별자·기간·허용된 정렬만 받는다. 중복·알 수 없는 매개변수와 잘못된 값은 400, 저장소 조회 실패는 내부 오류를 제외한 503이다. 인증과 관리자 조회 권한은 기존 API와 같다.

전체 건수와 행은 같은 읽기 트랜잭션에서 조회하고 응답을 캐시하지 않는다. 서로 다른 페이지 요청 사이에는 새 실행·상태 변경으로 결과가 달라질 수 있다. 목록은 실행 메타데이터만 조회하며 요청·응답·증적 원문은 포함하지 않는다. 읽기 전용 사용자는 동일한 조회를 사용할 수 있다.

화면의 목록·상세·증적은 인증 수명에 종속된다. 401·403 또는 세션/조회 권한 변경 시 기존 이력을 폐기하고 진행 중 조회를 취소한다. 조회 실패는 빈 결과로 표시하지 않으며 마지막 정상 조회 시각과 재시도를 제공한다.

## 검증과 범위

SQLite와 PostgreSQL의 100건 초과 조회·필터·복합 정렬·시간 경계·마이그레이션, API 권한·기존 응답을 검증했다. 전체 React 6,486개를 통과한 뒤 상세 링크·구버전 보호 변경에서 관련 247개를 다시 검증했다. 최종 내장 자산의 합성 화면·시각·접근성 검사 125개와 실제 Go 서버의 인증·제공자·SQLite 업무 9개를 통과했다. 실제 업무에는 읽기 전용 로그인 후 127개 이력의 마지막 페이지·상세·새로고침 검증이 포함된다. 두 테마·데스크톱·모바일의 새 시각 기준 4장을 검토했으며 이전 기준은 유지했다. 초기 전송 번들은 267,286바이트다. PostgreSQL 카탈로그의 인덱스 식 괄호 표기를 선언과 맞춰 동일한 식이 불일치로 보고되는 문제를 수정했다. 수정 전 실패를 재현하고, 수정 후 SQLite 전체 저장소·vet, PostgreSQL 17의 인덱스·기존 데이터 업그레이드·20만 행 계획·레드팀·메타데이터 조회 race 245개와 실제 서버 업무 9개를 통과했다. 출고 결과는 후보 CI와 실제 메인 CI·정식 배포 파일 검증으로 별도 확정한다.

이번 변경은 이력 조회 개선이다. 실행 취소·자동 복구·전역 잠금이나 정확히 한 번 과금의 보장은 추가하지 않는다. 운영 Preview 검증과 Stable 승격, 전체 Phase 0–6 인수는 계속 진행한다.
