# 레드팀 실행 중단과 결과 확인

v0.86.138 후보는 `/app/redteam`의 실행 결과와 기존 캠페인 실행기의 중단 처리를 보강한다. `/admin` 화면과 인증·권한 경로는 유지한다.

## 실행 중 검사

캠페인의 실제 모델 호출마다 요청 취소, 이 프로세스의 긴급 중지, 캠페인별 200회 호출 한도, 누적 비용을 확인한다. 호출 속도 대기와 모델 목록 조회가 끝난 뒤에도 검사한다. 한 검사에서 여러 모델을 호출할 때 첫 모델이 중단 조건을 충족하면 다음 모델을 호출하지 않는다. 호출 한도에 도달한 뒤 남은 검사를 자동으로 시뮬레이션하지 않는다.

호출 도중 취소되면 새 호출을 중단한다. 이미 얻은 결과와 중단 상태의 DB 기록은 취소된 요청과 분리해 각 기록 묶음에 최대 5초 동안 시도한다. 저장소 장애나 프로세스 종료까지 원자적으로 보장하는 작업 큐는 아니다. 중단된 대상별 실행은 `stopped`로 표시하며 통과 기준선을 갱신하지 않는다. 앞서 완전히 끝난 다른 대상의 결과와 기준선은 유지한다. 공급자 오류와 판정 불가 결과는 실패에 집계하여 통과 기준선에 반영하지 않는다.

## 한글 결과 화면

- 실행 결과 상단에서 중단 사유를 확인한다. 비용 기준 도달, 긴급 중지, 호출 횟수 한도, 요청 취소를 한글로 안내한다.
- 대상별 실행 수, 기록된 검사 결과, 실제 호출 시도와 기록 비용을 구분한다. 호출 시도는 게이트웨이 거부·오류 응답도 포함하며 공급자의 성공 응답 횟수가 아니다.
- 비용은 응답 사용량과 가격 설정을 사용한다. 사용량이 없어 비용을 계산하지 못하면 기존 기본 추정치를 사용한다. 예산은 호출 후 누적 비용을 확인하는 중단 기준이며, 마지막 호출의 비용이나 게이트웨이 재시도 비용까지 제한하는 결제 상한이 아니다.
- 결과 버튼으로 이미 기록된 검사만 확인한다. 실행 결과와 이력 화면 모두 중단된 실행의 일부 결과임을 표시한다. 이력에는 저장된 상태를 표시하며 중단 사유는 실행 응답에서 확인한다.
- 실행 요청의 인증 갱신 자동 재전송을 끈다. 결과가 불확실하면 이력부터 확인하고 실행 조건을 다시 검토한다.

## 적용 범위와 다음 단계

긴급 중지는 해당 프로세스의 후속 호출을 막는다. 이미 보낸 호출의 즉시 취소, 다른 서버의 중단, 재시작 후 상태 유지, 완전한 청구 비용 상한을 보장하지 않는다. 게이트웨이 내부 재시도와 모델 목록 조회는 캠페인 200회 모델 검사 한도와 구분한다. 전체 실행 시간·동시 실행 수의 강제 제한, 실행 대상·모델·출력 토큰 한도를 확정하는 검토 흐름, 일회성 실행 승인 및 운영 Stable 인수는 다음 단계다. 전체 Phase 0–6 완료로 표시하지 않는다.

## 검증

관련 React 1,133개(53개 파일), 최종 내장 브라우저 81개, 두 테마·1440/390px 시각 기준 4장과 키보드·axe·반응형 검사를 통과했다. 최종 내장 자산에서 실제 Go/OIDC/SQLite 인증 60개, Keycloak HTTPS 5개와 사용자 DB, 보고서·실패 산출물 29개를 검증했다. Go proxy/appui 회귀·vet, SQLite·PostgreSQL 17 race, 실제 Go OpenAPI·생성 타입·API 표면·린트·포맷·빌드·SBOM을 검증했다. 초기 압축 번들은 264,731바이트다.
