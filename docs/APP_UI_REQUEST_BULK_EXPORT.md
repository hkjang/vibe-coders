# 요청 여러 건 선택과 CSV — v0.86.123 개발 후보

## 화면 동작

요청 탐색기의 **여러 요청 선택**을 누르면 현재 페이지의 각 행과 전체 선택 체크박스가 나타난다.
선택한 건수와 범위를 한글로 안내하고 **선택한 요청 CSV**, **선택 해제**, **선택 마치기**를 제공한다.
읽기 전용 관리자도 조회가 허용된 운영 메타데이터를 내보낼 수 있다. 선택 순서와 무관하게
CSV는 서버가 보낸 행 순서를 유지하며 기존 열·ISO 8601 시각·반올림 전 비용을 사용한다.
프롬프트나 응답 본문을 추가하지 않으며 기존 CSV 수식 이스케이프를 적용한다.

선택하는 동안 자동 갱신·탭 복귀·연결 복구에 따른 갱신을 멈춘다. **선택 마치기**로 설정된
갱신 주기를 다시 적용한다. 수동 갱신은 가능하며 새 응답을 받으면 선택을 해제한다.
필터·페이지·계정·조회 객체가 바뀌거나 선택을 마친 뒤에는 이전 선택을 복원하지 않는다.
선택은 현재 페이지에만 적용하고 URL이나 영속 저장소에 남기지 않는다.

조회가 401·403으로 거부되면 이전 행과 연결된 상세·조회 데이터를 정리하고 한글 안내로
포커스를 옮긴다. 현재 안내의 **다시 시도**로만 재조회하며, 이전 새로고침·CSV 동작은
권한 복구 후에도 재사용할 수 없다. 일시 오류에서는 마지막 정상 행과 오류 안내를 유지하되
선택·내보내기는 새 조회가 성공할 때까지 비활성화한다. 빈 응답과 조회 실패를 구분한다.

기존 **현재 목록 CSV**에도 동일한 조회 상태 확인을 적용한다. 요청 화면·필터·결과 표를
분리하고 선택 상태와 체크박스를 공통 구성 요소로 둔다. 기존 업무 API·서버 권한·
`/admin`·의존성·단일 바이너리 배포는 유지한다.

## 검증과 범위

수정 전 401·403 뒤 이전 CSV 동작이 실행되는 문제를 두 검사에서 재현했다.
선택한 행·비용·순서·수식 이스케이프, 같은 내용의 새 응답, 조회 객체 교체, 페이지 왕복,
계정 변경, 화면 종료, 권한 거부와 명시 재시도를 검사한다.
실제 관리자·읽기 전용 관리자 인증으로 기존 Go API 응답과 선택 CSV를 대조하고 페이지 이동을 확인한다.

React 1,005개(68개 파일)·내장 Go 브라우저 97개·실제 Go/OIDC/SQLite 인증 50개·실제 Keycloak HTTPS 5개와 사용자 DB 검증·보고서와 실패 산출물 29개를 통과했다.
관리자와 읽기 전용 관리자의 실제 API 응답을 선택 CSV와 대조하고 서버 페이지 왕복을 확인했다.
두 테마·1440/390px 시각 기준 4장을 직접 검토했고 키보드·axe·본문 넘침을 검사했다.
최초 브라우저 검사에서 모의 응답에 변환 후 전용 필드를 넣어 새 시나리오 9개가 실패했다. 실제 전송 계약의 타입을 적용해 수정하고 새 시각 기준을 만든 뒤 97개를 재시도·건너뜀 없이 통과했다. 기존 시각 기준은 변경하지 않았다.
타입·린트·포맷·실제 OpenAPI·통합 SBOM·요청 계약/기존 관리자/내장 UI Go 회귀·vet·번들 예산을 통과했다. 초기 압축 번들은 262,464바이트다.
시각 검토에서 좁은 화면의 페이지 버튼 줄바꿈을 개선했다. 수정 후 실제 인증·제품·내장 산출물 검사를 다시 통과했으며 실행한 소스와 최종 산출물의 해시가 동일함을 확인했다.
후보 CI·리뷰·메인·정식 배포 검증과 운영 Stable 인수는 별도 단계다.
현재 페이지의 선택 내보내기를 제공하며 모든 도메인의 일괄 변경이나 전체 검색 결과 내보내기를
완료한 것으로 간주하지 않는다. 전체 Phase 0–6 개발과 운영 인수는 계속 진행한다.
