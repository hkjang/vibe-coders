# 요청 메타데이터의 바이트 처리

요청 탐색기·추적 흐름·팀 범위의 입출력 조회는 저장된 식별자의 바이트 길이를 검사합니다. PostgreSQL에서 문자열을 BYTEA로 변환하면 역슬래시를 이스케이프로 해석하므로, 정상 식별자를 기록할 때 오류가 나거나 `\x`로 시작하는 긴 문자열이 길이 제한을 잘못 통과할 수 있었습니다.

v0.86.156은 PostgreSQL의 `octet_length`로 저장된 문자열을 측정합니다. 요청·추적·키·팀·사용량·응답 식별자의 기존 512바이트 조회 경계를 유지합니다. SQLite의 BLOB 길이 검사, 기존 관리자 API와 원문 조회 권한은 유지하며 실제 이진 데이터 열의 BYTEA 형식도 바꾸지 않습니다.

## 기존 데이터 업그레이드

새 조회 조건과 같은 조건을 사용하는 여섯 부분 인덱스를 선언합니다. 기존 인덱스가 문자열을 BYTEA로 해석하는 조건을 가진 경우에만 동시 재작성하며, 다른 정상 인덱스는 유지합니다. 기존 시작 마이그레이션 잠금을 사용하고 완료된 인덱스는 다음 시작에서 다시 만들지 않습니다.

과거 표현식 통계가 남아 있으면 ANALYZE도 동일한 오류를 일으킬 수 있습니다. 현재 스키마에서 애플리케이션이 소유한 이전 요청·키 통계 세 개를 제거하고, 바이트 함수를 반영한 새 버전의 통계를 생성합니다. 기존 데이터가 있는 업그레이드는 새 통계의 표본을 수집합니다.

재작성 시간은 저장된 행 수와 동시 작업에 영향을 받습니다. 20만 요청의 자연 실행 계획과 시작 동시성은 테스트로 확인하며, 실제 운영 전체 규모의 작업 시간은 별도 운영 검증 대상입니다.

## 검증 범위

수정 전 실제 PostgreSQL에서 문자열·바이트 제한 실패 18개와 이전 인덱스/업그레이드 실패 2개를 재현했습니다. 수정 후 저장·조회·자연 실행 계획·동시 마이그레이션·상위 세션/연관 실행의 PostgreSQL race 검사 90개와 기존 요청 API·권한·입출력 PostgreSQL race 검사 54개를 통과했습니다. 역슬래시·Windows 경로·16진수 형태·한글 바이트 경계, 최초 및 재시작 업그레이드, 기존 정상 인덱스 보존을 포함합니다.

전체 Go 테스트(일반 SQLite 20만 행 실행 계획 포함), vet, 실제 Go OpenAPI 생성 계약과 API 표면(424 서버·484 OpenAPI·371 React 연결), 프런트엔드 포맷·린트·타입·빌드·성능 예산 및 통합 SBOM(19 Go·389 npm)을 확인했습니다. 최종 내장 추적 브라우저 61개, 실제 Go 로그인·SSO·API 키 60개와 라우팅·정책 계산 흐름 5개를 통과했습니다. SQLite 기능 race 68개가 통과했고, PostgreSQL 전용 검사 1개는 해당 SQLite 실행에서 제외하여 실제 PostgreSQL 검사로 검증했습니다. 초기 전송 크기는 268,905바이트입니다. 화면 소스와 시각 기준은 바꾸지 않았으며 전체 React 회귀 재실행으로 표시하지 않습니다.

추가로 실행한 SQLite 20만 행의 race 계측 검사는 7분 제한을 초과했습니다. 이를 통과로 계산하지 않으며, 같은 규모의 일반 실행 계획 검사와 별도의 기능 race 결과를 구분합니다. 최종 모의 실행 검사에서는 테스트 바이너리 복사의 실행 권한을 보존하도록 실행기를 바로잡은 후 다섯 시나리오가 모두 통과했습니다. 제품 소스는 검사 중 변경하지 않았습니다. 운영 Stable 승격과 전체 Phase 0–6 인수는 별도로 진행합니다.
