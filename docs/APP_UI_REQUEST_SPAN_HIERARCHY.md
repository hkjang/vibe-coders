# 요청 상세의 기록 관계 보기

LLM 관측의 호출 상세에서 **원인 설명 열기 → 처리 흐름 → 기록 관계**를 선택하면 요청과 하위 처리 기록을 묶어 볼 수 있습니다. 기본 **흐름 막대** 보기로 돌아갈 수 있고, 보기 전환 자체는 API를 다시 호출하지 않습니다. 각 묶음의 **하위 기록 N개**를 키보드로 접거나 펼칠 수 있습니다.

기존 요청 상세 API의 `span_id`와 `parent_span_id`가 유일하게 확인될 때만 연결합니다. 시간순서나 같은 이름, 마스킹된 문구로 관계를 추정하지 않습니다. 중복·누락·민감 식별자와 순환 관계는 해당 사유와 함께 별도 기록으로 표시합니다. 깊은 관계는 다섯 단계마다 별도 묶음으로 나누며 기록을 버리지 않습니다. 깊이 제한으로 분리된 기록에는 상위 기록이 없다는 뜻이 아니라는 안내를 표시합니다.

이 화면은 서버가 이미 구성한 요청·도구·Text2SQL 기록의 관계입니다. 현재 서버는 요청에 연결된 도구와 단계를 요청 아래에 배치합니다. 완전한 분산 추적이나 실제 호출 인과관계, 동시 실행과 시작·종료 시각을 재구성하지 않습니다. 막대의 상대 위치와 지연은 기존 기록값이며 도구별 소요 시간은 미기록 상태를 유지합니다.

## 권한과 조회

기존 `/admin/requests/{id}/trace`와 `/links` GET, 요청 상세의 팀 범위와 원문 열람 정책을 그대로 사용합니다. 추가 API나 원문 수집 기능은 없습니다. 이름·오류의 표시 보호, 조회 취소, 세션·권한 변경에 따른 기존 조회 정리와 개별 재조회는 유지합니다. 브라우저의 표시 보호가 응답 자체의 비식별화나 모든 개인정보 제거를 보장하지는 않습니다.

## 검증과 인수 범위

관계 보기의 행 보존·중복·누락·순환·민감 식별자와 2만 개 연결의 깊이 제한을 검사합니다. 실제 브라우저에서는 보기 전환, 키보드 접기, 재조회 후 접힘·초점 유지, 좁은 화면과 밝은/어두운 테마, 접근성 및 시각 기준을 확인합니다. 브라우저 API 응답은 합성 데이터이며 기존 서버의 권한·마스킹은 별도 Go 회귀로 검증합니다.

전체 React 6,640개(472개 파일)와 기본 Node 58개를 통과했습니다. 타입 검사에서 파싱 후 필수 필드를 요구하는 테스트 자료를 보완했으며, 최종 요청 상세 회귀 167개를 다시 통과했습니다. Node의 외부 산출물 선택 검사 15개는 해당 기본 실행의 제외 항목입니다. 기존 Go 팀 범위·원문 마스킹·경로·응답 회귀 race 61개와 최종 내장 브라우저 47개를 통과했고, 브라우저 재시도·제외·실패는 없습니다. 새 시각 기준 8장(밝은/어두운 테마, 1440/390px, 상단/하단)을 확인한 뒤 변경 없이 비교했으며 기존 화면의 시각 기준은 유지했습니다. 실제 Go OpenAPI 생성 계약, 포맷·린트·타입·빌드·성능 예산과 통합 SBOM(19 Go·389 npm)을 검증했습니다. 초기 전송 크기는 268,904바이트입니다.

운영 사용자의 Preview 검증과 Stable 승격, 전체 분산 추적 요구사항 및 Phase 0–6 최종 인수는 별도 진행 항목입니다.
