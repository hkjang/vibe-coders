# 요청 자동완성의 계정·권한 전환 — v0.86.126 개발 후보

모델·언어 자동완성 조회를 현재 계정, 팀, 역할, 원문 조회 권한, 인증 세션과 화면에 연결한다.
입력창에 처음 포커스할 때 조회하는 방식과 직접 입력을 유지한다. 쓰기 권한만 바뀌면 읽기
목록을 재조회하지 않으며, 읽기 범위가 바뀌면 이전 목록과 캐시를 지운다. 이전 요청이 늦게
끝나거나 같은 계정으로 돌아와도 폐기한 응답을 새 목록으로 사용하지 않는다.

서버가 자동완성 조회를 거부하면 이전 값을 지우고 자동 재조회를 중단한다. 한글 안내에서
직접 입력하거나 **다시 불러오기**를 선택할 수 있다. 재조회 버튼은 해당 입력창으로 포커스를
돌리며 진행 중 중복 요청을 막는다. 일시 오류에도 이전 추천과 서버 오류 원문을 표시하지
않고 직접 입력과 재조회 방법을 제공한다. 모델·언어의 오류 안내는 각 입력 영역에 배치한다.

기존 공통 읽기 수명 관리와 API 권한을 재사용한다. 조회 전후에 현재 화면과 취소 상태를
확인하며 기능이나 계정이 바뀐 뒤 이전 재조회 동작도 사용하지 않는다. 새 업무 API·서버
권한·의존성은 추가하지 않으며 기존 `/admin`과 단일 바이너리 배포를 유지한다.

수정 전 재현 검사 7개 중 6개가 실패했다. 팀·원문 조회 권한 변경, 늦은 이전 요청, 조회 권한
제거, 401·403 거부 뒤 이전 자동완성 값이 남거나 새 범위를 조회하지 않는 경우를 재현했다.
공통 조회 수명을 연결한 뒤 초기 응답의 구독 순서도 보완했고 관련 초기 검사 16개를 통과했다.

React 1,080개(77개 파일)·내장 Go 브라우저 132개·실제 Go/OIDC/SQLite 인증 50개·실제 Keycloak HTTPS 5개와 사용자 DB 검증·보고서와 실패 산출물 29개를 통과했다.
실제 관리자·읽기 전용 관리자의 모델 자동완성 표시를 같은 인증의 API 응답과 대조했다.
두 테마·1440/390px 시각 기준 4장을 직접 검토하고 키보드·axe·본문 넘침·입력칸 높이를 검사했다. 최초 화면 검토에서 오류 안내로 옆 입력칸 높이가 늘어나는 문제를 발견해 그리드 정렬을 보완했다. 기존 시각 기준과 비교 허용치는 변경하지 않았다.
원문 조회 권한 변경은 기존 요청 목록 조회도 교체하므로 필터가 초기화된다. 브라우저 검사는 이 동작에 맞춰 이전 입력·추천 정리와 새 입력 포커스에서의 재조회를 확인한다. 초기 두 구성 요소 검사의 자동완성 API 모의 응답을 실제 형식에 맞췄으며, 최종 고정 브라우저 검사는 재시도·건너뜀 없이 통과했다.
타입·린트·포맷·실제 OpenAPI·통합 SBOM·요청 계약/기존 관리자/내장 UI Go 회귀·vet·번들 예산을 통과했다. 초기 압축 번들은 262,517바이트다. 검증한 소스와 내장 산출물의 해시 일치를 확인했다.
후보 CI·리뷰·메인·정식 배포와 운영 인수는 별도다. 이 검증은 요청 자동완성의 범위이며
다른 모든 데이터 조회와 역할 조합 또는 전체 Phase 0–6 완료를 뜻하지 않는다.
