# 요청 기간 빠른 입력 — v0.86.127 개발 후보

요청 탐색기에서 **최근 1시간·24시간·7일·30일**을 선택해 시작·종료 시각을 입력한다.
기간은 선택한 순간의 브라우저 시각을 한 번 읽어 계산하며, 7일·30일은 각각 168·720시간이다.
입력값은 끝에 `Z`가 있는 UTC 절대 시각이므로 선택한 표시 시간대나 서머타임에 따라 길이가
달라지지 않는다. 화면에 시각 기준과 적용 방법을 안내한다.

기간 선택만으로 조회하거나 URL을 바꾸지 않는다. 다른 필터 초안과 시간대를 유지하고
**조회** 버튼으로 적용한다. 적용 시 기존 방식으로 첫 페이지로 돌아가며 주소에 시작·종료
시각을 저장한다. 뒤로·앞으로·새로고침에서도 같은 절대 기간을 복원하며 자동으로 현재까지
이동시키지 않는다. 다시 기간을 선택하면 그 시점의 시각을 사용한다.

시각을 직접 고치면 빠른 입력 안내를 지우고 기존 날짜·기간 검증을 적용한다. 필터 초기화와
읽기 범위 변경의 기존 정리 동작을 유지한다. 한글 버튼·키보드·상태 알림과 좁은 화면 줄바꿈을
지원한다. 새 API·의존성·비즈니스 로직을 추가하지 않고 `/admin`을 보존한다.

React 1,086개(78개 파일)·내장 Go 브라우저 139개·실제 Go/OIDC/SQLite 인증 50개·실제 Keycloak HTTPS 5개와 사용자 DB 검증·보고서와 실패 산출물 29개를 통과했다.
실제 관리자·읽기 전용 관리자에서 입력한 시작·종료 시각이 서버의 조회 요청과 URL에 그대로 전달되는지 확인했다. 다른 초안 보존·명시 적용·페이지 초기화·직접 입력 검증·주소 복원과 날짜·서머타임 경계를 검사했다.
두 테마·1440/390px 시각 기준 8장을 직접 검토했다. 빠른 입력이 추가된 기존 요청 필터 폼 4장만 의도적으로 갱신하고 새 기간 선택 화면 4장을 추가했다. 긴 폼 전체를 보여주기 위해 자동완성 시각 검사의 화면 높이를 1,100px로 늘렸다. 최초 브라우저 검사 두 곳은 주소 변경만 기다린 뒤 새 조회가 끝나기 전에 조작했다. 조회 완료도 기다리도록 보완한 뒤 입력·뒤로 가기 검증을 통과했다. 비교 허용치는 유지했으며 키보드·axe·본문 넘침과 고정 비교를 통과했다.
타입·린트·포맷·실제 OpenAPI·통합 SBOM·요청 계약/기존 관리자/내장 UI Go 회귀·vet·번들 예산을 통과했다. 초기 압축 번들은 262,497바이트다. 운영 코드·실제 인증 검사 소스와 내장 산출물의 해시 일치를 확인했다. 실제 인증 검증 뒤 변경한 브라우저 검사 두 파일은 별도로 타입·린트와 최종 브라우저 검사를 통과했다.
후보 CI·리뷰·메인·정식 배포와 운영 인수는 별도다. 전체 Phase 0–6 완료나 Stable 승격을 뜻하지 않는다.
