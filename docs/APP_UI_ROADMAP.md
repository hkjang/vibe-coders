# 차세대 관리자 콘솔 (`/app`) 로드맵

`/app`은 기존 `/admin`을 대체하지 않는 React 기반 차세대 관리자 콘솔이다. 두 UI는 같은 Go 서버, 인증, 권한, 데이터베이스, 관리 API를 사용한다. 신규 UI에 문제가 생기면 운영자는 언제든 `/admin`으로 복귀할 수 있다.

## 운영 원칙

- `/admin`은 Legacy Stable Console로 계속 제공하며 자동으로 `/app`으로 보내지 않는다.
- `/app`은 기본 비활성 상태로 배포한다. `ui.app.enabled=true`인 환경에서만 내장 React 빌드를 제공한다.
- `/app`이 비활성이거나 빌드가 누락되면 외부 자산 없는 안내 화면과 `/admin` 링크를 제공한다.
- 기능은 `Hidden → Legacy → Preview Read Only → Preview → Stable → Deprecated → Retired` 순으로 승격한다.
- 인증·RBAC·업무 로직을 UI별로 이중 구현하지 않는다.
- 운영 컨테이너에는 Node.js나 `node_modules`가 없고, Vite 산출물은 Go 바이너리에 포함된다.
- Service Worker, 외부 CDN, 외부 폰트, 런타임 외부 JavaScript를 사용하지 않는다.

## URL 계약

| 요청 | 서버 동작 |
| --- | --- |
| `GET /app` | 민감정보의 URL 잔존을 막기 위해 query를 폐기하고 `/app/`으로 308 이동 |
| `GET /app/` | 활성 시 React `index.html`, 비활성 시 안내 화면 |
| `GET /app/<client-route>` | 실제 파일이 없고 확장자가 없으면 SPA index |
| `GET /app/assets/<hash>.*` | 실제 파일만 제공, 1년 `immutable` 캐시 |
| 존재하지 않는 asset 또는 확장자 경로 | 404; SPA index로 fallback하지 않음 |
| `HEAD /app/*` | GET과 같은 상태·헤더, 본문 없음 |
| GET/HEAD 이외 `/app/*` | 405 및 `Allow: GET, HEAD` |
| `/admin`, `/auth`, `/v1`, `/mcp`, 운영 probe | 기존 핸들러가 계속 처리 |

`index.html`과 안내 화면은 항상 `Cache-Control: no-cache`이며 `/app`에만 별도 CSP와 보안 헤더를 적용한다. inline script/style을 사용하는 기존 `/admin`에는 이 CSP를 전역 적용하지 않는다.

## 활성화와 즉시 복구

기본값은 다음과 같다.

| 설정 | 기본값 |
| --- | --- |
| `ui.app.enabled` | `false` |
| `ui.app.default_entry` | `/app/overview` |
| `ui.app.legacy_fallback` | `true` |
| `ui.app.feedback_enabled` | `false` |
| `ui.app.telemetry_enabled` | `false` |

기존 `/admin`의 Runtime Settings에서 값을 변경할 수 있다. 컨테이너 최초 설정은 각각 `UI_APP_ENABLED`, `UI_APP_DEFAULT_ENTRY`, `UI_APP_LEGACY_FALLBACK`, `UI_APP_FEEDBACK_ENABLED`, `UI_APP_TELEMETRY_ENABLED` 환경변수로 제공할 수 있으며 DB override가 우선한다.

장애 시 `ui.app.enabled=false`로 전환한다. 각 pod는 기존 runtime setting reload 주기에 따라 반영하며 `/admin`과 API 트래픽은 영향을 받지 않는다.

## Bootstrap 계약

`GET /admin/ui-bootstrap`은 로그인 화면과 App Shell이 필요한 최소 정보를 집계한다.

- Backend/UI/API 버전
- `/app` 활성 상태와 기본 진입 경로
- 인증 모드, Keycloak 사용 여부, 로컬 로그인 허용 여부
- 유효한 credential이 있을 때만 현재 사용자·역할·scope
- 기능별 Migration Registry와 현재 사용 가능 판정
- 최소 시스템 상태와 Legacy route map

credential이 없는 응답은 공개 로그인 메타데이터만 포함한다. 유효하지 않은 credential은 401이며, 응답은 `no-store`다. 모든 응답에는 공통 `X-Request-ID`가 포함된다.

## 기능 전환 설정

각 registry 항목은 다음 override를 갖는다.

```text
ui.app.feature.<feature-id>.status
ui.app.feature.<feature-id>.roles
ui.app.feature.<feature-id>.rollout
ui.app.feature.<feature-id>.readonly
```

rollout bucket은 사용자 ID와 feature ID의 SHA-256 기반으로 계산하므로 새로고침이나 pod 변경 후에도 동일하다. Preview는 scope, 허용 역할, rollout을 모두 통과해야 한다. UI의 메뉴 숨김은 편의 기능일 뿐이며 모든 API는 기존 서버 권한 검사를 다시 수행한다.

`v0.84.0`부터 36개 기능 등록 항목 모두에 React 화면이 있다. 통합 현황, 게이트웨이 상태·공급자·모델·채팅 테스트, 라우팅, 요청·추적·세션·XView·LLM·프로브, 프롬프트 실험실과 라이브러리, 사용자·팀·내 홈, 거버넌스, MCP와 에이전트·워크플로·앱·스킬, Text2SQL, 데이터 웨어하우스·상품, 비용, 보안·레드팀·샌드박스, 시스템 상태·설정이 포함된다. 다만 화면 등록이나 API 선언의 존재가 모든 기존 작업의 이식·안전성 검증 완료를 뜻하지는 않는다. 정책 일괄 가져오기의 파일 검토·원자적 적용·원문 백업은 v0.86.37에서 제공하며, 게이트웨이 비밀키 회전과 고위험 변경의 전체 영향 검토에는 격차가 남아 있다. 미이전 작업은 기존 화면을 사용하며, 요구사항별 근거와 남은 작업은 [인수 검증표](APP_UI_ACCEPTANCE.md)에서 관리한다.

`v0.83.0` 추적 탐색기는 요청 단위 미리보기다. 시작 시각과 지연 구간, HTTP 상태, 모델, 안전 공급자 표시명, 토큰과 비용을 제공하며 세부 MCP·도구·Text2SQL 스팬 트리는 아직 Legacy 화면에 남겨 둔다. 해당 세부 기능은 팀 범위와 원문 제거가 보장되는 앱 전용 계약, 명시적 OpenAPI·Zod 스키마, 응답 행 상한을 갖춘 뒤 별도 단계에서 승격한다. 정확한 추적 ID 조회는 전용 복합 부분 인덱스로 지원하고 대용량 SQLite·PostgreSQL 계획 회귀로 검증한다.

공급자·모델 미리보기의 페이지 이동은 v0.82.0에서 서버 상한이 적용된 전체 응답을 사용하는 제한된 클라이언트 측 방식이다. `/admin/models`는 최대 20,000행·16MiB로 제한하지만 대규모 모델 목록의 화면 성능 목표는 아직 보장하지 않는다. 안정 기능으로 승격하기 전에는 커서 기반 서버 측 페이지 이동과 현재 페이지 범위의 품질·가격·태그 보강을 적용해야 한다. 운영에서 모델 응답이 1MiB를 넘거나 1,000행 이상이 상시 발생하거나 화면 API p95가 2초를 넘으면 미리보기 배포를 중지하고 페이지 이동 개선을 우선한다.

SQLite의 팀 범위 요청 조회는 전체 팀 이력을 먼저 정렬하지 않고 시간순 전역 커서를 따라가며 권한을 검사한다. 최신 구간에 해당 팀 요청이 매우 드문 환경에서는 더 오래 순회할 수 있으므로, 안정 기능 승격 전 빈 팀·희소 팀 성능 회귀를 추가하고 필요하면 최근 구간 탐색과 팀 인덱스 대체 경로를 결합한다.

1단계의 자동 갱신 기본값은 비활성이며 사용자가 1분 또는 5분을 선택할 수 있다. 대규모 보존 데이터에서도 자동 갱신을 기본 활성화하려면 `/admin/stats`와 장기간 라우팅 상태에 서버 집계·캐시를 추가하고 성능 회귀 기준을 먼저 통과해야 한다.

## 인증 안전성

- access/refresh token은 기존 호환을 위해 tab 단위 `sessionStorage`에만 저장한다.
- 여러 API가 동시에 401이어도 하나의 refresh promise만 실행하고 원 요청은 최대 한 번 재시도한다.
- 로그아웃 시 token과 Query cache를 지우고 `BroadcastChannel`로 다른 탭에 알린다.
- Keycloak `return_to`는 scheme/host/fragment가 없는 `/app/*` 또는 정확한 `/admin`만 허용한다.
- 검증한 `return_to`는 OIDC state와 함께 저장해 callback이 다른 pod에 도착해도 원래 화면으로 복귀한다.
- Keycloak 그룹은 팀 ID 또는 대소문자를 무시한 팀 이름으로 DB에서 직접 해석하고 실제 표준 팀 ID로 멤버십을 저장한다. ID와 다른 팀 이름이 충돌하면 권한 혼동을 피하기 위해 로그인을 차단한다.
- SSO 사용자·외부 식별자·팀 멤버십은 한 트랜잭션으로 저장한다. 서명 검증된 동일 발급자·사용자 식별자의 동시 첫 로그인은 하나의 SSO 전용 계정으로 수렴한다.
- `email_verified`가 없는 이메일은 계정 탐색·연결·저장에 사용하지 않는다. 로컬 비밀번호 계정이나 특권 계정과 이메일이 겹치면 권한을 상속하지 않는 별도 SSO 전용 계정을 만든다.
- Keycloak 설정에서 로컬 로그인을 끄면 로그인 화면뿐 아니라 `/auth/login` API도 403으로 차단한다.
- API Key, password, client secret, prompt/response 원문은 local storage나 UI telemetry에 저장하지 않는다.

## 화면 구성 구조

`/app`의 모든 화면은 도메인별로 자기 자신을 등록한다. 라우터, URL 쿼리 허용 목록, 구현 여부 판정이
한 곳에서 갈라져 어긋나지 않도록 하나의 등록부를 공유한다.

| 파일 | 역할 |
| --- | --- |
| `web/src/features/<domain>/routes.ts` | 그 도메인이 소유한 화면을 `{ featureId, load, queryKeys }`로 선언 |
| `web/src/features/registry.ts` | 도메인 선언을 모아 라우터·쿼리 허용 목록·구현 여부에 공급 |
| `web/src/shared/api/domains/<domain>.ts` | 그 도메인이 호출하는 서버 엔드포인트와 응답 스키마 |
| `web/src/shared/api/endpoint-factory.ts` | OpenAPI 경로·메서드 타입에 묶인 엔드포인트 선언 도구 |
| `web/src/shared/api/loose.ts` | 응답 스키마가 문서화되지 않은 기존 API를 위한 관대한 zod 도구 |

`queryKeys`에 등록하지 않은 쿼리 매개변수는 라우트 가드가 제거한다. 화면이 URL에 남길 수 있는 값을
화면 자신이 선언하므로, 비밀정보나 프롬프트가 실린 매개변수가 새 화면과 함께 조용히 들어올 수 없다.

구현 여부는 코드가 결정한다. `registry.ts`가 모은 featureId 집합이 곧 이 빌드가 소유한 화면이며,
런타임 전환 설정이 아직 화면이 없는 기능을 승격하더라도 라우트는 기존 화면 연결로 남는다.

Legacy와 `/app`의 격차는 CI가 기계적으로 검사한다. `go run ./cmd/api-surface-audit`는 Legacy 콘솔이
호출하는 모든 `/admin` 엔드포인트가 `/app` 콘솔의 API 계층에도 선언되어 있는지 비교하고, 하나라도
빠지면 실패한다. 두 콘솔은 현재 격차 0이다.

이 검사는 두 가지를 지켜야 의미가 있다. 첫째, 비교 대상에서 `web/src/shared/api/generated`를 제외한다.
생성된 OpenAPI 타입은 화면이 호출하든 말든 문서화된 모든 경로를 나열하므로, 이를 포함하면 Legacy 콘솔을
`/app` 콘솔이 아니라 카탈로그와 비교하게 된다. 둘째, Legacy 콘솔의 문자열 이어붙이기
(`'/admin/requests/' + id + '/trace'`)를 하나의 엔드포인트로 접는다. 첫 문자열만 읽으면
`/admin/requests/` 에서 멈춰 그 아래 모든 하위 동작이 이식된 것으로 계산된다. 실제로 이 두 허점 때문에
요청 추적·운영 홈·지식 캐시를 포함한 화면 여러 개가 `/app`에 없는 채로 이 검사가 통과했고, v0.84.1
이후 격차 15건을 찾아 모두 이식했다.

검사는 어떤 화면의 어떤 버튼이 그 엔드포인트를 호출하는지까지 보장하지는 않지만, 새 기능이 Legacy
콘솔에만 추가되어 이식 격차가 조용히 다시 벌어지는 것은 막는다. 같은 명령이 CLI·SDK·OpenAPI·서버 라우트
계약도 함께 검사한다.

## 공통 UI 구성요소

도메인 화면은 같은 조각을 사용해 한 제품처럼 보이도록 한다.

- 페이지: `PageHeader`(상태·기존 화면 링크·액션), `SectionCard`, `StatCard`/`StatGrid`, `KeyValueList`, `Toolbar`
- 목록과 상세: `DataTable`, `Sheet`(사이드 패널), `Dialog`, `JsonBlock`, `CopyButton`
- 입력과 변경: `FormField`, `FormDialog`+`useZodForm`, `ConfirmDialog`(사유 입력), `Select`, `Textarea`, `Checkbox`, `Switch`
- 상태 전달: `LoadingState`, `ErrorState`(요청 ID 포함), `EmptyState`, `InlineNotice`
- 훅: `useSearchState`(URL 필터), `useTabParam`, `useRefreshInterval`, `useMutationFeedback`(토스트와 캐시 무효화)

`v0.86.0`부터 공통 `DataTable`은 화면이 안정적인 `tableId`를 지정한 경우에만 열 표시·순서·너비
맞춤 설정을 제공한다. 공급자와 모델 목록에서 먼저 활성화했으며 리소스 식별 열과 쓰기 작업 열은
숨길 수 없다. 열 설정은 허용된 열 ID, 순서, 표시 여부, 80~640px 범위의 너비만 브라우저에 저장한다.
요청 ID, 행 데이터, 필터, 페이지 커서, Prompt와 Secret은 저장 형식에 포함되지 않는다. 저장값은
현재 열 allowlist로 다시 검증하고 손상된 값, 사라진 열, 마지막 열을 숨기는 값은 폐기한다. 표가 실제로
가로로 넘칠 때만 이동 안내를 표시하고 로딩 중에는 머리글과 열 폭을 유지하는 skeleton 행을 사용한다.
마우스 드래그뿐 아니라 열 이동 버튼과 머리글 resize handle의 화살표·Home·End 키도 지원한다.
`tableId`가 없는 기존 사용처는 전과 같은 호출·레이아웃 계약을 유지한다.

화면 테스트는 `renderScreen`, `mockApi`, `testAuth` 헬퍼를 사용한다. `mockApi`는 등록되지 않은 API 호출을
실패로 처리하므로, 화면이 호출하는 서버 계약이 테스트에 빠짐없이 드러난다.

### 공통 편집창의 미저장 변경 보호 (`v0.86.4`)

`FormDialog`를 사용하는 편집창은 입력이 변경됐을 때 취소·닫기·Escape·바깥 영역 클릭에 대해
‘계속 편집 / 변경 버리기’를 확인한다. 원래 값으로 되돌아갔거나 수정하지 않은 창은 바로 닫는다.
워크플로 단계 편집기와 앱·워크플로 예시 채우기도 변경 감지에 포함한다. 역할 편집과 관리자/내 API 키
신규 발급의 스코프 선택은 폼 상태로 통합해 스코프만 수정한 경우도 감지하고 제출 시점의 값을 보낸다.
역할의 기존 알 수 없는 스코프와 API 키 신규 발급의 빈 스코프 생략 계약은 유지한다.

- `/app`의 데이터 라우터에는 하나의 보호기를 두어 여러 편집창이 있어도 화면 이동·뒤로 가기·쿼리
  이동에 대한 결정을 한 번만 받는다. 계속 편집하면 초안을 유지하고, 버리기를 확정해야 이동한다.
  이동이 끝난 뒤 새 본문으로 포커스를 보내며, 보안상 로그아웃이 끼어들면 해당 포커스 이동도 취소한다.
- 새로고침·탭 닫기·문서 이동은 브라우저의 `beforeunload` 경고를 사용한다. 문구·노출 여부는
  브라우저가 결정하며 사용자 조작이 없거나 모바일에서 프로세스가 종료되는 상황까지 보장하지 않는다.
- 저장 중에는 입력 영역의 기본 폼 컨트롤과 편집 버튼을 잠가 서버에 보내지 않은 새 입력이
  성공 응답에 묻혀 사라지지 않게 한다. 편집창의 버리기와 `/app` 내부 이동, 중복 제출도 막는다.
  저장 성공은 경고 없이 닫고 검증·저장 오류는 입력을 유지하며 다시 편집할 수 있다.
  저장 완료 뒤 이전 이동 시도가 자동 실행되지는 않는다.
- 로그아웃·다른 탭 로그아웃·인증 만료는 초안 보호보다 우선한다. 이전 확인창을 기다리거나
  인증 복귀 후 이전 이동을 재개하지 않는다. 보안상 종료된 편집창의 초안을 복원하지 않는다.
  로컬 인증·조회 캐시 제거와 다른 탭 통지는 원격 로그아웃 응답보다 먼저 처리한다. 기존 자격 정보는
  해당 세션의 폐기 요청에만 사용하고, 늦은 SSO 로그아웃 응답이 새 로그인 화면을 이동시키지 않는다.
  API 요청과 공통 변경 처리에는 메모리 세대 검사를 두어 이전 토큰 갱신·401 재시도·저장 결과가
  새 세션의 토큰·캐시·알림·사용자 콜백을 갱신하지 않도록 한다. 같은 세션의 정상 토큰 회전은 유지한다.
  중복 로그아웃 전송은 한정된 메모리 식별자로 구분하며 입력값·사용자 식별자를 추가 수집하지 않는다.
  이미 서버가 처리 중인 저장을 취소하는 기능은 아니다. 같은 편집창 인스턴스를 다시 사용하는
  경우 이전 요청이 끝날 때까지 새 저장·취소를 잠그고, 응답 후 잠금을 해제하되 새 초안은 건드리지 않는다.
- 보호기는 변경 여부·진행 상태·수명주기 콜백만 메모리에 보관한다. 입력값·비밀값·URL을
  별도로 복사하거나 브라우저 저장소·로그·사용 관측에 기록하지 않으며 자동 저장 기능이 아니다.

이는 공통 `FormDialog` 사용처의 보호다. 아래에서 설명하는 전용 설정창과 `v0.86.11`의 API 키 권한 수정 외의
인라인 폼 등 다른 입력 방식은
별도 이전·검증 대상이며 검색 필터와 일회성 실행 입력까지 모두 저장 초안으로 간주하지 않는다.
전체 FORM-007 완료와 실제 서버 업무 E2E는 [인수 검증표](APP_UI_ACCEPTANCE.md)에서 따로 추적한다.

공통 기본·위험 작업 버튼과 본문 바로가기에는 배경에 대응하는 전경색 토큰을 사용한다.
다크 모드의 밝은 강조 배경에 흰 글자를 고정하던 대비 문제를 수정했으며, 390px 다크 편집 확인창을
axe·키보드·가로 넘침 검사로 검증한다. 이것만으로 모든 화면의 WCAG 적합성을 선언하지 않는다.

### 설정 초안과 복구 작업 보호 (`v0.86.5`)

콘솔 기능 전환 편집창과 개별 설정 상세창에도 공통 미저장 변경 보호를 연결한다. 설정값뿐 아니라
변경 사유도 초안에 포함하고, 저장 중에는 입력·닫기·중복 저장을 잠근다. 화면을 열었을 때의
설정값과 버전을 함께 고정하므로 자동 조회 갱신이 수정 중인 값이나 충돌 검사 기준을 바꾸지 않는다.
새 DB 오버라이드를 만드는 경우도 `expected_version=0`으로 부재 상태를 확인한다.

- 409 충돌은 초안을 유지하고 최신 설정을 다시 열어 검토하도록 안내한다. 자동 재저장하지 않는다.
- `503 setting_reload_pending`은 DB 저장 후 런타임 반영이 실패한 상태다. 저장이 안 된 것으로
  오인해 다시 보내지 않고, 반영 대기 안내와 최신 조회를 제공한다.
- 수정 중 **되돌리기 / 롤백**을 누르면 먼저 초안 폐기를 확인한 뒤 별도의 사유 입력창을 연다.
  그 사이 화면 이동이나 로그아웃이 발생하면 복구 확인창을 다시 열지 않는다.
- 콘솔 전환의 전역 설정과 런타임 설정은 같은 복구 구성요소를 사용한다. 전역 설정의 복구 버튼이
  상세창만 닫고 실제 작업으로 이어지지 않던 경로를 수정한다. 권한·비밀 설정의 롤백 제한은 유지한다.

롤백은 선택적 `expected_version`, `expected_updated_at`, `expected_history_id`, `expected_history_count`로
검토한 설정과 이력을 확인한다. 이력 행의 `history_count`는 같은 조회에서 LIMIT을 적용하기 전 해당
설정의 전체 이력 개수다. 서버 간 시계 차이 때문에 새 이력이 과거 시각으로 정렬되더라도 추가 사실을
감지한다. 새 화면은 이 개수가 없는 응답으로 롤백을 실행하지 않는다.
삭제 후 재생성되거나 환경변수 값으로 돌아간 경우도 오래된 검토 결과로
덮어쓰지 않도록 한다. 기존 필드를 생략하는 호출 형식은 유지하되 서버가 선택한 이력과 저장 사이의
변경도 검사한다. 새 설정 화면은 이 계약을 모르는 서버에서 열리지 않도록 프런트엔드의 최소
백엔드 버전을 `v0.86.5`로 고정하고, 이전 서버가 허용 상태를 광고해도 기존 화면으로 연결한다.
이 버전 확인은 서로 다른 서버 버전을 혼합한 운영 환경 전체의 원자적 전환을 보증하지 않는다.
원자 검사를 위해 롤백 저장 트랜잭션에서만 짧게 설정 쓰기를 직렬화하며,
일반 조회를 막거나 런타임 재적재 동안 잠금을 유지하지 않는다. 잠금 경합은 DB에 따라 대기하거나
변경 없이 실패할 수 있으며 쓰기를 자동 재시도하지 않는다. 잠금 동작은
[PostgreSQL의 명시적 잠금](https://www.postgresql.org/docs/current/explicit-locking.html)과
[SQLite 트랜잭션](https://www.sqlite.org/lang_transaction.html)의 규칙을 따른다.

이력 개수 검사는 지원 API가 이력을 추가만 하고 삭제·재작성하지 않는 현재 계약에 의존한다.
향후 이력 정리·교체 기능을 추가한다면 재사용되지 않는 별도 세대로 바꿔야 한다. 기존 시각순
이력 표시를 커밋 순서로 바꾸는 기능은 아니며, 검토한 이력의 복구 대상을 고정하는 보호다.
단건 저장·기본값 되돌리기의 기존 버전 검사는 유지하며, 그 두 API의 삭제·재생성까지 이력 세대로
보호하는 확장은 이 릴리즈의 완료 범위에 포함하지 않는다.

이 보호는 입력값·비밀값을 로컬 저장소에 복구하지 않는다. SSO·알림·비용 보호 등 나머지 자체
편집 폼의 이전과 실제 Go 서버를 연결한 브라우저 검증은 여전히 별도 인수 항목이다.

### 한글 표시와 전환 설정 저장

`v0.86.1`에서는 채팅 테스트·게이트웨이 MCP·스킬·레드팀 메뉴와 관련 작업 이름을 한글로 통일한다.
실제 메뉴는 서버 bootstrap의 제목을 사용하므로 서버와 React의 기본 전환 목록을 함께 맞춘다.
MCP 위험도·판단, 정책 조건·동작, Text2SQL 권한 주체·동작은 한글 표시 이름과 API 코드값을 분리한다.
알 수 없는 서버 코드나 사용자가 지은 리소스 이름을 임의의 정상 상태로 번역하지 않는다.

기능별 콘솔 전환 설정은 기존 `PUT /admin/settings/bulk`로 변경된 항목만 한 번에 저장한다.
각 항목에 조회 당시 버전을 보내고 DB override가 없으면 `expected_version=0`을 사용한다.
서버는 값·버전·설정 이력을 하나의 트랜잭션에서 반영하므로, 뒤 항목의 검증이나 버전 확인이 실패해도
앞 항목만 적용되는 상태를 만들지 않는다. 변경 사유는 기존 설정 이력에 함께 남는다.

- `409` 동시 수정 충돌: 입력 초안을 유지하고 재저장을 막는다. 최신 설정을 다시 조회한 뒤 편집창을
  다시 열어 변경을 검토한다.
- `503 setting_reload_pending`: DB에는 일괄 저장됐지만 런타임 반영이 대기 중임을 알린다.
  요청 ID와 함께 최신 설정을 확인하도록 안내하며 자동으로 같은 저장을 반복하지 않는다.
- 그 외 오류: 편집창과 입력을 유지하고 기존 공통 오류 처리와 서버 권한 검사를 사용한다.

이 개선은 `/app` 기본 활성화나 Stable 승격을 뜻하지 않는다. Phase 6의 기능별 사용·기존 화면 복귀
관측, 운영 기간의 안정성·성능 근거, 역할별 전체 업무 E2E 검증은 계속 남아 있다.

## 선택적 사용 관측 (`v0.86.2`)

`ui.app.telemetry_enabled`는 계속 기본 `false`다. 운영자가 명시적으로 켰을 때만 권한을 통과한
기능 진입과 해당 화면에서 기존 화면 링크를 연 방문을 같은 출처의 API로 관측한다.
`POST /admin/ui-telemetry/events`는 기능 ID, 방문마다 새로 만든 128비트 임시 ID, 두 종류의 이벤트만
받는다. 임시 ID는 메모리에만 있고 DB에는 SHA-256 해시만 남는다. 사용자·팀·역할·토큰·IP·User-Agent·
URL·검색어·Prompt·응답·SQL 결과를 이 집계에 넣지 않는다. 네트워크 인증·전송 자체에서 사용하는
Bearer와 IP를 없애는 기능은 아니며 기존 서버 인증·업무 감사 체계도 변경하지 않는다.

- 동일 방문의 재렌더·필터 변경·여러 클릭은 중복 집계하지 않는다. 클릭이 먼저 도착해도 하나의
  방문과 하나의 이동으로 저장한다. 비율은 ‘관측된 방문 중 기존 화면 링크를 연 방문’이며 순사용자,
  전체 채택률 또는 기존 화면 도착 성공률이 아니다.
- 수집 요청마다 현재 DB의 활성화·수집 설정과 기존 기능 권한·역할·점진 배포·이동 허용을 확인한다.
  수집을 끄기 전에 수락한 진행 중 요청은 끝날 수 있다. 취소 예산은 2초이며 드라이버 취소·정리
  지연까지 포함한 엄격한 응답 시간 보장은 아니다. 실패는 버리며 자동 재시도·영구 큐를 두지 않는다.
- 본문은 1KiB, 동시 처리는 프로세스당 4개, 수신은 초당 20개(순간 최대 40개)로 제한한다.
  인증을 통과한 호출자도 프로세스별 UTC 일자당 최대 600개 이벤트로 제한한다. 호출자 원본 ID 대신
  프로세스·날짜별 무작위 키로 만든 HMAC만 메모리에 두며 집계 DB·로그에 기록하지 않는다.
  메모리의 호출자 슬롯은 4,096개로 제한하고 가득 차면 기존 한도를 초기화하지 않고 새 호출자의
  이벤트를 버린다. 공유 관리자 자격은 같은 한도를 쓰며, 여러 파드의 합산 한도나 재시작을 넘는
  영속 한도가 아니다. 빠른 단일 호출자 용량 독점을 완화할 뿐 클라이언트가 신고하는 집계의
  진실성을 보증하거나 모든 서비스 거부 공격을 차단하지는 않는다.
  DB는 최대 10만 방문, 집계는 최근 30일로 제한한다. 만료 기록은 새 수집 트랜잭션·서버 시작·
  매시간 정리하며, 일반 retention이나 수집을 꺼도 정리 루프는 작동한다. DB 오류로 실패한
  정리는 다음 주기에 다시 시도하므로 실제 삭제 시각에는 지연이 있을 수 있다.
- SQLite 관측 트랜잭션은 전용으로 빌린 연결의 잠금 대기를 50ms로 제한하고 원래 값을 복원한다.
  복원에 실패한 연결은 풀로 돌려보내지 않는다. 전역 DB 잠금 정책이나 기존 업무 동작은 바꾸지 않는다.
- `GET /admin/ui-telemetry/summary?days=7|30`은 관리자 조회 권한으로 현재 접근할 수 있는 기능의
  집계만 반환한다. 원본 방문 ID/해시·개별 시각은 반환하지 않는다. **시스템 설정 → 콘솔 전환**에서
  수집 상태·기간·방문·이동·비율을 확인하며 기간은 URL에 유지한다.
- 좁은 화면에서는 사용 관측과 전환 설정 표 각각의 내부에서 가로 스크롤한다. 조회 버튼은
  갱신 중에도 키보드 포커스를 유지하며 중복 활성화를 무시한다. 제목 단계를 유지하고,
  390px 브라우저에서 문서 가로 넘침·기간 변경·키보드 갱신을 검증한다.
- 로그인·최상위 오류 화면, 계측되지 않은 브라우저 컨텍스트 메뉴 동작, 전송 실패와 상한 초과는
  관측에서 빠질 수 있다. 이 수치로 자동 Stable 승격하지 않는다. 별도의 업무·역할·안정성·성능
  근거가 필요하다. 기존 `tracking.*` 외부 방문 추적과 연결하거나 자동 활성화하지 않는다.

로그아웃·다른 탭 로그아웃·계정 교체 뒤 이전 인증 조회나 SSO 교환 응답이 늦게 도착해도 이전
인증·수집 상태를 복원하지 않는다. 수집 설정을 확인할 수 없을 때는 마지막 정상 탐색 상태와 달리
수집만 닫힌 상태로 처리한다.

## 빌드와 배포

### 검색과 키보드 탐색 (`v0.86.3`)

명령 팔레트는 한글 조합 입력 중 확인·후보 이동·취소 키를 명령으로 실행하지 않는다.
메뉴명·그룹·별칭을 여러 단어로 검색할 수 있으며 NFC로 한글 조합 형태를 맞춘다.
요청·추적·세션 ID 바로가기는 현재 권한으로 React 요청 탐색기를 열 수 있을 때만 제공한다.
기존 화면 전용 상태에는 React 필터를 넘길 수 없으므로 해당 바로가기를 숨긴다.
검색 결과가 없으면 안내와 초기화 버튼을 제공하고 live 영역에는 원문 대신 개수만 알린다.
닫기·도움말 연쇄 이동은 원래 요소로, 화면 이동은 본문으로 포커스를 복원한다.
낮고 좁은 화면에서도 검색·닫기는 유지하고 목록이나 도움말 본문만 스크롤한다.
검색어를 새로 영속 저장·전송하지 않으며 Route Guard와 서버 권한 검사를 대체하지 않는다.

### 빌드 성능 예산 (`v0.86.3`)

`pnpm build`는 Vite 빌드 뒤 성능 검사를 실행한다. 단순히 가장 큰 JS 파일 하나를 비교하지 않고,
Vite manifest와 실제 HTML·CSS 참조를 따라 동일 파일을 한 번만 합산한다. 숫자는 1KB = 1,000B 기준이다.

- **초기 빌드 에셋: 350,000B 이하.** HTML·정적 JS 의존성·스타일·참조 폰트와 이미지의 전송 크기
  참고값을 합산한다. Go가 압축하는 확장자는 파일마다 gzip level 9와 원본 중 작은 값을 쓰고,
  이미 압축된 폰트·이미지 등 나머지는 원본 크기로 계산한다. Go 서버 소유 `/favicon.ico`는
  프론트엔드 산출물이 아니므로 보고서의 제외 항목에 명시한다.
- **화면별 추가 에셋: 원본 250,000B 이하.** 각 지연 로딩 진입점에서 초기 캐시를 제외한 정적 의존성과
  하위 동적 의존성·CSS·에셋을 합산한다. 선택적으로 여는 하위 화면도 보수적으로 포함한다.
  초기 공통 파일은 의존성 순회 자체를 중단해 다른 화면 전체를 잘못 합산하지 않는다.
- manifest·진입점·정적으로 확인한 참조 파일 누락, 리터럴 외부 URL·출력 디렉터리 탈출, 예산 초과는 빌드를 실패시킨다.
  따라서 동일한 `pnpm build`를 쓰는 CI와 Docker 릴리즈 빌드도 실패한다. 환경변수나 CLI로 상한을
  완화하지 않으며, 변경하려면 검사 코드·테스트·문서를 함께 검토한다.
- `web/bundle-budget-report.json`은 재생성 가능한 검사 결과이며 Git과 Docker 컨텍스트에서 제외한다.
  CI는 성공·실패 여부와 별개로 생성된 보고서를 14일 보관한다. `pnpm bundle:check`로 기존 빌드를
  재검사할 수 있다. `.vite/manifest.json`은 빌드용이며 `/app`의 숨김 경로 차단 대상이다.
- 출력 JS의 정적 import·export, 문자열 리터럴 동적 import와 `new URL(..., import.meta.url)`도 검사한다.
  실행 중 계산하는 참조는 정적으로 확정할 수 없으므로 `unresolvedRuntimeReferences`에 파일·종류·건수만
  보고하고 측정에서 제외한다. React Router·Vite의 런타임 helper도 이 범주에 들어가며 코드나 URL 값은
  보고서에 넣지 않는다. 따라서 이 검사는 모든 런타임 네트워크 요청의 오프라인 적합성을 보증하지 않는다.

이 검사는 재현 가능한 빌드 용량 예산이다. Node gzip과 Go의 실제 압축 결과에는 차이가 있을 수 있고,
API 응답·HTTP 헤더·네트워크·기기 성능을 측정하지 않는다. 2초 사용 가능·300ms 화면 이동·Lighthouse
점수와 운영 Stable 승격에는 별도 실행 환경의 측정 근거가 필요하다.

프로덕션 이미지는 세 단계로 만든다.

1. Node 24 builder가 고정된 pnpm lockfile로 `web/dist`를 생성한다.
2. Go 1.26.8 builder가 해당 산출물을 `internal/appui/dist`에 복사하고 바이너리에 embed한다.
3. Distroless nonroot 런타임에는 단일 gateway 바이너리와 쓰기 가능한 `/data`만 남긴다.

동일한 release version을 `VITE_UI_VERSION`과 `proxy.AppVersion`에 주입한다. frontend build, 비어 있는 index, asset 누락 중 하나라도 발생하면 release build는 실패한다.

## SSO·알림 인라인 편집 보호 (`v0.86.6`)

- 조회 시각을 React `key`로 사용하던 재생성을 제거한다. 수정하지 않은 폼만 새 조회 값으로 갱신하고,
  수정·확인·저장 중인 값과 SSO 버전은 함께 고정한다. 공통 이동 보호·저장 중 입력 잠금·세션 세대
  검사를 재사용하며 비밀 초안을 브라우저 영속 저장소에 넣지 않는다.
- SSO 편집 조회는 한 DB 레코드의 값·버전·비밀값 존재 여부로 구성한다. 이전 로그인 런타임의 값과
  새 DB 버전을 섞지 않으며 조회만으로 로그인 런타임을 변경하지 않는다. DB 저장 후 재적재 실패는
  이미 저장된 결과로 안내하고 최신 상태를 다시 검토하게 한다.
- Mattermost 설정은 제공된 필드만 한 트랜잭션으로 저장하고 같은 시점의 마스킹된 응답을 반환한다.
  웹훅 원문을 응답·감사·전송 오류에 재노출하지 않는다. 이벤트를 모두 해제하면 실제로 아무 범주도
  발송하지 않는다. 테스트 발송은 저장된 설정을 사용한다.
- 시스템 설정의 신규 UI는 최소 백엔드 `v0.86.6`을 요구한다. 알림의 동시 편집 CAS, 모든 자체 폼의
  보호, 모든 서버의 반영 완료, 실제 인증 서버 브라우저 흐름이나 운영 Stable 승격을 뜻하지 않는다.

프론트엔드의 최소 버전 검사를 낮추지 않으며, 참조 조회 API가 없는 서버에서는 기존 화면으로 안내한다.

- 원본 공급자 이름 대신 불투명 참조로 조회하며, 비밀값·프롬프트·키 이름/해시·소유자/IP는

  각 구성 조회는 행 수·필드 길이로 제한하고 SQLite/PostgreSQL에서 동일 의미를 검사한다.
- 수정·삭제 검토에서 현재 설정과 미확인 범위를 안내한다. 전체 모델 사용 분석·패턴 교차 분석·
  편집안 시뮬레이션·동시 변경 CAS·실제 호출 성공과 운영 Stable 검증은 여전히 잔여다.

## API 키 권한 편집 보호 (`v0.86.11`)

- 기존 키의 권한 수정창을 공통 폼으로 이전하고 권한명과 설명을 한글로 제공한다.
  기계 식별자는 보조 설명으로 유지하며, 알 수 없는 기존 권한도 명시적으로 해제하기 전에는 보존한다.
  기존 `/admin/roles`의 지원 권한 목록으로 저장 전 검증하고 미지원 선택값이나 목록 미확인 시
  저장을 차단한다. UI에 설명은 없지만 서버가 지원하는 값은 허용하고 저장 API의 검증도 유지한다.
- 열린 대상·초기 권한은 고정한다. 목록 갱신이 초안을 덮어쓰지 않으며 닫기·이동·새로고침 보호,
  저장 중 입력·중복 제출 잠금, 오류와 요청 ID, 작업 후 포커스 복원을 적용한다.
- 전체 해제는 명시적인 빈 배열 저장이며 역할 권한을 자동 상속하지 않는다. 인증이 활성화된
  환경에서 필요한 권한이 없는 호출은 거부되지만 모든 키 사용의 중단은 별도 상태 변경이다.
  새 키 발급에서 권한 필드를 생략하는 기본값 적용과 구분한다. 서버 권한·저장 API와 기존
  관리자 화면은 변경하지 않는다.
- 로그아웃·새 로그인은 열린 초안을 폐기한다. 검증 중 세션 전환에 의한 요청 전송과 늦은
  이전 응답의 새 세션 변경을 차단한다. 구성요소·API fixture 브라우저·좁은 다크 화면을 검사한다.
  실제 Go 서버 키 편집 E2E, 관리자 간 동시 편집 CAS, 다른 모든 폼의 보호 완료는 주장하지 않는다.

## 정책 시뮬레이션의 실행 기준과 결과 해석 (`v0.86.30` 후보)

- 기존 정책 어드바이저의 추천별 계산을 유지하면서 실행한 이름·규칙·기간을 고정하고 한글 결과에
  명시한다. 실행 권한(`admin:write`·`security:read`)을 확인할 수 없게 되거나 사용자·역할·팀·화면 소유자·
  세션/탭 수명·기간이 바뀐 뒤의 늦은 결과와 중복 전송을 제한한다. 수동 재시도는 원래 규칙으로
  새 표본을 계산하며 정책 저장·적용으로 이어지지 않는다.
- 기능 읽기 전용은 순수 계산을 막지 않지만 기존 `admin:write`와 화면 조회 권한은 유지한다.
  기존 정책 초안 생성·CRUD·캐너리 변경이나 서버 평가 로직을 다시 구현하지 않는다.
- 결과 상태는 집계값만 보관하고 원문 표본을 새 캐시에 추가하지 않는다. 현재 접두사로 새 동적 표시를
  가리되 전송 규칙은 그대로다. 0·누락·분모 없음, 복원하지 못한 조건, 현재 팀 정보, 최대 5,000개
  조인 표본과 이동하는 조회 범위를 설명한다. 과거 추정 비용과 오탐 후보를 절감액·안전 판정으로 표시하지 않는다.
- 신규 UI 48개/관련 87개·전체 Vitest 2,538개, 전용 합성 브라우저 13개/전체 660개가 통과했다.
  390px 다크의 실제 Tab·PageDown 스크롤·초점 복원과 이름 있는 읽기 영역을 검증했다.
  별도 실제 Go·SQLite HTTP 4개와 하위 사례 8개는 기존 계약을 검사하며 합성 UI와 동일 E2E는 아니다.
  자세한 근거와 최초 실패는 [인수 검증표](APP_UI_ACCEPTANCE.md)에 구분한다.
- 이 사전 UI 검증은 v0.86.29 라벨 후보 빌드이며 최종 v0.86.30 버전·CI·릴리즈 검증과 구분한다.
  운영 정책 초안의 전체 영향·완전한 과거 문맥 재현·정식 승격은 미완료다. `/app`은 Preview,
  기본 OFF를 유지하고 `/admin`도 계속 제공한다.

## 추천의 비활성 정책 초안 생성 검토 (`v0.86.31` 후보)

- 기존 어드바이저의 추천→초안 생성 한 경로에 한글 검토창을 제공한다. 열린 추천의 이름·규칙 내용과
  선택한 분석 기간을 고정하며, 목록 갱신으로 새 추천이 도착해도 대상을 교체하지 않는다. 기간·조회 기준이
  달라지면 원래 규칙을 다시 확인해야 하고, 시뮬레이션 성공을 저장 요건이나 안전성 보장으로 추가하지 않는다.
- 초안 생성 API 호출을 시작하기 직전에 현재 기능 소유자·읽기 전용·`security:read`와 `admin:write`·사용자·역할·팀·세션을
  확인한다. 생성 중 중복을 제한하고 닫힌 검토의 콜백·늦은 응답·취소된 조회를 새 검토와 격리한다.
  조회 복구와 기간 왕복도 자동 생성으로 이어지지 않는다. 인접한 순수 시뮬레이션의 읽기 전용 허용과
  기존 캐너리 전송 본문·정책 CRUD·서버 권한은 유지한다.
- 기존 API의 `title/conditions/actions`만 그대로 보내 비활성 정책을 만든다. 실제 적용은 별도다.
  확인되지 않은 생성 응답은 불확실한 상태로 안내하고 일반 오류·불명확한 응답에 새 자동 재시도를
  추가하지 않는다. 기존 공유 클라이언트의 401 인증 갱신 후 재전송은 유지한다. 수동 재생성도 중복을
  만들 수 있으며, 확정된 생성 성공 뒤 조회 실패는 생성 실패와 구분해 GET만 다시 실행한다.
- 현재 접두사로 새 검토 내용·요청 ID의 표시를 보호하지만 원문 전송·정책 저장·별도 감사는 그대로다.
  원자적 감사·멱등성·서버 동시 변경 차단을 추가하지 않는다. 서버 설정에 따른 후속 모의 검사와
  최초 시드 설정·이력을 포함한 기록이 발생할 수 있으므로 모든 DB 쓰기가 정책 하나에 한정되지는 않는다.
- 신규 UI 57개/관련 180개·전체 Vitest 2,595개(191파일), 전용 합성 브라우저 13개/전체 673개가
  사전 후보에서 통과했다. 390px 다크의 줄바꿈·실제 Tab/PageDown·초점 복원·axe를 확인했다.
  별도 실제 Go·SQLite HTTP 5개와 하위 사례 16개는 정상/race로 기존 저장·권한·후속 기록 계약을
  고정한 검사이며 합성 UI와 동일한 실제 Go 브라우저 검증은 아니다. 최초 실패와 의도적 중단은
  [인수 검증표](APP_UI_ACCEPTANCE.md)에서 구분한다.
- 위 UI 근거는 v0.86.30 라벨의 사전 후보다. 최종 v0.86.31 버전·통합 회귀·CI·릴리즈 자산 검증은
  별도로 완료해야 한다. 활성화·캐너리 변경의 전체 영향 검토, 운영 IdP·업무 검증과 Stable 승격은
  이 범위로 완료되지 않는다. `/app` Preview·기본 OFF와 `/admin` 제공을 유지한다.

## 비활성 정책의 메타데이터·복수 규칙 편집 (`v0.86.32` 후보)

- 기존 정책 목록의 `초안 편집`에서 이름·설명·우선순위와 여러 규칙의 이름·사용 여부·우선순위·
  조건·동작 JSON을 편집한다. 규칙 추가·명시적 삭제와 한글 변경 전후 비교를 제공하고, 변경이
  없으면 POST하지 않는다. 모든 규칙 제거에는 추가 확인이 필요하며 정책 삭제를 의미하지 않는다.
  비활성 상태와 기존 적용 비율을 유지하며 기존 빠른 생성·사용 전환·캐너리·시뮬레이션 계약은 바꾸지 않는다.
- 기존 API의 정책 전체 저장·규칙 전체 교체를 재사용한다. 보존 가능한 규칙 ID·미편집 JSON과
  알 수 없는 중첩 필드를 유지하되 원문 전체의 바이트 보존을 약속하지 않는다. 이름·설명은 Go 공백
  정리 결과를 비교에 반영한다. 정규화로 정책 ID가 바뀌면 진입을 막고, 규칙 ID·JSON 최상위 키를
  보존할 수 없는 경우에는 해당 규칙의 교체·삭제 또는 JSON 전체 교체로 해결하도록 안내한다.
  실제 Go `omitempty`의 규칙 필드 생략만 빈 배열로 해석하고 `null`·불완전 원본을 임의로 정상화하지 않는다.
- 현재 접두사와 기존 민감값 판정에 해당하는 원문은 새 입력란·검토·배경 정책 목록에 표시하지
  않는다. 원문 유지와 빈 입력에서의 명시적 전체 교체를 구분하며 보호 문구를 저장하지 않는다.
  새 민감 입력은 거부하고 일반 정책 JSON 편집은 제공한다. 주소·브라우저 저장소·새 변경 요청
  캐시에 원문을 추가하지 않지만 기존 서버 저장·별도 감사의 비밀정보 제거를 보장하지는 않는다.
- 변경 폐기 보호와 고정 원본·검토 승인을 사용한다. 저장 전 최신 GET 뒤에도 현재 기능 소유자·
  사용자·역할·팀·세션·`security:read`·`admin:write`·읽기 전용과 동일한 비활성 원본을 확인한다.
  단일 실행 잠금, 계정 왕복 시 편집 폐기, 권한 회수·복구 뒤 옛 검토 거부, 현재 행 초점 복귀를
  검증한다. 조회 후 저장 사이의 서버 동시 변경까지 차단하는 CAS나 서버 멱등성은 추가하지 않는다.
- 유효한 저장 응답은 정책 ID·비활성 상태·변경값과 규칙 ID로 확인한다. 불명확한 응답을 미저장으로
  단정하지 않으며 명시적 수동 조회에서 원본 전체가 동일함을 확인하기 전에는 재저장을 잠근다.
  변경·삭제된 원본이나 실패한 조회는 잠금을 풀지 않는다. 일반 오류에 새 자동 재시도를 추가하지 않고 기존 401 인증
  갱신 후 재전송은 유지한다. 확인된 저장과 후속 조회 실패를 구분하고 조회만 다시 실행할 수 있다.
  서버 설정에 따른 기존 후속 모의 검사·감사·초기 시드 기록 가능성도 유지한다.
- 통합 전 신규 UI 82개/관련 262개, 전체 Vitest 2,677개(195파일), 전용 합성 브라우저 22개와
  전체 695개가 통과했다. 전용 브라우저는 다중 규칙 보존·현재 권한·보호값·불명확한 응답·재조회 및
  390px 다크의 키보드·스크롤·줄바꿈·axe를 검증한다. 별도 실제 Go·SQLite HTTP 7개와 하위 사례
  16개의 정상/race 검사는 기존 정규화·규칙 교체·권한·감사 계약 근거이며 실제 Go 브라우저 검증과는 다르다.
- 위 UI 검증은 v0.86.31 라벨의 통합 전 후보다. 이후 최종 v0.86.32 `e1357ca1`에서
  전체 Vitest 2,688개/195파일·브라우저 698개(재시도/불안정 0), 원격 CI와 7개 배포 자산을
  확인해 게시했다. 정책 활성화·캐너리의 전체 영향 검토, 운영 검증 및 전체 Phase 인수는
  완료되지 않았으며 `/app` Preview·기본 OFF와 `/admin` 제공을 유지한다.

## 선택한 요청의 안전한 단계 기록 (`v0.86.33`)

- 추적 탐색기에서 선택한 요청의 루트·도구·텍스트 SQL 하위 단계를 한글 표와 기록 타임라인으로
  제공한다. 기록 상대 위치는 음수를 유지하며 실제 실행 시작/종료와 구분한다. 도구 소요 시간,
  잘못된 기록 시각·지연은 추정값 대신 미기록/확인 불가로 표시한다. 표시 시간대만 변환하며
  요청 조회에는 원래 UTC 나노초 시각과 기존 불투명 요청 참조를 그대로 사용한다.
- 새 GET `/admin/app/request-flow`는 기존 저장소의 제한된 메타데이터를 집계한다. 기존 인증·
  팀 범위를 유지하고 후보 요청 200개·하위 소스별 100개의 상한을 적용한다. SQL 조회 열에서
  프롬프트·응답·SQL·도구 인자·원문 오류를 제외한다. 이 제한은 물리 디스크의 바이트 접근이나
  기존 원문 API·감사 전체의 무수집 보장이 아니다. 새로운 인덱스나 업무 변경은 추가하지 않는다.
- 현재 목록의 정상 조회와 인증·권한·선택 수명을 기준으로 상세 조회를 허용한다. 부모 목록
  갱신 중 기존 표·키보드 초점을 보존하되 이전 기록으로 표시하며, 조회 실패·다른 계정의 캐시를
  새 조회 근거로 쓰지 않는다. 계정 왕복·권한 회수 후의 늦은 응답을 폐기한다. 서버 데이터는
  TanStack Query가 관리하며 새 원문 ID·단계 내용을 URL이나 브라우저 영속 저장소에 넣지 않는다.
- 응답은 OpenAPI 생성 타입과 엄격한 런타임 계약으로 확인한다. 대상 불일치·중복 참조·잘못된
  부모·루트 시각/위치·상한 초과를 거부하고 원문 추적 API로 자동 우회하지 않는다. 오류·빈 하위
  목록·생략·조회 상한을 구분하며 현재 민감값 접두사에 따른 표시 보호와 수동 재조회를 제공한다.
- SQLite/PostgreSQL의 실제 쿼리·권한·대규모 자연 실행 계획과 합성 브라우저의 화면 수명·
  모바일/키보드 검사는 별도 근거로 관리한다. 최종 로컬 Vitest 2,745개/199파일, 브라우저
  721개(재시도 0), 전체 Go normal/race·실제 인증·공급자 검사가 통과했다. 컨테이너·원격 CI·
  정확한 태그와 배포 자산 확인은 별도 출고 게이트이며 사전 통과로 대체하지 않는다.
  이 기록은 선택된 한 요청의 제한된 직접 하위 관계이며 완전한 분산 추적·전체 세션 스팬 트리·
  실행 시간 재구성·운영 Stable 승격이나 Phase 0–6 완료를 의미하지 않는다.

최종 v0.86.33 `4668c416`은 메인 CI·태그·컨테이너와 공개 7개 배포 파일의 재다운로드 검증을
거쳐 게시했다. 이 출고 근거는 다음 버전의 구현·검사를 대신하지 않는다.

## 요청 상세창의 처리 단계 직접 조회 (`v0.86.34` 출고 기록)

- 요청 탐색기의 상세창에서 `처리 단계 보기`를 명시적으로 누를 때 기존 안전 GET을 사용한다.
  추적 ID가 없어도 원래 v2 참조·나노초 시각으로 조회하며 기존 요약·비교·기존 화면 연결은 유지한다.
- 기대 기능 소유자를 요청/추적 화면으로 명시하고 현재 인증·권한·팀·세션 및 목록 수명을 확인한다.

  ID·생성 시각·사용 상태는 편집하지 않으며 변경이 없으면 저장하지 않는다. 보호된 원문은
  표시하지 않은 채 유지하거나 명시적으로 새 값으로 교체한다.
- 기존 목록과 별도의 엄격 GET/저장 응답 계약을 사용한다. 현재 Query/성공 세대·선택·계정/
  팀·세션·기능 소유자·권한과 검토 기준을 연결하고 미저장 변경·초점·한글 안내를 보호한다.
- 확인된 저장 뒤 재조회 실패와 저장 여부 미확정을 구분한다. 미확정 뒤 수동 조회가 성공해도
  같은 창의 재전송은 잠근다. 기존 인증 갱신은 유지하며 정확히 한 번 실행을 약속하지 않는다.
- 서버는 기존 URL의 PATCH만 기존 ID 전용 부분 UPDATE로 보강한다. 삭제된 행을 PATCH가
  재삽입하거나 생략된 값을 이전 조회 값으로 덮지 않고 실제 쓰기 시점의 복잡도 범위를 검사한다.
  생성·학습 upsert·삭제·사용 전환·기존 관리자·API 권한은 유지한다.

양 DB 정상·레이스 각각 신규 최상위 7개/하위 25개와 기존 최상위 3개, 두 패키지 vet 및
엄격 API 단위 35개/registry 2개·Go OpenAPI 단위 1개를 확인했다. 실제 Go HTTP 생성물은
468경로를 유지하며 버전·기존 GET/PATCH·4개 스키마만 확장한다. 최초 서버 경합 실패 3개와
교정 후 결과는 보존한다. 동결 후보의 전체 UI 단위 3,075개/214파일·Node 45개(선택 실행 3개
건너뜀)와 정적 검사, 전체 합성 브라우저 816개/36파일의 재시도 없는 통과를 확인했다.
초기 앱 계산 예산 236,511바이트·37경로 빌드, 실제 인증 11개/공급자 업무 1개/보고서 보호
16개, SBOM/라이선스 재현·SDK·구성요소·최종 후보 컨테이너 검사도 각각 확인했다.
전체 Go 일반·내부 패키지 레이스/vet·빌드·API 감사도 통과했고 원격 CI·출고는 대기다. 최초 실패와 테스트의
표시 기대값·시간 정렬 가정 교정을 숨기지 않으며 세부 범위는 [인수 검증표](APP_UI_ACCEPTANCE.md)를 따른다.

사전 GET과 부분 UPDATE는 CAS가 아니다. 명시한 동일 필드는 마지막 쓰기가 남고, 외부에서
같은 ID를 재생성한 경우 그 행을 수정할 수 있다. 활성 규칙 변경은 실제 트래픽에 영향을 주며
감사는 best-effort, 설정된 후속 모의 검사와 다른 pod의 기존 5초 캐시 TTL은 유지한다.
표시 보호는 원본 응답·캐시·서버 감사의 비밀 제거가 아니며 부분 UPDATE 보장은 v39 서버에
한정한다. 전체 영향 시뮬레이션·원자적 감사/롤백·Stable 승격과 Phase 완료는 범위 밖이다.

## 단계별 상태

| Phase | 범위 | 현재 상태 |
| --- | --- | --- |
| 0 | route/embed, App Shell, API client, auth/RBAC, registry, Legacy Bridge, CI | 기반·회귀 및 실제 Go/로컬 OIDC 인증 브라우저 검사 제공; 운영 IdP·HTTPS·전체 업무 검증 잔여 |
| 1 | 현황, 상태, 요청·추적·세션, 사용량·비용, 공급자·모델 조회 | 조회 화면·제한된 직접 하위 단계와 v38 추적 조회 기준/현재 선택 개선 출고; 전체 분산 스팬 트리·대규모 목록·전체 데이터 정합성 및 운영 검증 잔여 |

| 3 | 사용자·팀·API Key·Quota·MCP·App·Workflow·Skill | 주요 화면과 실제 키 발급·권한/세션 격리 검사 제공; 역할별 전체 업무·회전/폐기·팀 범위 검증 잔여 |
| 4 | Routing·Policy·Settings·Text2SQL·DW retry | 주요 화면·제한된 정책 시뮬레이션·추천의 비활성 초안 생성 검토와 복수 규칙 편집 제공; v39 기존 라우팅 7필드 검토/부분 저장 후보 검증 중. 전체 영향 검토·정책 활성화·캐너리 등 변경 안전성 잔여 |
| 5 | Kill Switch·Secret Rotation·Bulk Import 등 Critical 작업 | 공급자 삭제 대상 재입력과 v37 정책 파일 검토·원자적 가져오기·부분 재적용 출고; 운영 인수, 전체 참조 영향·키 회전·전체 복구·다중 서버 전환 검증 잔여 |
| 6 | `/app` 기본화와 기능별 Legacy deprecation 검토 | 진행 중 (기본 비활성 사용 관측 추가, 운영 근거와 정식 승격은 미완료) |

이전 문서의 ‘완료’ 표시는 화면 이식 마일스톤을 가리켰으며 전체 요구사항 인수 완료로 해석하지 않는다.
각 기능은 데이터 정합성, 권한, URL 복원, 상태 UI, 접근성, 성능, 변경 안전성, 감사, E2E,
Legacy fallback과 운영 사용자 검증을 모두 통과한 뒤에만 Stable로 승격한다. 단계 번호는 이전 순서이지
뒤 단계 작업이 시작됐다는 이유로 앞 단계의 미완료 검증을 생략하는 근거가 아니다.

## 검증 명령

```bash
cd web
corepack pnpm install --frozen-lockfile
corepack pnpm check

cd ..
go test ./...
go vet ./...

docker build --build-arg VERSION=dev-appui -t vibe-coders:appui .
bash scripts/container-smoke.sh vibe-coders:appui dev-appui
```

컨테이너 smoke test는 `/admin` 회귀, `/app` 308, deep link, hashed asset 캐시, 누락 asset 404, 잘못된 method 405, nonroot 실행, Backend/UI version 일치를 함께 확인한다.
