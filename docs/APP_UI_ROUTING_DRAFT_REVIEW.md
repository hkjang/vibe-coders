# 라우팅 초안 비교와 검토한 규칙 저장

v0.86.159 개발 후보. 원격 검토·메인 병합·공개 릴리즈와 운영 Stable 승격은 별도 검증한다.

`/app/routing/rules`에서 기존 규칙을 수정하고 **변경 내용 검토 → 초안 결과 비교 → 규칙 저장**으로 진행한다. 시험 모델, 예시 요청과 변경 사유를 입력하며 정책을 적용할 기존 API 키 ID는 선택 사항이다. 비밀키를 입력하지 않는다. 입력과 비교 결과는 URL이나 브라우저 저장소에 보관하지 않는다. 입력을 바꾸거나 비교를 취소하면 이전 결과로 저장할 수 없다.

현재 저장된 규칙과 편집한 복사본을 기존 Go 실행 계획 계산기에 각각 전달한다. 모델, 공급자, 복잡도·위험·상태 점수와 대체 경로 계획을 비교한다. 실제 모델을 호출하거나 규칙·변경 감사를 저장하지 않는다. 자동 모델 선택은 실제 요청과 마찬가지로 복잡도 규칙 단계를 우회한다. 기존 순서 비교 API는 계속 복잡도 규칙 단계만 비교한다.

두 계획에 같은 규칙 기준과 키 권한을 사용한다. 공급자 상태·설정과 학습 값은 순차적인 현재 조회이므로 비교 중 달라질 수 있다. 이는 전체 트래픽 영향 추정이나 실제 대체 호출 성공, 다중 서버의 즉시 반영을 보장하지 않는다. 시험 입력은 텍스트 메시지이며 도구·공급자 고정·라우팅 비활성 헤더는 지원 범위에 포함하지 않는다.

명시적인 새 API 모드:

- `POST /admin/routing/preview`: `rule_edit`와 `request`를 전달한다. 원본 ID, 부분 수정안과 전체 규칙 리비전을 요구한다. 기존 요청 형식은 유지한다.
- `PATCH /admin/routing-rules/{id}?review=edit`: `expected_revision`, `patch`, `reason`을 전달한다. 기존 쿼리 없는 부분 수정 동작은 유지한다.
- `GET /admin/routing-rules?view=order`: 기존 검토 스냅샷을 재사용한다. 최대 1,000개 규칙을 대상으로 하며 동일 우선순위·생성 시각으로 순서가 불확실한 규칙은 먼저 정리해야 한다.

새 저장 모드는 전체 구성 리비전을 DB 쓰기 잠금 안에서 다시 비교한다. 다른 규칙을 포함한 변경은 409로 거부하고, 규칙 수정과 감사 기록을 같은 트랜잭션에 저장한다. 일반 수정·생성·삭제와도 DB 쓰기 잠금을 공유하며 트랜잭션 안에서 외부 호출이나 재시도를 하지 않는다. 감사 실패와 저장 결과 불일치 시 롤백한다. 리비전은 구성 내용 해시이므로 ABA 탐지나 재전송 방지 토큰은 아니다. 응답을 잃으면 자동으로 다시 저장하지 않는다.

초안 비교는 기존 `routing:read`, 새 검토 저장은 `routing:read`와 `routing:write`가 모두 필요하다. 기존 키 정책의 팀 범위와 원문 조회에 따른 결과 보호를 유지한다. 백엔드 v0.86.159 이상에서 새 흐름을 사용하고 이전 서버에서는 기존 수정 흐름을 제공한다. `/admin`은 유지한다.

변경 후 보안 검사가 활성화되어 있으면 검토 저장과 순서 변경에도 기존 라우팅 보안 검사 팩을 적용한다. 저장·감사 커밋 이후 설정된 대상 수 상한 안에서 모의 실행하며 외부 공급자 호출을 허용하지 않는다. 검사 비활성화·긴급 중지 또는 저장 거부 시 캠페인을 만들지 않는다. 검사 생성 실패가 이미 커밋된 설정을 되돌리지는 않는 기존 정책을 유지한다. 실제 HTTP의 두 저장 경로에서 누락을 재현한 뒤 수정했으며, 허용·비활성화·긴급 중지·권한 거부·충돌·잘못된 입력과 기존 라우팅 검사를 포함한 race 52개 및 vet를 통과했다.

최종 기능 소스에서 전체 React 6,651개(474개 파일)와 기본 Node 63개를 통과했다. Node 선택 검사 16개는 기본 명령의 제외 항목이다. 첫 전체 React 실행에서 기존 검사 두 건이 5초 제한을 넘었으며 해당 파일과 새 기능 29개를 분리 검증한 뒤, 같은 소스와 제한으로 전체를 다시 통과했다. 시간 초과 원인은 확정하지 않았다.

Go 전체 검사 3,894개와 기존 제외 26개를 확인했다. 이후 추가한 저장 실패·트리거 변경·생성 시각 순서 검사는 최종 SQLite·PostgreSQL 레이스 검사 각 89개에 포함해 통과했다. 각 레이스 명령의 실제 브라우저 선택 검사 1개는 제외했으며, 별도 실제 Go·React·SQLite 업무 검사 3개에서 저장·감사·충돌·읽기 전용·외부 모델 미호출을 검증했다. 기존 실제 시뮬레이션 5개와 인증·OIDC 60개도 통과했다. 초기 인증 실행은 하니스 중단 뒤 완료 보고가 없어 성공으로 계산하지 않고, 격리한 최종 실행을 다시 검증했다.

새 초안과 기존 수정·순서 변경의 내장 브라우저 검사 21개를 재시도·제외 없이 통과했다. 밝은/어두운 테마와 1440/390px 시각 기준 4장을 확인하고 변경 없이 비교했으며 비교 결과로의 초점 이동과 저장 영역의 가시성을 확인했다. 계약 검토에서 오류 응답 설명을 보완한 뒤 실제 Go OpenAPI와 타입을 재생성하고 계약·정적 검사를 다시 수행했다. 이후 변경 후 보안 검사 분류 보완은 위의 별도 HTTP·race 검사로 확인했으며 화면 소스와 API 계약은 동일하다.

타입·린트·포맷·빌드·번들 예산·vet·API 표면·통합 SBOM을 검증했다. 초기 전송은 276,016바이트이고 SBOM은 Go 19개·npm 389개다. 원격 후보 CI·리뷰·메인 병합·순차 공개 릴리즈와 운영 Stable·전체 Phase 0–6 인수는 별도로 진행한다.
