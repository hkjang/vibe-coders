# 라우팅 규칙 순서 검토 (v0.86.91 후보)

`/app/routing/rules`의 **규칙 순서 변경**에서 전체 규칙의 처리 순서를 조정한다.
기존 `/admin`, 규칙 추가·개별 편집·삭제, 라우팅 활성 설정은 그대로 사용한다.
이 기능은 기존 라우팅 화면의 Preview에 포함하며 Stable 승격을 의미하지 않는다.

## 사용 방법

1. 순서 변경 창을 열어 서버가 반환한 현재 순서를 확인한다. 같은 우선순위의 규칙을
   모델명으로 다시 정렬하지 않는다.
2. 규칙을 끌어서 놓거나 **위로·아래로** 버튼으로 이동한다. 키보드 초점도 이동한
   규칙을 따라간다. 비활성 규칙을 포함한 전체 우선순위가 `1…N`으로 바뀌는 차이를 확인한다.
3. 변경 사유, 검증할 모델명, 요청 복잡도(0~100)를 입력하고 **순서 변경 비교**를 실행한다.
4. 변경 전후의 적용 규칙·모델·공급자와 비교 범위를 확인한 뒤 확인란을 선택한다.
5. **검토한 순서 저장**을 실행한다. 성공하면 우선순위와 감사 기록이 함께 저장되며
   목록에도 저장한 순서가 반영된다.

입력·순서·권한·표시 보호 기준이 바뀌면 이전 비교와 확인은 저장 근거로 사용할 수 없다.
입력 오류는 해당 필드에서 안내하고 초점을 이동한다. 저장하지 않은 입력은 창을 닫거나
화면을 이동할 때 확인한다. 로그인 사용자가 바뀌면 이전 작업과 늦은 응답을 폐기한다.

## 비교의 범위

비교는 실제 라우터와 같은 **복잡도 규칙 단계**의 첫 일치 규칙 평가를 사용한다.
비활성 규칙은 건너뛰고, 대상 모델이 비었거나 입력 모델과 같은 규칙은 모델을 유지하며
뒤 규칙을 평가하지 않는 기존 동작을 따른다. 실제 모델은 호출하지 않는다.

사용자·팀 선택, 정책, 학습, 공급자 상태, 장애 대체 경로와 최종 요청 전체의 결과를
예측하는 기능은 아니다. 해당 운영 판단에는 기존 라우팅 미리보기와 결정 이력을 함께 사용한다.
기존 규칙의 우선순위와 생성 시각이 모두 같으면 서버 순서가 확정되지 않으므로 경고한다.

## 저장과 충돌

`GET /admin/routing-rules?view=order`는 최대 1,000개 전체 규칙과 설정 내용의 SHA-256
검토 기준을 반환한다. 이 기준은 증가하는 버전 번호나 재시도 토큰이 아니다.
`PATCH /admin/routing-rules`는 전체 ID 순서·검토 기준·변경 사유를 받고, DB 쓰기 잠금 안에서
설정이 그대로인지 재확인한다. 일반 추가·개별 수정·삭제와 충돌하면 409로 거부한다.
부분 목록이나 중복 ID는 저장할 수 없다. 2~1,000개 범위의 전체 규칙만 순서 편집한다.

우선순위 변경과 실행자·변경 전후 우선순위·사유의 감사 기록은 하나의 트랜잭션으로 저장한다.
감사 기록 또는 COMMIT 실패 시 전체 변경을 롤백한다. 잠금 중에 외부 모델을 호출하거나
재시도하지 않으며, 설정된 변경 후 점검은 커밋 후에 실행한다. 현재 서버 캐시는 커밋 후
무효화하고 다른 서버는 기존 5초 캐시 주기를 유지한다.

저장 결과가 확인되지 않으면 이미 적용됐을 수 있으므로 같은 창에서 재전송하지 않는다.
창을 닫고 현재 목록과 감사 이력을 확인한다. 충돌이면 최신 목록으로 다시 검토한다.

## 호환성과 권한

순서 편집 버튼은 백엔드 v0.86.91 이상에서 제공한다. 조회와 비교는 기존 `routing:read`,
저장은 `routing:read`와 `routing:write`를 모두 요구한다. 화면의 읽기 전용 전환 설정도
적용한다. 기존 Legacy 읽기 전용 토큰의 POST 거부 규칙은 유지한다.
기존 API의 일반 GET 응답, 생성 및 개별 PATCH·DELETE 파서는 바꾸지 않는다.
새 비교 요청은 기존 `/admin/routing/preview`의 `rule_order`·`rule_revision` 입력으로 구분한다.
실제 쓰기 권한은 서버에서 다시 검증한다.

SQLite·PostgreSQL의 동시 변경, 전체 감사 트랜잭션과 롤백, 실제 HTTP 권한·캐시·입력을
검사했다. 전체 React 테스트 5,690개가 통과했으며 원본 순서, 검토 폐기, 응답 미확정
재전송 차단, 권한 회수, 사용자 전환과 입력 오류 초점을 포함한다.

외부 네트워크가 차단된 Go 내장 서버에서 관련 브라우저 43개, 두 테마·두 화면 폭의
시각 기준 8개와 axe를 확인했다. 별도의 실제 Go·OIDC 인증 통합 브라우저 38개에서는
규칙 비교·저장·새로고침을 실행하고 DB 우선순위·원본 필드·단일 감사 기록을 대조했다.
기존 `readonly_admin`은 라우팅 조회 권한도 없으므로 화면과 API에서 거부한다.
`routing:read`만 가진 사용자의 조회 허용·쓰기 거부는 별도 HTTP·컴포넌트 검사로 확인한다.
PR·실제 메인 CI, 정식 이미지와 공개 릴리즈 인수 및 운영 Stable 승격은 별도로 확정한다.
