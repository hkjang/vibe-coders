# 비밀키 교체 백업 검증

v0.86.135 후보는 기존 게이트웨이 바이너리에 `verify-secret-backup` 점검 명령을 추가한다. `/app/system/secrets`에서 한글 안내와 명령 복사를 제공하며, 교체 결과가 불명확하면 안내를 펼쳐 보여 준다. 기존 교체 API·권한·확인 절차·감사와 `/admin`은 유지한다.

## 점검 범위

DB를 변경하지 않고 공급자 API 키, MCP 인증값, Text2SQL 실행 연결 문자열, 비밀 관리자 설정, Keycloak SSO 클라이언트 비밀값을 검사한다. 기존 AES-GCM 복호화 구현을 사용한다. 관리자 설정의 JSON 문자열과 과거 원시 암호문 형식을 모두 지원하며 공개 설정은 제외한다. 결과에는 고정 저장소 이름과 성공·실패·빈 값 건수만 포함한다. 키, 암호문, 복호화한 원문, 항목 이름, DSN, 파일 경로와 내부 SQL 오류를 출력하지 않는다.

한 개의 읽기 전용 Serializable 트랜잭션에서 다섯 저장소를 검사한다. 스키마 누락, 연결·조회·롤백 실패, 취소는 부분 성공 보고서 없이 판정 불가로 끝난다. 전체 100만 행, 값 하나당 1MiB, 실행 30초를 제한한다. 큰 값과 NULL은 실패로 센다. 비어 있지 않은 암호문이 없으면 키 일치를 증명할 수 없다. 다른 키로 암호화된 값과 손상된 값은 구별할 수 없다.

## 백업 준비

1. 교체 전 DB와 당시 환경 파일을 함께 백업한다. SQLite는 백업 API로 만든 일관된 독립 파일이나 정상 종료 후 체크포인트된 파일을 사용한다. 실행 중인 DB 파일만 복사하지 않는다.
2. PostgreSQL은 덤프를 별도 데이터베이스로 복원하고 그 복원본의 연결을 사용한다. 운영 DB를 대상으로 삼지 않는다.
3. 검사 중 사본을 바꾸지 않는다. 키는 접근이 제한된 일반 파일에 정확한 바이트로 보관한다. 환경 파일 전체, 변수명, 새로 추가한 따옴표·줄바꿈을 넣지 않는다. 원래 키에 포함된 공백·줄바꿈은 보존된다.
4. 명령은 실행 환경의 `DB_DSN`, `DB_DRIVER`, `GATEWAY_SECRET`을 자동으로 사용하지 않는다. 백업과 키 파일을 모두 명시해야 한다.

```sh
gateway verify-secret-backup --sqlite /backup/gateway.db --key-file /run/secrets/gateway-key
```

SQLite 경로는 DSN이 아닌 파일 경로다. 읽기 전용·immutable 연결을 사용해 파일과 sidecar를 쓰지 않으며 비어 있지 않은 `-wal`, `-journal`은 거부한다. 해당 파일을 지워서 통과시키지 말고 정상적인 일관 백업을 만든다. 심볼릭 링크 DB와 일반 파일이 아닌 대상, 없는 파일도 거부한다.

PostgreSQL 복원본의 DSN을 안전한 환경 파일 또는 점검 환경의 `SECRET_BACKUP_POSTGRES_DSN`으로 전달한 뒤 실행한다. DSN을 명령 인자로 받지 않는다. 세션 기본값과 조회 트랜잭션 모두 읽기 전용으로 설정하며 마이그레이션, 게이트웨이 서버, 백그라운드 작업을 시작하지 않는다.

```sh
gateway verify-secret-backup --postgres --key-file /run/secrets/gateway-key
```

Distroless 이미지에도 같은 명령이 포함되므로 셸이나 Node.js가 필요 없다. SQLite 사본과 키를 각각 읽기 전용 마운트하고, 점검 사용자에게 읽기 권한을 부여한다. PostgreSQL 점검은 격리 복원본에 접근할 수 있는 네트워크를 명시적으로 사용한다.

## 결과 판정

| 종료 코드 | 결과 | 의미 |
| --- | --- | --- |
| 0 | `matched` | 암호문이 한 개 이상이며 모두 인증 복호화 성공 |
| 1 | `mismatch` | 한 개 이상 실패. 키 불일치·혼합 키·손상 가능 |
| 2 | 입력 오류 | 대상 선택·키 파일·인자 문제 |
| 3 | `no_secrets` 또는 검사 오류 | 암호문 없음, 스키마/연결 문제, 제한/시간 초과 등으로 판정 불가 |

코드 0은 공급자 자격증명이 유효하거나 실제 SSO 로그인이 성공한다는 뜻이 아니다. 실제 호출과 로그인도 별도로 확인한다. 데이터 파일 자체의 전체 정합성, 백업 최신성·완전성, 환경 파일 복원과 다중 서버 조정까지 보장하지 않는다.

교체 응답을 잃으면 트래픽 중단을 유지하고 현재 DB의 격리 사본을 이전 키와 새 키로 각각 검사한다. 일부 값만 성공하면 새 교체를 재실행하지 않는다. 복구가 필요하면 교체 전 DB와 그 키를 함께 복원한다. 이 도구는 검사만 수행하며 운영 복원과 교체를 실행하지 않는다.

## 검증과 남은 작업

실제 스키마와 저장 API로 다섯 종류를 넣고 회전·종료·백업 복원 뒤 이전/새 키 판정과 복원된 공급자 복호화를 검증한다. SQLite 파일/sidecar 불변, PostgreSQL 읽기 전용 강제, 손상·혼합·빈 값·스키마 누락·출력 비밀값 제외를 검사한다. 화면은 기존 교체 확인·미확정 결과 처리와 두 테마·모바일·키보드·접근성을 검증한다.

관련 React 1,391개(74개 파일), 내장 Go 브라우저 82개, 실제 인증 60개, 실제 Keycloak HTTPS 5개·사용자 DB 검증, 보고서·실패 산출물 29개를 통과했다. store/proxy/appui와 새 검사 패키지·gateway 명령의 Go 전체 테스트·vet, SQLite·PostgreSQL 17 race, 실제 저장 API의 회전·백업 복원, 운영 빌드 바이너리 명령, API 표면·OpenAPI·타입·린트·포맷·번들·SBOM을 검증했다. 두 테마·1440/390px 시각 기준 4장과 키보드·axe·문서 넘침을 확인했으며 초기 압축 번들은 264,691바이트다. 초기 모바일 영역 캡처의 제목 가림을 전체 화면 캡처로 보완하고 절차 번호를 표시했다. 검색 거부 표시의 상위 PR 보완도 포함한 상태에서 다시 검증했다. 실제 운영 백업을 검사하거나 복원하지 않았으며 전체 Phase 0–6 및 운영 Stable 인수, 자동 복원·다중 서버 조정은 잔여다.
