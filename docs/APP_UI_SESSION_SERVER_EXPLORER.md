# 세션 탐색기: 기간 전체 검색과 페이지 조회

v0.86.153은 세션 탐색기의 최근 200개 한도를 해소한다. `/app/observability/sessions`에서 기간(1~365일)과 세션 ID 일부로 검색하고, 25·50·100개 단위로 이동한다. 요약 카드의 세션·요청·오류·비용과 전체 토큰은 현재 권한으로 조회 가능한 검색 범위 전체의 합계다. 뒷페이지에 행이 없어도 전체 합계를 유지하고 처음으로 돌아갈 수 있다.

검색 대상은 세션 ID이며 대소문자를 구분하지 않는다. `%`, `_`, `!`도 일반 문자로 검색한다. 메시지 원문은 검색하지 않으며 주소에 넣지 않는다. 세션 ID 검색어는 주소에 보존하지만 서버 응답에는 되돌려주지 않는다. 마지막 메시지는 저장된 마스킹 텍스트에 추가 마스킹을 적용한 뒤 160자로 표시한다. 원문 조회 권한이 있어도 새 목록의 마스킹은 유지한다. 안전하게 표시할 수 없는 세션 ID는 상세 이동 없이 표시 불가로 남긴다. 기존 `/admin`에서는 기존의 최근 세션 및 메시지 검색 동작을 계속 사용할 수 있다.

기존 세션 비행기록 API와 상세 패널을 재사용한다. 상세 기록은 목록의 기간과 별개인 제한된 최근 요청이며 전체 세션 재현을 보장하지 않는다. 패널을 닫으면 실행 버튼으로 키보드 초점을 복원한다. 기간·검색·페이지 크기·위치는 주소와 로그인 복귀에서 보존한다. 조건 변경은 첫 페이지로 이동한다. 조회 중 상세 버튼을 막고, 오류를 빈 결과와 구분한다. 계정·팀·역할·원문 권한·인증 세션 변경 시 조회를 취소하고 이전 응답을 폐기한다. 401/403 뒤에는 명시적인 권한 확인 후 재조회한다.

`GET /admin/sessions/page`는 기존 요청·사용량·마스킹 메시지의 읽기 투영이다. `/admin/sessions` 및 `/admin/sessions/{session_id}/flight-recorder`를 변경하지 않는다. `/app`은 Backend v0.86.153 이상에서 새 목록을 사용하며 구버전은 기존 화면을 유지한다. 혼합 배포 중 새 API 실패 시 기존 목록으로 자동 대체하지 않는다. 인증과 팀 ID·이름 별칭 범위는 기존 서버 검사를 재사용한다. 응답은 `no-store`이고 중복·알 수 없는 쿼리, 잘못된 경계, 민감한 검색어를 거부한다. 페이지 위치는 1,000,000까지이며 한 요청에 100개, 쿼리 실행에 3초의 제한을 적용한다. 한도가 넘으면 검색 범위를 좁혀야 한다.

한 SQL 문장에서 팀 범위와 기간을 먼저 적용하고, 검색·그룹 집계·전체 합계·현재 페이지를 조회한다. 기간은 응답 `from` 이상 `to` 미만이다. UTC 나노초 마지막 활동 시각, 이진 세션 ID 내림차순으로 정렬한다. 페이지마다 최신 기록을 읽으므로 여러 페이지에 걸친 스냅샷은 보장하지 않는다. 여러 사용량 레코드의 토큰·비용을 합산하되 요청·오류 수가 중복해서 늘어나지 않게 집계한다. 요청 시각 인덱스를 재사용하고 스키마 마이그레이션은 추가하지 않는다.

전체 React 6,602개(468개 파일)·기본 Node 검사 57개를 통과했다. 외부 산출물 선택 검사 15개는 기본 명령의 제외 항목이다. 이후 페이지 버튼 초점·간격 보완 후 관련 React 502개(16개 파일), 최종 권한 안내 문구까지 반영한 내장 Go/CSP 브라우저 44개를 이미지 갱신·재시도·건너뜀·불안정 결과 없이 통과했다. 새 시각 기준 8장을 직접 확인했으며 기존 기준 이미지는 바꾸지 않았다. 전체 Go 테스트·vet·API 표면(424 서버/484 OpenAPI/371 React 연결) 통과 후 안정된 행 식별값의 관련 Go·PostgreSQL 17 race 5개도 통과했다. SQLite·PostgreSQL에서 2만 건의 선택적 기간 조회 자연 계획과 225세션 전체 검색·합계를 확인했다. 실제 Go OpenAPI 생성·타입·린트·포맷·빌드·번들·통합 SBOM(19 Go/389 npm)을 검증했다. 최종 초기 전송은 268,812바이트다. 브라우저 관리 API는 합성 응답이며 실제 SQL·권한·마스킹은 Go/DB 검사로 분리한다.

읽기 전용 Preview 개선이다. 전체 분산 추적 트리, 다른 목록의 전환, 운영 사용자 안정성 검증과 Phase 0–6 인수는 계속 진행한다. 선행 공개 릴리즈·후보 CI·현재 커밋 리뷰·메인 CI·공식 공개 산출물을 순서대로 확인한다. `.gitframe/`, `output/`, `seed.sql`은 커밋·푸시·빌드에서 제외한다.
