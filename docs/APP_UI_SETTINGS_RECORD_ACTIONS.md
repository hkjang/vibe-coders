# 설정 기록 변경 검토와 조회 보호

v0.86.151 개발 후보. `/app/system/settings?tab=tracking`과 `tab=errors`의 기존 조회·변경 API를 사용한다. 기존 `/admin` 화면과 추적 스니펫 설정 방식은 유지한다.

방문 추적 출처의 **허용** 버튼은 즉시 저장하지 않고 추가할 출처, 기존 추가 허용 목록, 변경 후 목록과 보안 정책 영향을 보여 준다. 차단 보고가 출처의 안전성을 보증하지 않음을 알린다. 허용은 추적을 자동으로 켜지 않으며 다음 페이지 로드부터 적용된다. 되돌리려면 런타임 추적 설정에서 추가 허용 출처를 편집한다. 표시한 비교는 현재 조회의 검토 자료이며 서버의 동시 변경 잠금이나 전체 영향 분석을 뜻하지 않는다.

시스템 오류는 최근 최대 100건을 보여 주며 요약도 조회 범위 기준이다. 전체 비우기는 표시 범위 밖과 처리 시점에 추가된 기록까지 삭제할 수 있다. 방문 추적 기록 비우기는 현재 서버 프로세스의 수집 기록을 삭제하며 허용 목록과 다른 서버의 기록을 변경하지 않는다. 두 작업 모두 확인창에서 범위를 안내한다.

확인창을 연 뒤 현재 기능의 읽기 전용 상태, 변경 권한, 조회 성공 여부와 조회 세대를 다시 확인한다. 새로고침되거나 실패한 기록으로 변경을 실행하지 않는다. 성공한 조회 한 번당 확인한 작업을 한 번만 전송하며, 실패·응답 불명확 시 상태를 다시 조회하고 새 확인창을 열어야 한다. 쓰기 요청의 인증 오류에 자동 재전송하지 않는다. 서버의 기존 권한 검증과 감사 기록을 그대로 사용한다.

계정·팀·역할·원문 권한·인증 세션이 바뀌거나 화면이 닫히면 이전 조회와 확인을 폐기한다. 조회에서 401/403을 받으면 이전 데이터를 지우고 명시적인 권한 재확인 전에는 조회를 반복하지 않는다. 일반 조회 실패와 빈 기록을 구분하며 이전 정상 데이터가 있으면 갱신 시각과 오류 안내를 함께 보여 준다. 시스템 오류 API 응답과 두 화면의 요청에는 캐시 재사용을 금지한다. 키보드로 확인창을 닫으면 그 창을 연 버튼으로 초점을 복원한다.

수정 전 즉시 허용·읽기 전용 전환 후 삭제 실행 세 건을 재현했다. 전체 React 6,569개(465개 파일)와 Node 기본 검사 57개를 통과했고 Node 외부 산출물 선택 검사 15개는 기본 명령에서 제외된다. 이후 브라우저에서 허용 확인창 닫기 초점 실패 다섯 건을 확인·수정하고, 최종 소스로 설정 관련 React 315개와 내장 Go·운영 CSP 기반 브라우저 109개를 통과했다. 최종 브라우저는 이미지 갱신·재시도·건너뜀·불안정 결과 없이 실행했다. 관리 API는 공개 합성 응답이며 실제 처리기·저장소는 전체 Go 회귀에서 별도로 검사한다. 신규 이미지 8장(두 테마, 1440/390px)을 직접 확인했고 기존 이미지는 변경하지 않았다.

전체 Go 테스트·vet·기존 관리자 회귀·API 표면(423 서버 경로/482 OpenAPI/369 React 연결), 실제 Go OpenAPI 생성, 린트·포맷·타입·빌드·번들 예산·통합 SBOM(19 Go/389 npm)을 검증했다. 최종 초기 전송 크기는 268,037바이트다. 최종 빌드 소스와 내장 브라우저 검사 소스의 지문이 일치하며 검사 후 변경은 문서·SBOM·라이선스뿐이다. 운영 역할별 인수·동시 변경과 다중 서버 검증·Stable 승격·전체 Phase 0–6 인수 및 정식 공개 릴리즈는 별도 후속 단계다.
