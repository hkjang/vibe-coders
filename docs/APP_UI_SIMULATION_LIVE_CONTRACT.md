# 라우팅·정책 미리보기의 실제 서버 검증

v0.86.155 후보는 요구사항 E2E-009·E2E-010의 브라우저→Go 연결을 검증한다. 기존 합성 HTTP 화면 검사와 Go HTTP 계약 검사는 유지한다. 업무 API를 추가하거나 `/admin`을 변경하지 않는다.

## 검증하는 사용자 흐름

| 흐름 | 실제 서버에서 확인하는 결과 |
| --- | --- |
| 라우팅 미리보기 | `/app/routing/rules/preview`에서 샘플 모델을 보내 저장된 우선순위의 첫 모델을 선택한다. 실행 후 입력을 바꾸면 기존 결과의 기준을 안내하고 자동 재실행하지 않는다. |
| 키 정책 오류 복구 | 존재하지 않는 키 ID의 404를 오류로 표시한다. 키 ID를 지우고 사용자가 다시 실행하면 정상 모델 선택을 표시한다. |
| 비용 기반 정책 추천 | 실제 과거 요청·비용 기록으로 추천을 생성한다. 최근 7일의 표본 8개 중 승인 예상 7개·허용 1개, 최근 24시간의 표본 6개 중 승인 예상 5개·허용 1개를 표시한다. 분석 창을 닫으면 실행 버튼으로 초점이 돌아온다. |
| 복원할 수 없는 조건 | 실제 비밀정보 탐지 메타데이터로 만든 추천을 계산한다. 과거 로그에서 비밀정보 포함 여부를 복원하지 못해 차단 예상이 0이어도 한계와 주의 문구를 표시한다. |
| 조회 계정 | 라우팅 화면 접근을 거부하고 정책 영향 실행 버튼을 잠근다. 직접 POST한 두 API도 401을 반환한다. |

기존 서비스의 권한을 그대로 검증한다. 정책 계산 POST는 저장을 하지 않지만 서버가 요구하는 `admin:write`를 우회하지 않는다. 비밀정보 탐지 메타데이터에는 비밀정보 원문을 넣지 않는다.

## 격리와 CI

`TestSimulationBrowserIntegration`은 기존 인증 테스트의 로그인·JWT·라우터·내장 자산·실제 SQLite를 재사용한다. 별도의 데이터베이스에 합성 사용자와 기록만 넣고 모델 응답기는 루프백으로 제한한다. 모의 관리자 API나 인증 우회 경로는 없다. 모델 호출은 0회여야 하며, 전후의 정책·규칙·라우팅 순서·설정·설정 이력·과거 평가 표본을 비교한다. 인증 사건 기록의 추가는 허용한다.

CI는 내장 프런트엔드를 준비한 뒤 다음 명령을 실행한다.

```sh
VIBE_SIMULATION_BROWSER_TEST=1 CGO_ENABLED=0 go test ./internal/proxy \
  -run '^TestSimulationBrowserIntegration$' -count=1 -timeout=3m
```

다섯 시나리오가 모두 통과해야 한다. 누락·건너뜀·재시도 결과는 통과로 처리하지 않는다. 스크린샷·트레이스·HAR·영상·인증 저장 상태를 보관하지 않고, 고정된 시나리오 ID·상태·소요 시간·실패 소스 줄번호만 `simulation-live-summary.json`으로 보관한다. 새 보고서 선택값으로 임의 파일 경로를 지정할 수 없다.

## 범위

실제 UI와 API의 연결, 저장하지 않는 계산 동작과 기존 권한 경계를 검증한다. 실 운영 데이터에서의 정책 정확도, 전체 과거 맥락 복원, 미래 안전성, 운영 Stable 승격을 뜻하지 않는다. 읽기 전용 계정에는 현재 서버에서 허용하지 않는 라우팅 권한을 추가하지 않는다. Phase 0–6 전체 인수는 계속 진행한다.

## 최종 빌드 확인

관련 React 1,129개·기본 Node 58개와 Go·생성 계약·린트·타입·빌드를 검증했다. 이후 상위 추적 필터의 보기 유지 수정을 반영한 v0.86.155 빌드에서 기존 시각 기준을 사용하는 내장 추적 브라우저 61개와 실제 Go 로그인·SSO·API 키 업무 60개, 계산 흐름 5개를 다시 통과했다. 외부 네트워크 없이 실행했으며 검사 중 소스 지문이 변하지 않았음을 확인했다. 최종 초기 전송 크기는 268,884바이트다.
