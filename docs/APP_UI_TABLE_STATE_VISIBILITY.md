# 공통 표의 상태 안내 가시성

v0.86.149 개발 후보는 가로로 긴 관리 표에서도 빈 상태 문구, 오류 안내와 `다시 시도` 버튼을 현재 보이는 표 너비 안에 표시한다. 열 설정이 있는 표와 기본 표에 함께 적용한다.

기존 표의 헤더·열 너비·스크롤·정렬·페이지·행 작업을 유지한다. 상태 안내는 기존 colspan 셀 안에 남으며, 현재 표 영역의 너비에 맞춰 줄바꿈하고 가로 스크롤을 따라 표시한다. 공통 상태 셀 컴포넌트가 ResizeObserver와 창 크기 변경으로 표 영역 너비를 추적한다. 요청 목록, SSO 역할 매핑, 콘솔 전환 설정, 변경 세트, 감사·인증·오류·추적 설정의 직접 작성한 표에도 같은 셀을 사용한다. 가로 스크롤 영역이 없던 설정 표에는 키보드로 접근 가능한 표 영역을 추가한다. 로딩은 기존 다섯 줄의 골격과 스크린리더 안내를 유지한다. 오류의 alert와 다시 시도 동작도 유지하며 별도의 API 호출이나 데이터 저장을 추가하지 않는다.

수정 전 일반 표·열 설정 표의 빈 상태·오류 상태 네 경우에서 안내가 가로 스크롤 밖으로 가려짐을 브라우저로 재현했다. 시작·중간·끝 스크롤, 화면 크기 변경, 로딩 전환, 키보드 재시도, 접근성과 시각 기준을 검증했다.

전체 React 6,527개(462개 파일)와 기본 Node 검사 57개를 통과했다. 외부 산출물 선택 검사 15개는 기본 Node 명령의 제외 항목이다. 운영 CSP를 적용한 내장 Go 서버와 합성 관리 API로 전체 브라우저·시각·키보드·접근성 회귀 1,991개를 통과했다. 이후 최종 소스 확인에서 포맷터가 오류 셀 클래스의 공백을 제거하는 문제를 발견했다. 전체 브라우저 검사는 공백이 유지된 이전 빌드를 사용했으므로 최종 소스 검증과 구분한다. 오류 셀의 회귀 실패를 재현하고 포맷에 안전한 표현으로 수정한 뒤 관련 React 38개, 전체 린트·포맷·타입 검사, 새 프로덕션 빌드·예산 검사와 내장 브라우저 24개를 다시 통과했다. 마지막 브라우저 검사는 빌드 시점 소스와 자산 해시를 확인했으며 이미지 갱신·재시도·건너뜀·불안정 결과 없이 통과했다. 신규 기준 이미지 8장과 바뀐 기존 이미지 14장을 직접 확인했다. 전체 Go 테스트·vet·API 표면(423 서버 경로/482 OpenAPI/369 React 연결), 실제 Go OpenAPI 생성 계약과 통합 SBOM 19 Go/389 npm 패키지를 검증했다. 최종 초기 전송 크기는 267,910바이트다.

기존 `/admin`·인증·권한·API 업무·데이터를 변경하지 않는다. 후보 CI·리뷰·순차 공개 릴리즈, 운영 Preview와 전체 Phase 0–6 인수는 별도 절차다.

전체 브라우저 회귀는 운영 CSP가 적용된 내장 Go 서버에서 실행한다. 접근성 검사 도구는 테스트 런너의 페이지 초기화 단계에 설치하며, CSP 허용 범위를 늘리지 않는다. 조회 조건 초기화 검사는 실제 조회가 관측될 때까지 기다린다. 공급자 표의 행 수 선택과 주소 이력 복원은 독립 사례로 검증하며 다수 행을 반복 조작하는 두 통합 사례의 실행 상한을 10초로 지정하고 기능 검증 조건은 유지한다. 브라우저 접근성과 번들 성능 예산은 별도 기준으로 검증한다.
