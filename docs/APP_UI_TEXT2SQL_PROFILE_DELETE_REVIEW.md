# Text2SQL 프로필 삭제 검토

v0.86.113 후보. `/app/text2sql?tab=runtime`에서 프로필 삭제 전에 현재 설정과 영향을 확인하고, 가상 모델 이름과 사유를 입력한다. 생성·수정 검토에 이어 삭제 작업도 같은 변경 버전과 감사 트랜잭션을 사용한다. 기존 `/admin`과 기존 DELETE API는 유지한다.

## 사용 흐름

1. 목록의 삭제 버튼을 누르면 현재 계정으로 검토용 프로필을 조회한다. 조회 실패·존재하지 않는 대상·구버전 검토 응답은 삭제 화면으로 진행하지 않는다.
2. 처음에는 영향 설명에 포커스를 둔다. 삭제는 DB에 저장된 프로필 설정만 제거한다. 가상 모델 호출이나 SQL 실행을 중지하지 않으며, 이후 요청은 기존 서버 기본 설정과 기본 모델 규칙을 따른다. 실행 DB의 테이블·데이터는 삭제하지 않는다.
3. 가상 모델 이름을 정확히 다시 입력하고 1~500자의 삭제 사유를 입력한다. 입력 오류는 가까이 표시하고 첫 오류로 포커스를 옮긴다. 오류가 표시된 입력을 고치면 오류 문구도 갱신한다.
4. 검토한 프로필 삭제 버튼으로 실행한다. 중복 제출과 자동 재시도를 막는다. 다른 변경이 확인되면 삭제하지 않고 사유를 보존한다.
5. 최신 상태로 다시 검토하면 이전·최신 설정을 나란히 표시하고 이름 재입력을 요구한다. 이미 없어진 프로필에는 삭제를 재전송하지 않는다. 결과가 불확실해도 먼저 존재 여부를 다시 확인한다.

쓰기 권한만 회수되면 입력을 보존하며 제출을 막는다. 인증·조회 권한 상실이나 계정 변경은 기존 초안을 제거한다. 늦은 응답은 다른 계정의 화면·알림을 변경하지 않는다. 사유 입력 후 닫을 때는 초안 폐기를 확인한다. 삭제 후 행이 사라지면 본문으로 포커스를 복귀시킨다.

## 서버 계약과 범위

`POST /admin/text2sql/profiles/reviewed-delete`는 `virtual_model`, `confirmation`, `expected_revision`, `reason` 네 필드만 받는다. 4KiB UTF-8 JSON, 필수·중복·null·알 수 없는 필드, 추가 쿼리를 검증한다. 이름은 정규화된 가상 모델과 정확히 같아야 하며 `absent` 버전으로 삭제할 수 없다. `admin:write`뿐 아니라 조회와 원문 권한도 서버에서 확인한다.

기존 검토 조회의 불투명 버전을 같은 짧은 SQLite/PostgreSQL 트랜잭션 안에서 다시 검사하고, 정확히 해당 행의 삭제와 `text2sql.profile.reviewed_delete` 감사 기록을 함께 커밋한다. 감사에는 검토한 이전 설정·버전·삭제 사유가 남는다. 현재 저장 경로의 재작성·삭제 후 재생성, 구버전의 필드 변경, 별도 DB 풀의 경쟁을 감지한다. 기존 난수 버전의 구버전 한계는 [생성·수정 검토](APP_UI_TEXT2SQL_PROFILE_REVIEW.md)와 같다.

존재하지 않거나 변경된 대상은 409, 검증 실패는 400, 메타데이터 실패는 내부 오류를 숨긴 503을 반환한다. 성공 응답의 대상·검토 버전도 UI에서 대조한다. 감사 삽입·커밋 실패 시 삭제를 취소하고 연결을 복구한다. 구버전 서버의 404·405 또는 계약 오류에서 기존 DELETE로 자동 전환하지 않는다.

검토 범위는 해당 프로필이며 연결·스키마·환경 설정까지 고정하지 않는다. 저장 또는 삭제 중 실제 DB 접속·모델 호출·SQL 실행은 하지 않는다. 전체 참조 영향 분석·전체 Critical 작업 인수·운영 Stable 승격을 뜻하지 않는다.

## 검증

SQLite와 격리 PostgreSQL 17에서 HTTP 권한·엄격한 입력 계약, 독립 DB 풀의 수정/삭제·삭제/삭제 경쟁, 같은 값 재작성·삭제 후 재생성, 감사 실패·커밋 실패와 연결 복구를 검증했다. 기존 프로필 생성·수정 검사도 함께 수행한다.

관련 React·공통 폼·대화상자·미저장 변경 검사 191개를 통과했다. 초기 내장 브라우저 69개가 통과한 뒤 이미지 검토에서 사유 오류 문구가 남는 현상을 발견해 입력 후 검증을 보완했다. 수정 후 브라우저 69개도 재시도·건너뜀 없이 통과했다. 삭제 화면 8장과 기존 시각 기준 28장, 모바일 충돌 처리, 사라진 행의 포커스 복귀, 키보드·axe 검사를 포함한다. 업무 브라우저 데이터는 모의 응답이며 실제 DB 계약은 별도 Go HTTP/Store 검사로 확인한다.

실제 Go 서버 OpenAPI와 생성 타입, 기존 관리자·App UI·API 경로·vet·타입·린트·포맷·프로덕션 빌드를 검증했다. 초기 압축 번들 262,092/350,000바이트, 화면 48개·선택 도구 6개가 예산 안이다. 통합 SBOM은 Go 19개·npm 389개이며 배포 기본값은 v0.86.113이다. 실제 인증·PR·메인 CI·정식 공개 검증은 별도 출고 게이트이며 운영 Keycloak·고객 DB 인수를 대신하지 않는다.

`.gitframe/`, `output/`, `seed.sql`은 커밋·푸시·배포 대상에서 제외한다. 전체 Phase 0–6는 계속 진행한다.
