# Text2SQL 프로필 변경 검토

v0.86.112 후보. `/app/text2sql?tab=runtime`에서 프로필을 추가하거나 수정할 때 변경 전후 설정과 적용 범위를 먼저 확인한다. 기존 `/admin`과 기존 프로필 POST·DELETE 동작은 유지한다.

- 수정 시작 시 현재 프로필을 조회하고 편집 기준을 고정한다. 백그라운드 목록·프로필 갱신은 초안이나 검토 내용을 덮어쓰지 않는다. 일시적 재조회 실패는 요청 ID와 함께 알리고 입력과 검토 기준을 유지한다. 인증·조회 권한이 사라지면 기존 초안을 제거한다. 같은 이름을 새로 추가하여 기존 프로필을 덮어쓰지 않으며 목록의 수정 작업을 안내한다.
- 가상 모델, 실행 모드, 업스트림·요약 모델, 스키마, 실행 DB와 프로필 적용 여부를 비교한다. 변경 사유를 입력하고 별도의 저장 버튼으로 확정한다. 프로필 미적용은 서버 기본 설정 사용이며 SQL 전체 중지가 아님을 표시한다.
- 충돌 시 입력을 유지하고 저장을 막는다. 최신 기준으로 다시 검토하면 다른 관리자의 변경과 현재 초안을 비교하고 다시 명시적으로 저장한다. 자동 저장 재시도는 하지 않는다. 저장 결과가 불확실하면 현재 상태를 다시 조회한다.
- 미저장 변경 확인, 저장 중 중복 제출 방지, 권한 회수 시 제출 차단, 계정·화면 전환 후 늦은 결과 폐기를 적용한다. 키보드 검토 위치와 수정 버튼으로의 포커스 복귀, 작은 화면의 비교 표와 고정 작업 영역을 제공한다.

## 서버와 호환성

기존 프로필 경로에 `GET ?view=review&virtual_model=...`와 `PUT` 검토 저장을 추가했다. 신규 UI는 지원 표시와 정확한 검토 버전을 확인하며 구버전 서버의 목록 응답을 검토 응답으로 간주하지 않는다. `PUT`을 모르는 구버전 서버에서는 405로 거부한다. 검토 없이 저장하는 기존 POST로 자동 전환하지 않는다.

검토 저장은 기존 `admin:write`에 더해 조회 및 민감 원문 권한을 확인한다. 본문은 16KiB, 필드는 512바이트, 변경 사유는 공백 제거 후 1~500자로 제한한다. 중복·누락·null·알 수 없는 필드와 쿼리를 거부하며 변경 없음은 400, 검토 기준 충돌은 409로 응답한다. 내부 DB 오류 원문은 응답하지 않는다.

프로필 테이블에 기존 행을 보존하는 `revision_nonce` 열을 추가한다. 현재 저장 경로의 난수 토큰과 필드·수정 시각으로 검토 버전을 만들며 토큰 원문은 응답하지 않는다. 짧은 SQLite/PostgreSQL 트랜잭션에서 기존·신규 저장자와 직렬화하고 검토 버전을 다시 검사한 뒤 프로필과 감사 기록을 함께 커밋한다. 감사 기록 또는 커밋 실패 시 함께 취소하며 연결도 복구한다. 별도 서버 프로세스의 현재 저장 경로에도 적용된다. 오래된 바이너리의 변경은 필드·시각으로 감지하며 구버전이 동일 필드와 동일 시각을 재현하는 경우까지 난수 토큰 보호가 확장되는 것은 아니다.

검토 대상은 해당 프로필이다. 연결·스키마·환경 변수의 버전까지 함께 고정하지 않으며 실제 DB 연결, 모델 호출, SQL 실행을 저장 과정에서 수행하지 않는다. 진행 중인 요청에 소급 적용하지 않는다. 기존 삭제 작업의 보호 강화와 전체 업무의 운영 Stable 인수는 별도 후속 범위다.

## 검증

관련 React 170개/15파일, SQLite·격리 PostgreSQL 17의 race 검사를 통과했다. 공통 대화상자·미저장 변경 보호, 지연 조회 중 쓰기 권한 회수, 일시적 재조회 실패와 401·403의 초안 처리도 확인했다. HTTP 검토 생성·수정, 변경 사유·응답 시각·버전, 현재/구버전 저장과의 충돌, 권한 조합, 중복·누락·초과 본문, 두 독립 DB 풀의 동시 생성·수정, 기존 행 마이그레이션, 감사 삽입·커밋 실패의 원자성과 연결 복구를 확인했다.

초기 브라우저 검사 63개 중 4개는 모바일의 숨겨진 헤더 선택기 조작과 CSP가 차단하는 검사 스크립트 주입 때문에 실패했다. 기존 페이지 초기화 방식으로 검사 도구를 주입하고 불필요한 헤더 조작을 제거했다. 후속 검사에서 마우스 위치에 따른 입력 테두리 차이 1개를 확인해 촬영 전 포인터 위치를 고정했다. 첫 입력 포커스 검사를 추가하자 로딩 대화상자의 포커스 복귀가 편집 화면의 포커스를 덮어쓰는 문제가 드러났으며, 화면 전환 시 포커스 인계를 수정했다. 후속 브라우저 63개는 재시도·건너뜀·불안정 통과 없이 통과했다. 프로필 폼·비교 화면 8장과 기존 시각 기준 20장을 검사했다. 작은 화면의 단어 줄바꿈과 체크 상자 정렬도 이미지로 확인했다.

실제 Go·OIDC·SQLite 인증 46개와 기존 관리자·Go App UI·OpenAPI·API 경로·vet 검사를 통과했다. 업무 UI 검사는 모의 응답이고 DB 검사는 격리 SQLite/PostgreSQL이다. 운영 Keycloak·고객 DB 검증을 대신하지 않는다.

타입 검사·린트·포맷·프로덕션 빌드·번들 예산, 실제 Go 서버와 OpenAPI 생성 계약 대조를 확인했다. 초기 압축 262,070/350,000바이트, 화면 48개·선택 도구 6개가 예산 안이다. 내장 에셋 191개의 해시·CSP·캐시·깊은 주소·404·405와 기존 관리자 제공을 확인했다. Go 19개·npm 389개 통합 SBOM과 배포 기본값을 v0.86.112로 맞췄다.

PR·실제 메인 CI·정식 릴리즈는 별도 출고 게이트다. 전체 Phase 0–6 및 운영 Stable 인수 완료를 뜻하지 않는다. `.gitframe/`, `output/`, `seed.sql`은 커밋과 배포 대상에서 제외한다.
