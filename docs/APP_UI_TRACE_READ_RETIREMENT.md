# 추적 목록·단계 기록의 조회 거부 처리 — v0.86.119 개발 후보

## 문제와 사용자 동작

추적 탐색기에서 목록 또는 단계 재조회가 401·403으로 거부된 뒤에도 이전 목록·단계 기록이
화면과 Query Cache에 남던 문제를 수정한다. 기존 인증·메뉴 허용 정보가 유지되는 조건으로
목록/단계 × 401/403 재현 검사 4건에서 이전 화면과 캐시의 잔존을 확인했다.

목록 조회가 거부되면 이전 행·집계·연결된 단계 기록을 정리하고 한글 안내에 초점을 옮긴다.
조회 조건과 선택 주소는 유지한다. 탭 활성화로 자동 복원하지 않고 **권한 확인 후 다시 조회**로
새 목록과 연결된 단계를 읽는다. 이전 행 선택·새로고침·단계 조회 콜백은 재사용하지 않는다.

단계 조회만 거부되면 허용된 목록과 요청 상세를 유지한다. 부모 목록을 새로 조회해도 단계는
거부 상태를 유지하며 명시 재시도로만 복구한다. 부모 조회가 미완료·실패한 동안 재시도는 잠긴다.
이 동작은 추적 탐색기와 요청 탐색기의 처리 단계 팝업에 공통 적용한다.
503 등 일시적 실패는 이전 데이터와 기존 선택·현재 부모 확인 동작을 유지한다.

진단은 오류 원문을 숨기고 문자·길이·비밀 접두사 검사를 통과한 요청 ID만 표시한다.
로그인 사용자·팀·세션 세대·비밀 접두사·원문 보기 권한이 달라지면 이전 조회 수명을 폐기한다.
기존 서버 API·인증·권한·데이터 투영·감사와 `/admin`은 유지한다. 새 비즈니스 API를 만들지 않는다.

## 검증 상태와 한계

- 최초 재현 검사에서 Query 검색의 기본 exact 옵션 때문에 대상 검색이 실패했다. 검색 조건을
  바로잡은 뒤 수정 전 목록/단계의 401·403 잔존 4건을 실제 컴포넌트와 Query Cache로 확인했다.
- 최초 회귀에서 비밀 접두사 변경 후 기존 테스트가 즉시 재조회 버튼을 찾던 1건이 실패했다.
  새 권한 수명의 목록·단계 조회를 기다린 뒤 마스킹과 오류 진단 보호를 확인하도록 보강했다.
- 관련 React 837개/42파일을 통과했다. 이전 queryFn·행·재조회 콜백 차단, 동일 데이터로 복구,
  부모 갱신 후 명시 단계 복구, 요청 상세 팝업 유지와 진단 값 제한을 포함한다.
- Go 내장 화면의 합성 HTTP 브라우저 99개와 고정 시각 기준 재검사 99개를 통과했다. 재시도·건너뜀·
  불안정 통과는 없다. 별도의 실제 Go/OIDC/SQLite 인증 46개도 통과했다.
- 모바일 390px·데스크톱 1440px와 밝은·어두운 테마의 안내 4장을 직접 확인했다. 키보드 복구·
  초점·axe와 기존 요청/세션 회귀를 포함하며 소스와 내장 에셋 해시를 검사 전후 확인했다.
- 타입·린트·포맷·실제 Go OpenAPI 계약, 통합 SBOM(Go 19개·NPM 389개), 단계 API 권한·조회 경계와
  기존 관리자·내장 UI 전체 검사·vet를 통과했다. 초기 압축 번들은 262,423바이트이며 의존성 변경은 없다.
- 합성 HTTP 검사는 실제 서버의 권한 배정이나 팀 범위 증거를 대신하지 않는다. Query Cache 정리는
  이미 내보낸 파일과 외부 코드가 참조하는 모든 JavaScript 객체의 물리적 삭제를 의미하지 않는다.
- 후보의 원격 CI·리뷰, 실제 메인과 정식 배포 검증, 운영 Preview 인수는 별도다. 전체 Phase 0–6는 계속 진행한다.

## 통합 출고

v0.86.118 세션 조회 거부 보완(PR #194)과 함께 v0.86.119로 출고한다. 각 후보의 정확한 커밋에 대한
리뷰·전체 CI·골든 검사를 확인하고 v0.86.117 공개 검증 이후 차례로 병합한다. 최종 메인 CI와
정식 이미지·공개 파일 검증은 v0.86.119에서 수행하며 v0.86.118 별도 태그·릴리즈는 만들지 않는다.
