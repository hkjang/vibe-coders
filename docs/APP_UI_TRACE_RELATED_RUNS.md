# 추적 연관 실행 조회

v0.86.152 후보. `/app/observability/traces`의 유효한 추적 ID에서 워크플로·앱 실행을 조회한다. 요청 목록의 기간·모델·상태 필터와 별개로 같은 추적 ID 전체 기간의 메타데이터를 보여 준다. 전체 분산 추적 Span Tree나 실행 간 부모·자식 인과관계를 추정하지 않는다.

기존 `/admin/traces/{trace_id}` 내보내기와 `/admin` 화면을 유지한다. 신규 읽기 하위 경로 `/admin/traces/{trace_id}/runs`는 기존 실행 기록의 메타데이터 투영이며 업무 실행 로직을 복제하지 않는다. 구버전 서버는 중첩 경로를 거부하므로 새 쿼리 옵션을 무시하고 기존 원문 응답을 반환할 수 없다. 화면은 부트스트랩의 Backend v0.86.152 이상에서만 패널을 제공하며, 혼합 배포 중 실패 시 원문 API로 대체하지 않는다.

서버는 기존 admin:read와 팀 ID·팀 이름 별칭 범위를 count/limit 이전에 적용한다. 한 SQL 문장에서 전체 수와 현재 페이지를 조회하고, 최대 100개·offset 1,000,000·3초 조회 제한을 적용한다. 페이지마다 최신 기록을 읽으므로 여러 페이지 간 스냅샷을 보장하지 않는다. UTC 나노초 기록 시각과 ID 내림차순이다. 실행 기록에 저장된 시각을 표시한다.

프롬프트·입출력·오류 원문·사용자·팀·입력 해시·단계 정의를 응답하지 않는다. 표시할 수 없는 이름/ID와 유효하지 않은 지표는 null로 남긴다. 불투명 행 키는 식별값을 노출하지 않고 표 렌더링에만 사용한다. 정의 링크는 현재 정의를 열며 당시 실행 정의 스냅샷이 아니다. 본인 실행 영수증 여부와 대상 기능 권한을 모두 확인한 뒤 링크를 표시하고, 대상 API가 다시 권한을 검사한다.

API 캐시는 no-store, React Query 데이터는 화면 조회 수명에 한정한다. 계정·팀·역할·원문 권한·세션 전환 시 취소/정리하고 늦은 응답을 폐기한다. 401/403은 데이터와 링크를 닫으며 명시적인 권한 확인 후 재조회한다. 조회 오류를 빈 결과와 구분하고 원문 서버 오류를 출력하지 않는다. 종류·페이지 크기·위치를 URL에 보존하고 선택 변경 시 초점을 유지한다.

부분 인덱스는 trace_id 1~1024바이트만 포함해 오래된 대형 식별값 때문에 PostgreSQL 마이그레이션이 실패하지 않게 한다. PostgreSQL에서는 CONCURRENTLY로 생성한다. 조회·업그레이드·자연 쿼리 계획을 SQLite와 PostgreSQL 17로 검증했다.

검증: 전체 React 6,585개(466파일)와 Node 57개를 통과했다. 기본 Node 명령의 외부 산출물 선택 검사 15개는 제외 항목이다. 이후 공통 URL 정리에서 연관 실행 페이지 조건이 사라지는 결함을 회귀 테스트로 재현·수정하고, 추적·보안·로그인 복귀 관련 React 588개(21파일)를 다시 통과했다. API 경로 바인딩의 타입 오류와 브라우저 합성 응답 형식 오류도 검증 과정에서 수정했다.

최종 내장 Go·운영 CSP 브라우저 62개를 기준 이미지 갱신·재시도·건너뜀·불안정 결과 없이 통과했다. 관리 API는 공개 합성 응답이며 실제 서버 RBAC와 DB 정합성 검증을 대신하지 않는다. 실제 내장 에셋 195개의 해시·MIME·캐시·CSP·직접 주소·에셋 404·POST 405·기존 /admin 200을 네트워크 없는 컨테이너에서 확인했다. 1440/390px·두 테마·페이지 결과/빈 상태의 새 시각 기준 8장을 직접 확인했고 기존 기준 이미지는 변경하지 않았다. 시각 캡처 높이는 1600px이며 좁은 너비와 가로 스크롤, 키보드·axe 검사를 포함한다.

전체 Go 테스트·vet·API 표면(423 서버 경로/483 OpenAPI/370 React 연결)과 실제 Go OpenAPI·생성 타입을 검증했다. 그 뒤 잘못 인코딩된 쿼리·1024바이트 초과 ID의 명시적 400 처리를 추가하고 관련 Go 검사를 다시 통과했다. PostgreSQL 17 race 7개, SQLite 자연 계획과 대형 기존 식별값 업그레이드 검증은 SQL 구현을 검증하며, 마지막 HTTP 쿼리 검증 보완 이전에 실행했다. 최종 린트·포맷·타입·빌드·번들 검사를 통과했다. 초기 전송은 268,463바이트이고 통합 SBOM은 19 Go/389 npm 패키지다. 최종 빌드와 브라우저 사이 소스 변화는 의도적으로 생성한 새 기준 이미지뿐이며, 이후 변경은 SBOM·라이선스·문서다.

이 단계는 읽기 전용 Preview 보강이며 운영 Stable 승격이나 전체 Phase 0–6 인수를 뜻하지 않는다. 선행 공개 릴리즈·후보 CI/리뷰·메인 CI·공식 공개 산출물 검증은 별도로 수행한다. `.gitframe/`, `output/`, `seed.sql`은 제외한다.

### PostgreSQL 문자열·인덱스 호환성 보완

추적 ID·실행 메타데이터의 길이는 PostgreSQL에서 `octet_length`로 측정한다. 문자열을 BYTEA로 해석하지 않으므로 리터럴 역슬래시·Windows 경로가 포함된 추적 ID와 이름도 삽입·조회할 수 있다. 부분 인덱스와 조회 조건은 동일한 바이트 범위를 사용한다. 기존 후보 빌드가 만든 두 추적 인덱스의 BYTEA 조건도 시작 마이그레이션 잠금 안에서 감지하고 동시 인덱스 재생성으로 교체한다. 다른 유효 인덱스는 유지한다.

실제 PostgreSQL 17에서 기존 코드의 삽입 실패를 재현했다. 수정 후 워크플로·앱의 리터럴 문자열, 기존 데이터에서의 인덱스 생성, 이전 후보 인덱스 교체, 반복·동시 마이그레이션, 자연 조회 계획과 HTTP 검사를 포함한 race 12개를 통과했다. SQLite 관련 race와 Go vet도 통과했다. 이 변경은 추적 메타데이터에 한정하며 다른 기존 메타데이터 조회의 바이트 계산은 별도 점검 범위다.
