# 요청 단계 탐색

v0.86.114 개발 후보. 기존 요청·추적 조회 API와 권한을 재사용하는 읽기 전용 개선이다.

## 사용 방법

- 추적 탐색기에서 요청을 선택하면 조회된 하위 단계의 오류·정상·건너뜀·확인 불가 건수를 본다.
- 단계 유형과 상태를 함께 선택해 표를 좁힌다. 조건에 맞는 단계가 없으면 초기화 안내를 표시한다.
- 부모 요청은 항상 표시한다. 시간축은 필터 적용 전 전체 조회 결과를 기준으로 계산하므로 필터를 바꿔도 막대의 위치·길이는 동일하다.
- 추적 화면은 `flow_kind`·`flow_status` 열거값만 주소에 추가한다. 요청 선택과 목록 조건을 유지하고 새로고침·뒤로 가기에서 복원한다.
- 요청 탐색기의 상세 팝업에서는 팝업 내부 상태만 사용한다. 목록 주소를 바꾸지 않으며 팝업을 닫거나 다른 요청을 열면 초기화된다.
- 필터만 변경할 때 목록·단계 API를 다시 호출하지 않는다. 단계 이름이나 원문을 주소 또는 브라우저 저장소에 추가하지 않는다.

## 범위

요약은 이번 응답의 하위 단계만 센다. 서버의 후보 상한·표시 생략 안내와 단계 이름의 표시 보호를 유지한다.
현재 계약은 부모 요청 한 건과 직접 하위 단계 최대 200건이다. 전체 분산 추적, 실제 시작·종료·동시 실행,
미기록 도구 소요 시간을 추정하지 않는다. 전체 Phase 0–6와 운영 Stable 인수를 완료한 것은 아니다.

## 검증

관련 React 요청·추적·응답 계약과 URL 보안·로그인/SSO 복귀 검사 623개를 통과했다. 필터 교차 적용·초기화·주소 복원·시간축 유지·부분 조회와
비공개 이름 표시, 기존 권한 회수·계정 전환·지연 응답 보호를 포함한다. 첫 검사에서 이전 탭 순서와
합성 입력·접근 가능한 이름을 기대한 테스트가 실패했으며 새 UI의 실제 동작에 맞춰 보완했다.
첫 내장 브라우저 검사에서는 모의 인증 미연결·엄격한 라벨 탐색·CSP에 차단된 접근성 검사 주입을
보완했다. 이후 공통 URL 검증기가 새 필터를 지우면서 화면과 포커스를 초기화하는 제품 문제를
확인하여 추적 경로의 허용 키와 유한 열거값 검증을 추가했다. 중복·알 수 없는 값은 제거하고
로그인/SSO·초기 부트스트랩에서도 유효한 필터를 유지한다.
수정된 Go 내장 브라우저 69개가 재시도 없이 통과했다. 밝은·어두운 테마와 1440/390px의
필터·표 시각 기준 8장을 확인했고 axe·키보드·팝업 초기화·로그인 복귀·추가 API 호출 없음도 검증했다.
업무 브라우저는 모의 API 응답을 사용하며 실제 Go/OIDC 인증 게이트와 구분한다.
Go 기존 관리자·요청 단계·명세·SBOM 버전·App UI 검사를 통과했다. 초기 압축 번들은 262,386바이트로
350,000바이트 예산 이내이며 라우트 48개·선택 도구 6개도 통과했다. 원격 CI·메인·정식 출고는 별도 진행한다.
