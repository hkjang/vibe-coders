# 분기 워크플로 편집과 검토

v0.86.160 개발 후보. `/app/agents/workflows`에서 단계와 조건별 연결을 편집하고, 저장·게시 전 현재 정의를 검토한다. 운영 Stable이나 Phase 0–6 전체 완료를 뜻하지 않는다. `/admin`의 순차 편집과 기존 조회·인증·팀 제한을 유지한다.

## 사용 흐름

- `새 분기 워크플로`는 중지 상태로 시작한다. 기존 순차 정의는 `분기 편집기로 전환`으로 연다.
- 시작 단계, 단계 종류와 참조, 조건의 참·거짓 연결, 마지막 `종료`를 지정한다. 그림에서 클릭·Enter·Space로 단계를 선택하거나 선택 상자로 모든 연결을 편집할 수 있다.
- 조건은 현재 텍스트 입력의 유무, 정확한 일치, 포함 여부를 검사한다. 대소문자를 구분하며 입력 유무만 양끝 공백을 제거한다. 스크립트나 표현식을 실행하지 않는다.
- `변경 내용 검토`에서 상태·팀과 전체 전후 정의를 확인하고 사유를 입력한다. 초안이나 권한을 바꾸면 이전 검토로 저장할 수 없다. 동시 변경·삭제는 충돌로 거부한다.
- 사용 상태로 저장한 정의는 다음 실행부터 적용된다. 이미 시작한 실행은 시작할 때 읽은 정의를 사용한다. `게시`는 검토한 현재 정의를 버전 이력에 남기고 사용 상태로 바꾼다. 실행을 특정 게시 버전에 고정하는 기능은 아니다.
- 게시 이력의 `정의 보기`로 당시 순차·분기 정의를 조회한다. 실행 영수증은 실행 순서, 실제 단계 ID, 원래 정의 위치와 조건에서 선택한 분기를 구분한다.
- 저장·게시 응답을 확인하지 못하면 자동으로 반복 전송하지 않는다. 창을 닫고 최신 정의·버전·감사 기록을 확인한다.

## 실행 범위와 전환 차이

버전 1은 최대 128단계의 비순환 단일 경로 그래프다. 참·거짓 중 한 경로를 고르며 병렬 실행하지 않는다. 도달할 수 없는 단계, 중복 식별자, 누락 연결, 순환을 저장 전에 거부한다. 승인 대기는 실행을 멈추며 재개 기능이 없으므로 종료에만 연결할 수 있다. `입력 전달`은 변환 프로그램 없이 현재 입력을 그대로 전달한다. 자연어 SQL 단계는 기존 미리보기 모델을 사용하며 실행 DB를 직접 호출하지 않는다.

채팅·스킬은 기존 채팅 처리 경로, MCP 도구는 기존 `/mcp` 인증·정책·거버넌스·업스트림 경로를 사용한다. MCP 단계에는 전체 도구 이름과 JSON 객체 입력이 필요하며, 텍스트 결과를 다음 단계로 전달한다. 자체 `/mcp/gateway` 도구를 분기 단계에서 재귀 호출하지 않는다. 채팅·스킬 출력 토큰 제한과 단계 시간 제한을 적용하며 MCP 허용 도구는 전체 이름을 정확히 비교한다. 단계별 비용 상한·테이블 제한·채팅 도구 제한은 강제되지 않으므로 분기 모드에서는 설정을 거부한다. 서비스 전체 예산·정책의 보장 범위를 늘린 것으로 해석하지 않는다.

HTTP로 실행한 분기 워크플로는 로그인 계정의 사용자·팀·허용 범위를 내부 모델·MCP 호출에 전달한다. 각 실제 호출 직전에 세션 유효성과 해당 범위를 다시 확인한다. MCP 도구는 `mcp:use`, 모델 호출은 `chat:completion`이 필요하다. MCP 진입점에서 시작한 실행은 기존 API 키·OAuth 범위를 유지한다. 직접 `/mcp`나 모델 API에서 로그인 토큰을 허용하도록 인증 규칙을 넓히지 않는다. 단계 사이에 세션이 폐기되면 다음 호출은 거부하며 이미 진행 중인 호출의 강제 취소를 뜻하지 않는다.

기존 순차 정의의 MCP 단계는 종전대로 건너뛴다. 분기 전환은 실제 도구 호출, 조건 거짓 시 종료, 적용되지 않던 제한 제거라는 의미 변경을 수반하므로 전환안을 중지 상태로 만들고 전후 정의를 보여준다. 순차 편집기는 알 수 없는 필드를 조용히 버리지 않고 저장을 거부한다. 기존 순차 화면에서 분기 정의를 덮어써 연결을 지울 수 없다.

## API와 데이터

- `GET /admin/workflows?view=review&id=...`: 전체 정의와 비교 리비전. 정확히 두 매개변수, 없으면 404.
- `POST /admin/workflows?review=graph`: `{workflow, expected_revision, reason}`. 빈 리비전은 신규 생성만 허용한다. UTF-8 JSON 256KiB, 중복·알 수 없는·null 필드를 거부한다.
- `POST /admin/workflows/{id}/publish`: 분기 정의는 `{expected_revision, note}`가 필수다. 사유 1–500자, 본문 8KiB, 조회·변경 권한이 필요하다. 순차 정의는 기존 note 요청을 유지한다.

리비전은 전체 저장 정의와 시각의 비교용 해시다. 중복 실행 키가 아니다. SQLite 쓰기 잠금 또는 PostgreSQL 정의 테이블 쓰기 잠금 안에서 현재 값과 비교한다. 저장·감사, 또는 버전 할당·스냅샷·활성화·감사를 각각 한 트랜잭션으로 커밋한다. 잠금 안에서 모델·도구를 호출하지 않는다.

기존 테이블에 선택적 흐름과 단계 실행 메타데이터 열을 추가한다. 기존 정의에는 flow를 만들지 않으며 기존 영수증에는 새 필드를 강제로 채우지 않는다. 실제 실행 결과와 영수증 기록은 기존 best-effort 정책이므로 기록 저장 실패까지 성공으로 보장하는 기능은 아니다. 실행 원문은 새 영수증 필드에 추가하지 않는다.

## 검증 상태

- Go 전체 개발 회귀 3,963개 통과(선택 실행 25개 제외), SQLite 분기·게시 race 60개, PostgreSQL 17 race 67개와 인증된 HTTP/MCP 진입점 5개를 통과했다. 동시 수정·게시, 감사 실패 롤백, 기존 데이터 업그레이드·재마이그레이션, 실제 단계별 영수증과 사용자·팀 제한을 포함한다. 전체 Go 검사 후 추가한 실제 브라우저 진입점은 별도로 실행했다.
- 전체 React 6,670개(478개 파일)와 최종 간격 조정 후 관련 React 89개, 실제 Go/SQLite 브라우저 4개, 기존 Go/OIDC 인증 브라우저 60개를 통과했다. 실제 브라우저에서 수정·게시·버전 저장·동시 변경 거부·조회 계정 쓰기 거부를 검사하고 DB 정의·버전·감사 기록과 모델 호출 0회를 확인했다.
- 내장 Go 서버의 합성 브라우저 39개를 재시도·제외 없이 통과했다. 4개 신규 분기 편집 화면과 의도적인 ‘변환 → 입력 전달’ 명칭 변경에 따른 기존 영수증 2개 시각 기준을 검토했다. 밝은/어두운 테마, 1440/390px, 키보드, 초점 복원, axe와 그림의 실제 크기를 검사한다.
- ESLint·포맷·타입·실제 Go OpenAPI·생성 타입·API 표면·빌드·Go vet를 확인했다. Node 검사 64개 통과, 외부 브라우저 산출물 선택 검사 16개 제외다. 초기 전송은 276,858바이트이며 Go 19개·npm 389개의 통합 SBOM과 라이선스 목록을 생성했다.

개발 중 전체 React 검사는 소스 변경과 겹쳐 결과를 폐기한 뒤 고정된 소스로 다시 실행해 6,670개를 통과했다. 그 이후 변경은 한글 분기 설명의 열 간격과 이를 확인하는 브라우저 검사뿐이며, 최종 코드에서 관련 React 89개·합성 브라우저 39개·실제 Go 브라우저 4개와 빌드·정적 검사를 다시 통과했다. 초기 시각 검사에서 발견한 그림 축소와 선택 단계 스타일 오류는 수정했고, 이미지 기준을 승인하기 전에 다시 확인했다. 실제 인증 검사 중 호스트 실행 연결은 종료됐으나 동일 컨테이너의 정상 종료 기록과 새로운 60개 결과, 소스 해시를 확인했다. 중복 인증 실행으로 대체하지 않았다.

후보 커밋 CI·리뷰·메인·공식 릴리즈 및 운영 사용자 Preview 검증은 별도 단계다. 운영 Stable, 장기 안정성, 병렬 실행·승인 재개·게시 버전 고정·비용 상한을 완료한 것으로 해석하지 않는다.

## HTTP 실행 인증 보완 검증

PR 검토에서 로그인 토큰으로 분기 워크플로를 실행하면 MCP 인증에서 거부되는 문제를 실제 로그인·HTTP·로컬 도구 경로로 재현했다. 관련 모델 단계도 같은 실패를 별도로 재현한 뒤, HTTP 분기 실행에서만 사용할 수 있는 내부 주체 전달로 수정했다. 기존 MCP 정책·도구 거버넌스와 모델 처리 경로를 재사용한다.

최종 실제 HTTP 시나리오 15개, 관련 Go race 83개와 vet를 통과했다. 정상 모델·도구 응답, MCP OAuth 켜짐·꺼짐, 부족한 범위·팀 제한·도구 정책·거버넌스·단계 허용 목록, 만료·잘못된 토큰·폐기한 세션, 첫 호출 후 세션 폐기 시 두 번째 호출 차단, 출력 토큰 상한과 사용자별 실행 기록을 확인했다. 일반 race에서 선택 브라우저 검사 한 개는 제외했으며 실제 인증 브라우저 60개와 워크플로 저장·게시 브라우저 4개는 별도로 실행해 통과했다. 최종 소스 해시와 각 명령의 정상 종료를 확인했다.

제품 변경은 Go 두 파일이다. UI·API 계약·의존성은 변경하지 않아 앞선 React·시각·번들 근거와 이 후속 인증 검증 범위를 구분한다. 첫 실패·중간 검사와 순차 정의를 만들 때 그래프 ID를 남긴 테스트 fixture 오류는 보존했으며, 최종 검증 수에 실패를 포함하지 않는다.
