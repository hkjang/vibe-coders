# 업무 앱 목록과 독립 상세 — v0.86.93 후보

`/app/agents/apps`는 전체 앱 정의를 내려받지 않고 필요한 페이지의 메타데이터를 조회한다.
검색·정렬은 전체 목록에 적용한다. 한 번에 10·25·50개를 표시하고 최대 세 가지 정렬을
선택한다. 제목·설명·책임자·허용 팀·역할·ID를 검색하며 한글과 `%`, `_`를 그대로 찾는다.
주소에 검색·상태·정렬·페이지·크기를 보존하므로 새로고침과 상세 닫기 후에도 복원한다.

전체 앱·활성·공개 범위 미지정 수치는 필터와 관계없는 전체 요약이다. 공개 범위 미지정은
기존과 같이 허용 팀과 역할이 모두 빈 문자열인 앱이다. 실행 이력에는 현재 앱 이름을
표시하고 삭제된 앱의 이력은 ID로 유지한다. 실행 이력의 본인 계정 범위는 변경하지 않는다.

목록의 이름 링크를 키보드로 열거나 정확한 앱 ID 주소를 사용할 수 있다. 현재 페이지에
없는 앱도 별도로 조회하고 목록 장애가 상세 조회를 막지 않는다. 상세의 로딩·실패·없음·
잘못된 주소를 구분하며 실패 시 요청 ID와 재시도, 기존 관리자 이동을 제공한다.

현재 페이지 CSV는 표시 중인 메타데이터만 내보낸다. 구성 요소 정의나 실행 원문은 목록
캐시·CSV에 포함하지 않는다. CSV 수식 주입 방지와 비밀값 검색·주소 보호를 적용한다.
기존 생성·수정·검증·발행·지원 중단·삭제·권한 관리 절차를 유지한다. 저장 뒤에는 현재
계정의 목록과 상세를 갱신한다. 권한 편집 중인 초안은 조회 갱신으로 다른 앱에 연결되지 않는다.

## 기존 API와 호환성

- `GET /admin/apps`의 기본 전체 목록과 모든 변경 경로는 유지한다.
- `view=page`는 1~100개 메타데이터와 검색 결과 수·전체 요약을 한 SQL 문장으로 조회한다.
- `view=detail&id=…`는 정확한 기존 정의 또는 `null`을 반환한다. ID의 공백·예약 문자를 보존한다.
- 두 조회는 `no-store`를 사용하고 중복·잘못 인코딩된 조회 조건을 거부한다.
- 실행용 팀·역할 제한을 관리자 목록 필터로 사용하지 않는다. 기존 관리자 읽기 권한을 유지한다.
- 권한 거부·계정 변경·화면 종료 시 해당 계정의 목록·상세 캐시를 취소하고 제거한다.

SQLite·PostgreSQL의 검색·정렬·경계·요약·기존 목록 일치와 HTTP 권한을 검증했다.
PostgreSQL 관련 레이스 검사, 전체 Go 테스트·vet·API 표면 감사가 통과했다.
React 5,719개와 보조 도구 54개 검사가 통과했다. 보조 도구의 선택적 환경 검사 15개는
이번 로컬 실행에서 건너뛰었다. 계정 경계·권한 초안·특수 ID의 버전/상세 캐시 충돌도 검사했다.

운영 CSP와 Go 내장 자산을 사용하는 브라우저 61개가 재시도·건너뛰기 없이 통과했다.
업무 API는 합성 응답으로 화면 흐름을 검증하고 실제 HTTP/DB 계약은 위 서버 검사로 검증한다.
두 테마·두 화면 폭의 시각 기준 4개와 axe·가로 넘침, 공급자 모바일 회귀를 확인했다.
린트·포맷·TypeScript·OpenAPI 생성 계약과 통합 SBOM을 검증했으며 초기 압축 번들은
254,990/350,000바이트다. 화면 47개와 선택 도구 5개도 예산을 통과했다.
최종 원격 CI·정식 출고 및 운영 Stable 승격은 별도 검증 대상으로 남는다.

## 함께 보완한 공급자 초점 이동

공급자 상세를 닫은 직후 검색 입력이나 다른 버튼을 선택하면 늦게 실행되는 초점 복원이
새 입력을 방해할 수 있었다. 이미 선택한 조작 요소의 초점을 유지하고, 본문·목록 제목에
초점이 남은 경우에는 현재 목록의 원래 링크로 복원한다. 자동 초점 이동과 새 선택을
분리해 검사하며 기존 비공개 공급자 이름 보호와 검색 조건을 유지한다.
