# Probe CSV 편집과 가져오기

내보내기는 UTF-8 BOM이 있는 CSV입니다. 기존 13개 열 뒤에 `vibe_probe_csv_format` 열이 붙으며, 모든 데이터 행의 값은 `probe-v1`입니다. 이 열과 헤더를 유지하세요. 열 순서는 바꿀 수 있습니다.

일반 프롬프트는 셀에서 바로 편집할 수 있습니다. 수식으로 해석될 수 있는 값, 맨 앞의 작은따옴표, 공백·제어 문자, 예약된 접두사가 포함된 일부 텍스트는 `vibe-text-v1:` 뒤의 JSON 문자열로 표시합니다. 예를 들어 실제 프롬프트 `=1+1`은 셀 값 `vibe-text-v1:"=1+1"`로 표시됩니다. `\r`, `\n`, `\t`는 각각 원래의 CR, LF, 탭으로 복원됩니다. 인코딩된 셀을 편집할 때에는 JSON 문자열 안의 내용을 바꾸세요. 일반 텍스트로 셀 전체를 교체해도 되며, 일반 셀의 작은따옴표는 그대로 저장됩니다. 실제 데이터가 예약 접두사로 시작하면 JSON 문자열 안에 넣어 명시적으로 표현합니다.

`target_types`와 `risk_tags`는 보통 `provider|model`처럼 `|`로 구분합니다. 항목 자체에 `|`, 빈 항목 또는 양끝 공백이 있으면 `vibe-list-v1:["literal|pipe",""," leading "]`처럼 JSON 문자열 배열로 표시하여 항목을 보존합니다.

표시된 형식에서는 팩 이름과 요청 프롬프트의 공백·줄바꿈을 보존합니다. ID, 검사 키, 정책·평가자 코드, 심각도와 승인 여부는 기존 정규화 규칙을 따릅니다. 필수 검사 키 또는 공백뿐인 프롬프트가 없는 행은 기존처럼 건너뛰고 결과에 표시합니다. 나머지 행을 원자적으로 한 번에 적용한다는 의미는 아닙니다.

가져오기는 표시된 파일의 헤더, 모든 행의 열 수·버전, 인코딩을 먼저 확인합니다. 표시된 파일의 텍스트는 유효한 UTF-8이어야 하며 데이터베이스에서 지원하지 않는 NUL 문자는 허용하지 않습니다. 알 수 없는 버전이나 잘못된 인코딩은 어떤 팩·검사도 수정하기 전에 거부합니다. CSV 파일은 최대 8 MiB이며, raw 또는 multipart 전송 모두 초과 입력을 저장 전에 거부합니다. multipart 전송 전체에는 파일 크기 외에 1 MiB의 형식 오버헤드 한도가 있습니다.

`vibe_probe_csv_format` 열이 없는 기존 CSV도 가져올 수 있습니다. 기존 파일의 열 생략, 양끝 공백 정리와 행 건너뛰기 동작을 유지하며, 작은따옴표나 인코딩처럼 보이는 접두사를 임의로 제거하지 않습니다.

CSV와 수동 프롬프트 편집에서 표현하지 않는 기존 팩의 버전·활성 상태, 검사의 실행 파라미터는 그대로 유지합니다. 기존 생성자와 생성 시각, 파일에 없는 검사도 보존합니다. 새 팩은 기존 기본값인 `v1`·활성 상태로 생성하고, 새 검사의 실행 파라미터는 빈 객체입니다. CSV에 포함된 이름·프롬프트·대상·위험 태그 등의 편집은 계속 적용합니다. 전체 팩·검사를 관리하는 기존 저장 경로는 명시적인 메타데이터 교체 동작을 유지합니다.
