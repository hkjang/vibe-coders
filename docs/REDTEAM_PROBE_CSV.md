# Probe CSV 편집과 가져오기

내보내기는 UTF-8 BOM이 있는 CSV입니다. 기존 13개 열 뒤에 `vibe_probe_csv_format` 열이 붙으며, 모든 데이터 행의 값은 `probe-v1`입니다. 이 열과 헤더를 유지하세요. 열 순서는 바꿀 수 있습니다.

일반 프롬프트는 셀에서 바로 편집할 수 있습니다. 수식으로 해석될 수 있는 값, 맨 앞의 작은따옴표, 공백·제어 문자, 예약된 접두사가 포함된 일부 텍스트는 `vibe-text-v1:` 뒤의 JSON 문자열로 표시합니다. 예를 들어 실제 프롬프트 `=1+1`은 셀 값 `vibe-text-v1:"=1+1"`로 표시됩니다. `\r`, `\n`, `\t`는 각각 원래의 CR, LF, 탭으로 복원됩니다. 인코딩된 셀을 편집할 때에는 JSON 문자열 안의 내용을 바꾸세요. 일반 텍스트로 셀 전체를 교체해도 되며, 일반 셀의 작은따옴표는 그대로 저장됩니다. 실제 데이터가 예약 접두사로 시작하면 JSON 문자열 안에 넣어 명시적으로 표현합니다.

`target_types`와 `risk_tags`는 보통 `provider|model`처럼 `|`로 구분합니다. 항목 자체에 `|`, 빈 항목 또는 양끝 공백이 있으면 `vibe-list-v1:["literal|pipe",""," leading "]`처럼 JSON 문자열 배열로 표시하여 항목을 보존합니다.

표시된 형식에서는 팩 이름과 요청 프롬프트의 공백·줄바꿈을 보존합니다. ID, 검사 키, 정책·평가자 코드, 심각도와 승인 여부는 기존 정규화 규칙을 따릅니다. 필수 검사 키 또는 공백뿐인 프롬프트가 없는 행은 기존처럼 건너뛰고 결과에 표시합니다. 적용 가능한 나머지 행은 아래의 트랜잭션 규칙에 따라 함께 저장합니다.

가져오기는 표시된 파일의 헤더, 모든 행의 열 수·버전, 인코딩을 먼저 확인합니다. 표시된 파일의 텍스트는 유효한 UTF-8이어야 하며 데이터베이스에서 지원하지 않는 NUL 문자는 허용하지 않습니다. 알 수 없는 버전이나 잘못된 인코딩은 어떤 팩·검사도 수정하기 전에 거부합니다. CSV 파일은 최대 8 MiB이며, raw 또는 multipart 전송 모두 초과 입력을 저장 전에 거부합니다. multipart 전송 전체에는 파일 크기 외에 1 MiB의 형식 오버헤드 한도가 있습니다.

`vibe_probe_csv_format` 열이 없는 기존 CSV도 가져올 수 있습니다. 기존 파일의 열 생략, 양끝 공백 정리와 행 건너뛰기 동작을 유지하며, 작은따옴표나 인코딩처럼 보이는 접두사를 임의로 제거하지 않습니다.

CSV와 수동 프롬프트 편집에서 표현하지 않는 기존 팩의 버전·활성 상태, 검사의 실행 파라미터는 그대로 유지합니다. 기존 생성자와 생성 시각, 파일에 없는 검사도 보존합니다. 새 팩은 기존 기본값인 `v1`·활성 상태로 생성하고, 새 검사의 실행 파라미터는 빈 객체입니다. CSV에 포함된 이름·프롬프트·대상·위험 태그 등의 편집은 계속 적용합니다. 전체 팩·검사를 관리하는 기존 저장 경로는 명시적인 메타데이터 교체 동작을 유지합니다.

승인은 팩 위험도가 `high`·`critical`이거나 `requires_approval=true`인 경우에 필요합니다. `low`·`medium`은 위험도만으로 승인을 강제하지 않습니다. CSV의 명시적인 승인 설정은 이 기준 안에서 적용하며, 승인 필드가 없는 수동 프롬프트 편집·이전 CSV 행은 기존 `승인 필요` 설정을 해제하지 않습니다. 위험도 판정과 별개로 MCP 도구 대상은 계속 시뮬레이션만 수행합니다.

가져오기는 파일 전체를 먼저 해석한 뒤 팩·검사 변경과 감사 기록을 하나의 데이터베이스 트랜잭션으로 저장합니다. 행 저장이나 감사 기록이 실패·무시되면 성공으로 응답하지 않으며, 해당 트랜잭션의 앞선 변경도 남기지 않습니다. 응답을 받지 못한 경우에는 이미 커밋되었을 가능성이 있으므로 현재 목록을 확인한 뒤 명시적으로 다시 시도하세요. 기존의 중복 검사 ID 마지막 행 반영, 팩 첫 유효 행 반영과 건너뛴 행 집계는 유지합니다.


## 적용 전 변경 비교 API

`POST /admin/redteam/probe-packs/import-review`에 CSV를 보내면 팩·검사별 생성/수정/변경 없음과 전체 변경 전후 값을 읽기 전용으로 반환합니다. 이 경로는 기본 팩을 생성하거나 가져오기 감사 기록을 쓰지 않습니다. 기존 `admin:write`에 더해 `admin:read`도 필요합니다. CSV에 없는 실행 파라미터와 생성자 정보는 응답에 포함하지 않습니다.

검토에는 파일 최대 8 MiB, 데이터 행 최대 10,000개, 관련 기존 레코드 텍스트 합계 최대 32 MiB 한도가 적용됩니다. 페이지 응답의 JSON도 최대 32 MiB입니다. 초과하면 일부 내용으로 대체하지 않고 `413 redteam_import_review_limit`로 거부하므로 파일을 나누어 검토하세요. `offset`은 0부터, `limit`은 1~100(기본 50)입니다. 첫 응답의 `revision`을 큰따옴표로 감싸 `If-Match` 헤더에 넣어 다음 페이지를 요청합니다. 모든 페이지는 같은 CSV 바이트를 다시 보내야 하며, 변경 전 상태가 달라졌으면 `409`로 거부합니다. 순서는 팩 ID, 검사 ID 각각의 정렬 순서이며 중복 검사 ID의 최종 값은 마지막 행, 팩은 첫 유효 행을 따릅니다. 집계의 `imported_cases`는 중복을 포함한 적용 대상 행 수이고 `total_items`는 고유 팩과 검사의 합계입니다.

사용자가 비교 내용을 확인한 뒤 동일한 CSV 바이트와 `If-Match: "<revision>"`으로 `PUT /admin/redteam/probe-packs/import`를 호출합니다. 적용 직전에 데이터베이스 쓰기 잠금을 얻고 파일·계정·세션·팀·역할·권한·관련 저장 내용/갱신 시각을 다시 검사합니다. 다르면 `409 redteam_import_review_changed`로 거부하고 새 검토를 요구합니다. 같은 세션의 토큰 갱신만으로는 검토가 무효가 되지 않습니다. 변경과 감사 기록은 원자적으로 저장합니다.

이 버전 값은 상태 충돌 검사 값이며 비밀 승인 토큰이나 유효 기간이 있는 예약이 아닙니다. 검토 중 다른 관리자의 편집을 막지 않습니다. 적용 전 저장 오류로 롤백된 경우에는 같은 검토를 명시적으로 재시도할 수 있지만, 응답이 유실되면 먼저 현재 목록을 확인하세요. 자동 재시도나 기존 `POST /import`로의 자동 대체를 하면 안 됩니다. 기존 `POST` API는 검토 없는 호환 경로로 유지하며 새 검토 전용 행 수 한도를 추가하지 않습니다. 화면의 CSV 가져오기도 이 검토·적용 경로를 사용하며, 지원하지 않는 서버에서는 적용하지 않습니다.


## 화면에서 변경 내용을 확인하고 적용하기

`/app/redteam`의 **대상·검사 묶음 → CSV 가져오기**에서 파일을 선택하세요. 파일 확인 뒤 변경 전후 비교 창이 열립니다. 이 단계에서는 저장하지 않습니다. 생성·수정·변경 없음 집계와 건너뛴 행 수를 확인하고, **이전 변경/다음 변경**으로 전체 비교 내용을 읽을 수 있습니다. 변경 없음은 표시된 편집 필드 기준이며, 적용하면 처리 시각과 감사 기록은 갱신됩니다.

**원본 파일을 적용합니다** 확인란을 선택한 뒤 **변경 내용 적용**을 눌러야 저장합니다. 페이지를 바꾸거나 다시 검토하면 확인란이 초기화됩니다. 화면에서 민감정보로 판정한 값은 가려 표시하지만 파일의 원문은 그대로 전송합니다. 취소·닫기에는 입력 폐기 확인을 거치며, 저장 중에는 중복 적용이나 닫기를 막습니다.

다른 관리자가 내용을 바꿨거나 적용 결과가 불확실하면 기존 확인을 폐기합니다. 현재 목록을 확인한 뒤 **현재 내용으로 다시 검토**하고 새로 확인하세요. 계정·세션·관련 권한·화면 조건이 바뀌면 진행 중 읽기/적용 요청과 검토 상태를 폐기하며, 이전 요청의 늦은 응답을 새 화면의 성공으로 표시하지 않습니다. 요청 취소는 서버에서 이미 저장된 변경을 되돌리지 않으므로 새 화면에서 현재 목록을 확인하세요.
