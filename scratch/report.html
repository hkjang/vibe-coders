1. 프레임워크 정의 및 세부 구성 요소 (Framework & Components)

1.1 기능, 역할, 비즈니스 가치 분류

AI Proxy Gateway의 설계 철학은 단순한 네트워크 트래픽 중계를 넘어, AI 도구 통합 관리와 기업 규정 준수(Compliance)의 교차점에 위치합니다. 본 시스템의 기여도를 세 가지 축으로 분류하여 정의합니다.

1. 기능 (Features)

시스템이 기술적으로 제공하는 직접적인 동작 메커니즘을 의미합니다.

  • Reverse Proxy 라우팅 및 SSE 스트리밍 중계
  • 사용자 및 팀 단위 실시간 비용/토큰 집계
  • XView 실시간 APM 트랜잭션 분산 산점도
  • 지능형 자동 라우팅 및 Failover 아키텍처
  • MCP 정책 제어 및 툴 호출 차단 엔진

2. 역할 (Roles)

본 시스템이 인프라 거버넌스와 보안 아키텍처에서 수행하는 임무를 의미합니다.

  • 사용자 애플리케이션과 외부 AI 서비스 간의 단일 관문(Gatekeeper)
  • 모든 AI 호출 이력에 대한 투명한 기록관(Auditor)
  • 트랜잭션 지연 원인 분석가 및 해설가 (XView & Explain)
  • 비정상적 비용 유출을 조기에 진압하는 수호자(Guard)

3. 비즈니스 가치 (Values)

기능과 역할을 통해 기업 경영, 재무 안정성 및 보안 규제 대응력에 가져다주는 정량적·정성적 이점을 의미합니다.

비즈니스 가치 부문 설명 및 효과
재무 리스크 예방 (정량적) 사용자별 임계치를 설정하여 통제 불가능한 API 과금 폭주 예방. Anomaly Detector 작동으로 1분 내 탐지 차단.
기업 자산 보호 (정성적) 데이터 및 사내 민감 사양이 외부 공용 모델 학습에 활용되거나 무단 유출되는 것을 프록시 단 필터링으로 차단.
인프라 가용성 보장 Upstream Provider 장애 시 우회 경로로 Failover하여, 업무 조직의 업무 중단 비용(Downtime Cost) 발생 방지.

1.2 시스템 세부 구성 요소 분석 (System Component Breakdown)

본 게이트웨이는 엔터프라이즈 거버넌스 및 AI APM 요건을 충족하기 위해 유기적으로 연동되는 18대 핵심 서브시스템으로 구성되어 있습니다.

① 3계층 세션 추론 엔진

클라이언트가 명시적 세션을 제공하지 않더라도 API 트래픽 내의 지연 간격 및 사용자 아이덴티티를 비교하여 Work Session(최상위 작업 브랜치 단위) - Task Session(유사 태스크 단위) - Request(개별 요청)의 다차원 세션으로 추론 및 연결합니다. 특히 서버 재기동 시에도 세션이 유실되지 않도록 데이터베이스(inferred_sessions)와 실시간 연동해 영속 추론 상태를 자동 복구하며 주기적 GC 청소를 지원합니다.

② 지능형 비용/대기시간 라우터

업스트림 공급자들의 응답 지연 시간, 가용성 통계, 토큰 단가 데이터를 바탕으로 최적의 비용-효율적 모델 제공 서버를 실시간 결정하고, 장애 발생 시 연쇄적인 Transport Failover 우회를 처리합니다. 특히 클라이언트가 특정 업스트림을 강제 고정(Pinned)한 상태에서도 auto/auto-reasoning 별칭 모델명을 감지하여 실시간 최적 모델로 동적 리라이트(Rewrite)하는 연동 메커니즘을 지원합니다.

③ 사내 거버넌스 & 룰 러너

중앙 관리자가 정의한 정책에 의거하여 비인가 도구 호출, 민감 인자(Secret Key 등) 누출을 차단하며, 백그라운드 Governance Runner 워커가 비정상 패턴 및 초과 과금 위험을 선제 차단합니다. 인증 활성화 시 신규 API Key 및 static 환경변수 기인 키에 대해 기본 역할(Role)별 스코프(chat, embeddings, models 등)를 안전하게 자동 위임·보완하는 호환성 정책 엔진을 탑재했습니다. 특히, 어드민 UI 내에서 관리자별 소속 팀 수정, API Key 개별 권한 스코프 편집 모달 및 super_admin 전용 키 영구 삭제(Hard Delete) 기능을 온전히 제공합니다.

④ VCS 트래픽 기반 이벤트 추론기

VCS(Git) 웹훅의 부재 혹은 오프라인 제약 속에서도 LLM에 유입되는 개발 트래픽(프롬프트 내용 및 쉘 명령)을 스캔하여 git commit, git push 이벤트를 비동기로 역추론해 개발 이력 타임라인을 매핑합니다.

⑤ 자동화된 성능 벤치마킹 모듈

사내에 등록된 모든 LLM 모델 및 커스텀 로컬 업스트림에 대하여 일정한 워크로드를 인가하고 응답 가속도, TTFT(첫 토큰 소요 시간), TPS를 정기 측정하여 모델 신뢰성 가중치 맵을 갱신합니다.

⑥ 감사 및 설명성 데이터 스토어

SQLite 및 PostgreSQL 다중 호환 스키마 상에 토큰 사용량과 피드백 라벨을 집계하고, XView APM 대시보드의 데이터 닷을 분석하여 병목 원인을 자연어 해설로 설명(Explain)해 주는 감사 스토어입니다.

⑦ 위임형 스코프 거버넌스 & API Key 생명주기 관리자

어드민 UI 내에서 API Key의 개별 세부 권한을 실시간 제어할 수 있는 Scopes Editor를 연동하여, super_admin의 권한으로 API Key를 안전하게 영구 폐기(?hard=1)하고, 권한이 부여되지 않은 구형 키의 비정상 차단 상태(scope_denied)를 백그라운드 마이그레이션 및 기본 롤 권한 자동 상속 메커니즘을 통해 유기적으로 자동 조율합니다.

⑧ 사용자-팀 소속 동적 매핑 엔진

다중 테넌트(Multi-tenant) 환경에서 사용자를 특정 팀에 유연하게 바인딩하고, 관리자 권한 수준(team_admin 등)에 따라 자신의 소속 팀 정보 및 관련 API Key에만 접근하도록 필터링해 정보 노출 및 권한 상승(Privilege Escalation) 위험을 원천 차단합니다.

⑨ 명시적 파이프라인 및 단계별 미들웨어 (`PipelineStep`)

게이트웨이에 유입되는 API 호출 라이프사이클을 PipelineStep 인터페이스로 구조화하여, 각 단계(인증, 속도 제한, 룰 검사, 라우팅, 로깅)가 순차 미들웨어 체인처럼 동작하도록 설계함으로써 유지보수성과 확장성을 대폭 강화한 리팩토링 아키텍처입니다.

⑩ 다차원 비용 할당 및 정산 모듈

전사 API 트래픽을 Git 리포지토리, 브랜치, 프로젝트, 서비스, 코스트 센터 단위로 세분화하여 토큰 소모량과 원화 환산 비용을 즉각 연동하고, 사용자별 주간 리포트를 자동 적재하여 클라우드 자산의 정량적 회계 정산 프로세스를 수립합니다.

⑪ 엔터프라이즈 프롬프트 관리 및 회귀 게이트 (Prompt CI Gate)

골든 프롬프트 회귀 테스트 게이트를 통해 배포 전 품질 규격을 CI 상에서 자동 계량 검증하며, 실험-검증-배포로 이어지는 프롬프트 라이프사이클 승격 단계와 중앙 집중형 AI Task 템플릿 관리 기능을 결합하여 전사적 프롬프트 자산화를 제공합니다.

⑫ 능동적 보안 위험도 및 안심 통제 계층 (Ops Risk Score)

실시간 프롬프트 인젝션 차단 및 MCP 도구에 대한 정밀 권한 등급 분석(Access-class Risk Grading), 가용성 기반 업스트림 SLO 실시간 통계 및 월말 비용 예측 알고리즘을 조합하여 시스템의 전반적인 운영 위험 점수(Operational Risk Score)를 산출 및 통제합니다.

⑬ 폐루프 자동 라우팅 강화 학습 및 DW 적재 (DW Staging)

실제 LLM 호출 처리 결과(TTFT, 성공/실패 여부, 단가)의 피드백 루프를 통해 차기 최적 경로를 능동 수정하는 폐루프 강화 학습 라우터 및 대규모 아카이빙을 위한 분석용 DW 스태이징 롤업 테이블 연동 기능을 내장했습니다.

⑭ 자연어 기반 SQL 번역 및 샌드박스 실행 엔진 (Text2SQL Pipeline)

vibe/text2sql-* 가상 모델 요청을 실시간 인터셉트하여, 사용자의 자연어 질의를 고효율 SQL 쿼리로 자동 변환하고 읽기전용 DB 커넥션을 통해 결과를 실행/필터링/마스킹하여 반환하는 가상 모델 지능형 컴파일러입니다.

⑮ 장기 분석 및 클릭하우스 OLAP 스토어 (ClickHouse OLAP Sink)

게이트웨이를 거쳐가는 대규모 감사 로그 및 Text2SQL 실행 이력 등의 정밀 팩트 데이터를 분산 처리하여 컬럼형 OLAP인 ClickHouse 데이터베이스로 실시간 및 스케줄링 배치 적재하여 장기 대용량 통계 분석 성능을 극대화합니다.

⑯ AI 보험(SLA-claims Ledger) 및 에러 버짓 분석

API 호출 중의 4xx/5xx 에러, 응답 지연, failover 우회 작동을 에러 버짓 소모(Claim)로 자동 식별 및 집계하여, 등록된 스코프별 SLA 약정 대비 가용율(SLA Target) 및 Burn Rate를 다차원 스코어링하는 서비스 안정성 회계 모듈입니다.

⑰ 프롬프트 탄소 배출량 추정기 (Prompt Carbon Estimator)

사용 토큰량 및 모델 가중치를 기반으로 전력 소모량(Wh)을 계량화하고, 데이터센터 PUE와 전력 생산 탄소 강도(gCO2e)를 조율 연산하여 AI 서비스 운용에 따른 탄소배출 기여도를 투명하게 보고하는 ESG 통계 엔진입니다.

⑱ 시맨틱 벡터 캐싱 계층 (Chat Semantic Cache)

단순 텍스트 일치 기반의 캐시 처리를 넘어, 질문 프롬프트를 실시간 벡터 임베딩화하고 코사인 유사도 연산을 적용하여 의미론적으로 유사한(Near-duplicate) 대화 요청에 대해서도 캐시 히트를 제공하는 지능형 캐시 계층입니다.

2. 지능형 라우팅 및 고가용성 우회 (Routing & Failover)

2.1 사용자 핀 및 모델 기반 자동 라우팅 (Features)

게이트웨이는 클라이언트 요청의 메타데이터와 사전에 등록된 업스트림 프로바이더 설정값들을 대조하여 실시간으로 최적의 업스트림 경로를 확정합니다.

라우팅 선택 시퀀스 (`selectProvider`)

  1. 명시적 지정: 클라이언트가 HTTP 헤더 X-Proxy-Provider 또는 쿼리 매개변수 ?provider=에 값을 싣는 경우 이를 최우선 매핑합니다.
  2. 와일드카드 패턴 자동 라우팅: 위의 명시적 지정이 없고 model 필드가 지정된 경우, 프로바이더 설정 내의 와일드카드 문자열(예: gpt-4*, claude-3*)과 사용자 요청 모델명을 대조하여 자동으로 프로바이더를 찾아갑니다. (`matchGlob` 매칭 알고리즘 활용)
  3. 기본값 처리: 두 조건 모두 불충족 시, 서버 실행 환경에 기본 등록된 UPSTREAM_PROVIDER로 라우팅을 폴백 처리합니다.

2.2 다중 업스트림 Failover 장애 복원력 (Roles & Values)

단일 퍼블릭 LLM API 벤더의 service 장애 사태에도 사내 AI service 활용 프로세스는 중단되어서는 안 됩니다. 본 시스템은 전송 계층 수준의 자동 복원력(Transport-level Failover)을 수행합니다.

[동작 원리] Failover 연쇄 감지 및 교차 밸런싱

1. 요청 시점에 primary 프로바이더 외에 동일 모델 패턴을 service할 수 있는 다른 활성 프로바이더 후보군 목록(failoverCandidates)을 실시간으로 구축합니다.
2. primary 전송 시도 중 타임아웃, 커넥션 에러, EOF 에러 등이 감지되면, 루프를 돌며 후보 프로바이더들에게 순차적으로 재전송(dialUpstream)합니다.
3. 재전송에 성공하면 응답 헤더에 X-Failover-From: [원래실패한프로바이더]를 주입하여 통계상 장애 전이 지표를 축적하고, 사용자에게는 중단 없는 AI 결과를 반환합니다.

3. XView 트랜잭션 분포도 및 설명성 제공 (APM & XView)

3.1 XView 트랜잭션 분산 산점도 (Features & Roles)

사내 인프라 관리자 및 정보보안 담당자는 **XView 대시보드**를 통해 유입되는 트랜잭션의 상세 처리 양상을 한눈에 관측할 수 있습니다.

XView 시각화 주요 매커니즘

  • X축(시간)과 Y축(지연시간) 매핑: 가로축은 트랜잭션이 수행된 절대 시간, 세로축은 전체 응답 시간(Latency) 또는 첫 번째 토큰이 수신되기까지 걸린 시간(First Chunk Latency)을 매핑하여 분산도를 플로팅합니다.
  • 선형 / 로그 스케일링 필터: 짧은 호출(100ms)과 긴 호출(60s)이 극명히 나뉘는 LLM 통신 특성을 보완하기 위해 세로축 스케일을 log 스케일로 압축하여 가독성을 강화할 수 있습니다.
  • 트랜잭션 카테고리 색상 구분: 사용된 토큰 및 연산 비용의 수준에 따라 complex (임계치 4000토큰 초과 상위 10% 트랜잭션), standard, light 상태로 점의 컬러를 다르게 마킹하여 이상 현상을 한눈에 파악합니다.

3.2 XView 설명성 보기 (Explainability View - Values)

특정 트랜잭션이 유독 긴 처리 시간을 보였거나, 비정상적 경로로 라우팅되었을 경우 담당자가 이에 대해 **합리적인 추적 해설(Explainability)**을 얻을 수 있습니다.

[기술 설계] XView 설명 모달 (internal/proxy/admin_explain.go)

특정 닷(Dot)을 클릭했을 때 호출되는 설명 엔진은 해당 요청의 상세 기록을 분석하여 다음을 자연어로 설명합니다:
- 캐시 처리 여부: 임베딩 캐시 히트로 인한 지연 시간 절감 내역.
- 라우팅 이유(RouteReason): 클라이언트 헤더 주입으로 고정되었는지, 혹은 모델 패턴 와일드카드 매칭에 따라 게이트웨이가 동적 결정을 내렸는지 기술.
- Failover 이력: 어떤 백업 프로바이더를 타고 최종 응답을 획득했는지와 장애 런타임 추적 데이터 해설.
- 보안 검출 사항: MCP 정책 매칭 이력, 툴 루프 차단 기록 등 통제 근거 명시.

4. 데이터베이스 설계 및 호환성 (Database & SQL)

4.1 핵심 데이터 모델 및 스키마 관계

엔터프라이즈 레벨의 안정성을 보장하기 위해 데이터베이스 스키마는 외래 키 관계를 맺고 있으며, 성능 향상을 위한 적절한 인덱스(Index)가 구성되어 있습니다.

테이블 명 주요 필드 설명
`api_keys` `id` (PK), `key_hash`, `owner`, `team`, `status` 사내 프록시 접속 키 정보 및 소속 팀 관리
`request_logs` `id` (PK), `api_key_id` (FK), `model`, `latency_ms` 프록시 중계 상세 트래픽 및 오디트(Audit) 정보
`token_usage` `id` (PK), `request_id` (FK), `total_tokens`, `estimated_cost` 원화(KRW) 환산 비용 및 사용 토큰 저장
`llm_evaluations` `id` (PK), `request_id` (FK), `score`, `passed` AI 답변 분석 결과에 대한 자동 평가 통계
`llm_feedback` `id` (PK), `request_id` (FK), `rating`, `label` 실제 사용자가 제출한 AI 성능 평가 피드백

4.2 PostgreSQL 마이그레이션 호환성 패치

데이터베이스 스토어를 SQLite에서 PostgreSQL로 교체할 때 발생하는 문법 및 작동 방식 상의 차이점을 분석하여 아래와 같이 개선하였습니다.

1. BLOB 데이터 타입 자동 치환

SQLite의 `BLOB` 타입은 PostgreSQL에서 지원되지 않습니다. 스키마 마이그레이션 DDL을 실행할 때, 드라이버가 PostgreSQL인 경우 정규식 (?i)\bblob\b을 적용하여 자동으로 BYTEA 데이터 타입으로 실시간 보정 후 실행하도록 구현하여 테이블 생성 실패 오류를 완벽히 해결했습니다.

2. PostgreSQL GROUP BY 42803 에러 영구 패치

LLM 관측 및 피드백 라벨 집계 쿼리 실행 시, PostgreSQL 환경에서 GROUP BY에 없는 원본 컬럼 f.label을 ORDER BY에 직접 사용하여 sqlstate 42803 기동 실패 오류가 발생하던 부분은 SELECT 절에 AS label 별칭을 부여하고 정렬 기준을 해당 가상 컬럼 별칭으로 교체하여 에러를 영구 배제하였습니다.

5. 에이전트 엔지니어링 분석 및 차세대 보안 (Agent Analytics & Security)

5.1 3계층 세션 추론 엔진 (3-Tier Session Inference)

단순 개별 API 호출 로그 적재 방식을 넘어, 개발자의 의도적인 워크플로우를 분석하기 위해 Work Session(개발자 작업) - Task Session(개별 작업 태스크) - Request(개별 요청)의 3계층 구조로 데이터를 구조화하고 자동 추론합니다.

  • Work Session (최상위): 개발자가 리포지토리나 특정 브랜치에서 수행하는 하나의 전체 개발 프로젝트 단위 세션.
  • Task Session (중간): "에러 수정", "테스트 코드 생성", "리팩토링" 등 구체적인 태스크 단위로 구분된 작업 세션. 프롬프트 간의 유사도와 시간차(time gap)를 계산하여 동일 태스크 여부를 판정합니다.
  • Request (최하위): 실제 Gateway를 거쳐간 개별 API 트랜잭션 호출 로그.

5.2 에이전트 분석 및 프롬프트 핑거프린트 (Agent & Prompt Analytics)

에이전트 거버넌스 및 자원 소모의 투명성을 극대화하기 위해 에이전트별 성능 및 비용 통계를 정밀 추적합니다.

  • Agent Analytics: Cursor, Roo Code 등 사내에서 활용되는 개발 에이전트 종류를 탐지하고, 에이전트별 도구(Tools) 호출 빈도 및 연산 비용을 지표화합니다.
  • Prompt Fingerprints: AI 요청에서 빈번하게 사용되는 프롬프트의 특징적 핑거프린트(템플릿 구조)를 추출하여, 어떤 프롬프트가 과도하게 반복되고 토큰을 낭비하고 있는지 분석합니다.

5.3 지식 베이스(Knowledge Base) & MCP 업스트림 게이트웨이

개발 인프라 환경에서 모델에 대한 지식 주입 및 환경 결합을 단순화하기 위해 게이트웨이 단에서 프레임워크를 직접 연동합니다.

  • 지식 베이스(RAG) 엔진: 프록시 수준에서 RAG를 적용하여, 사내 개발 표준 가이드라인이나 보안 규정을 AI 호출 시 실시간으로 컨텍스트에 바인딩하여 안전한 답변을 유도합니다.
  • MCP Upstream Gateway: Model Context Protocol(MCP) 서버군을 게이트웨이로 중계 관리하여, 다수의 에이전트 클라이언트가 사내 인트라넷 도구에 안전하고 효율적으로 접속하도록 제어합니다.

5.4 지능형 라우팅 (Intelligent Routing) & 통합 인증 (Enterprise Auth)

동적 인프라 환경에서 연산 효율성을 높이고 보안 경계를 명확히 하기 위해 강화된 라우팅 및 인증 메커니즘을 제공합니다.

  • 지능형 라우팅: 각 업스트림 공급자(Provider)의 실시간 상태 지표(Latency, Success Rate) 및 비용 효율성을 종합 분석하여, 런타임 최적의 업스트림으로 호를 동적 전환하는 Intelligent Routing 엔진을 내장했습니다.
  • 엔터프라이즈 통합 인증: Gateway 인입 시점의 API Key 유효성 정밀 검증, 어드민 권한 제어 및 클라이언트 그룹 식별을 통해 전사 다중 테넌트(Multi-tenant) 통신 보안을 완성합니다.

5.5 사내 보안 거버넌스 및 규칙 실행기 (Governance & Runner)

비정상 비용 소모와 보안 정책 위반을 프록시 레벨에서 선제 방어하기 위한 거버넌스 계층입니다.

  • Governance Rule: 특정 툴 차단, 보안 민감 인자 검열, 사용 가능 범위 통제 등 상세 규칙을 중앙 어드민에서 정의하고 일괄 전파합니다.
  • Governance Runner 워커: 백그라운드에서 주기적으로 도구 사용 기록 및 요금 한도 위반 여부를 스캔하여, 위반 사항 발생 시 API 호출을 즉각 중지하거나 강제 토큰을 차단합니다.
  • 도구별 IP 제한 필터링: 민감 툴(예: 시스템 명령 실행) 감지 시 클라이언트 IP 대역의 VPN 소속 여부를 사전 검증합니다.

6.2 운영 통제 및 이중화 구성

Gateway를 사내 이중화 서비스로 구성하여 무장애 운영을 실현하기 위한 구성 기준입니다.

프로덕션 고가용성 요건

  • 환경 변수 일치: 모든 게이트웨이 파드(Pod) 또는 인스턴스는 동일한 GATEWAY_SECRET(32바이트 암호화 키)을 소유해야 합니다. 불일치 시 인스턴스 간 키 해독 불가로 인한 에러가 발생합니다.
  • PostgreSQL 클러스터: 로드 밸런서 하단에 여러 대의 게이트웨이가 공통된 외부 PostgreSQL 서비스를 이용하도록 구성하여 데이터 일치성을 보장합니다.
  • 헬스체크 프로브 구성: L7 로드 밸런서나 쿠버네티스의 Readiness/Liveness 프로브 대상을 /ready 경로로 매핑하여 DB 접속이 끊긴 인스턴스를 실시간 자동 격리합니다.

6.3 장애 복구 절차 (Runbook)

① 전체 게이트웨이 서비스 즉각 잠금 (Kill-Switch)

중대한 보안 결함이나 악성 트래픽이 사내 네트워크 전체에 식별될 경우, 아래의 어드민 잠금 API를 사용하여 모든 /v1 호출을 1초 내에 전면 차단합니다. 

curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"disabled":true, "reason":"내부 보안 등급 상향으로 인한 임시 차단"}' \
  http://localhost:8080/admin/kill-switch

② 데이터 백업 및 복구 (PostgreSQL 환경)

데이터베이스 유실 사고 방지를 위해 아래의 원격 데이터 백업/복구 절차를 정기적으로 수행할 것을 권장합니다. 

# 백업 명령어
pg_dump -h [VM_IP_OR_DNS] -p 5432 -U gateway_user -d gateway_db > backup_gateway_$(date +%Y%m%d).sql

# - 복구 명령어
psql -h [VM_IP_OR_DNS] -p 5432 -U gateway_user -d gateway_db < backup_gateway_YYYYMMDD.sql
본 문서의 지식재산권은 IT AI 추진단에 있으며, 정보 보안 등급 분류에 따라 대외비로 관리됩니다.
