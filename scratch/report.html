1. 프레임워크 정의 (Features, Roles, and Values)

AI Proxy Gateway의 설계 철학은 단순한 네트워크 트래픽 중계를 넘어, AI 도구 통합 관리와 기업 규정 준수(Compliance)의 교차점에 위치합니다. 본 시스템의 기여도를 세 가지 축으로 분류하여 정의합니다.

1. 기능 (Features)

시스템이 기술적으로 제공하는 직접적인 동작 메커니즘을 의미합니다.

  • Reverse Proxy 라우팅 및 SSE 스트리밍 중계
  • 사용자 및 팀 단위 실시간 비용/토큰 집계
  • XView 실시간 APM 트랜잭션 분산 산점도
  • 지능형 자동 라우팅 및 Failover 아키텍처
  • MCP 정책 제어 및 툴 호출 차단 엔진

2. 역할 (Roles)

본 시스템이 인프라 거버넌스와 보안 아키텍처에서 수행하는 임무를 의미합니다.

  • 사용자 애플리케이션과 외부 AI 서비스 간의 단일 관문(Gatekeeper)
  • 모든 AI 호출 이력에 대한 투명한 기록관(Auditor)
  • 트랜잭션 지연 원인 분석가 및 해설가 (XView & Explain)
  • 비정상적 비용 유출을 조기에 진압하는 수호자(Guard)

3. 비즈니스 가치 (Values)

기능과 역할을 통해 기업 경영, 재무 안정성 및 보안 규제 대응력에 가져다주는 정량적·정성적 이점을 의미합니다.

비즈니스 가치 부문 설명 및 효과
재무 리스크 예방 (정량적) 사용자별 임계치를 설정하여 통제 불가능한 API 과금 폭주 예방. Anomaly Detector 작동으로 1분 내 탐지 차단.
기업 자산 보호 (정성적) 데이터 및 사내 민감 사양이 외부 공용 모델 학습에 활용되거나 무단 유출되는 것을 프록시 단 필터링으로 차단.
인프라 가용성 보장 Upstream Provider 장애 시 우회 경로로 Failover하여, 업무 조직의 업무 중단 비용(Downtime Cost) 발생 방지.

2. 지능형 라우팅 및 고가용성 우회 (Routing & Failover)

2.1 사용자 핀 및 모델 기반 자동 라우팅 (Features)

게이트웨이는 클라이언트 요청의 메타데이터와 사전에 등록된 업스트림 프로바이더 설정값들을 대조하여 실시간으로 최적의 업스트림 경로를 확정합니다.

라우팅 선택 시퀀스 (`selectProvider`)

  1. 명시적 지정: 클라이언트가 HTTP 헤더 X-Proxy-Provider 또는 쿼리 매개변수 ?provider=에 값을 싣는 경우 이를 최우선 매핑합니다.
  2. 와일드카드 패턴 자동 라우팅: 위의 명시적 지정이 없고 model 필드가 지정된 경우, 프로바이더 설정 내의 와일드카드 문자열(예: gpt-4*, claude-3*)과 사용자 요청 모델명을 대조하여 자동으로 프로바이더를 찾아갑니다. (`matchGlob` 매칭 알고리즘 활용)
  3. 기본값 처리: 두 조건 모두 불충족 시, 서버 실행 환경에 기본 등록된 UPSTREAM_PROVIDER로 라우팅을 폴백 처리합니다.

2.2 다중 업스트림 Failover 장애 복원력 (Roles & Values)

단일 퍼블릭 LLM API 벤더의 서비스 장애 사태에도 사내 AI 서비스 활용 프로세스는 중단되어서는 안 됩니다. 본 시스템은 전송 계층 수준의 자동 복원력(Transport-level Failover)을 수행합니다.

[동작 원리] Failover 연쇄 감지 및 교차 밸런싱

1. 요청 시점에 primary 프로바이더 외에 동일 모델 패턴을 서비스할 수 있는 다른 활성 프로바이더 후보군 목록(failoverCandidates)을 실시간으로 구축합니다.
2. primary 전송 시도 중 타임아웃, 커넥션 에러, EOF 에러 등이 감지되면, 루프를 돌며 후보 프로바이더들에게 순차적으로 재전송(dialUpstream)합니다.
3. 재전송에 성공하면 응답 헤더에 X-Failover-From: [원래실패한프로바이더]를 주입하여 통계상 장애 전이 지표를 축적하고, 사용자에게는 중단 없는 AI 결과를 반환합니다.

3. XView 트랜잭션 분포도 및 설명성 제공 (APM & XView)

3.1 XView 트랜잭션 분산 산점도 (Features & Roles)

사내 인프라 관리자 및 정보보안 담당자는 **XView 대시보드**를 통해 유입되는 트랜잭션의 상세 처리 양상을 한눈에 관측할 수 있습니다.

XView 시각화 주요 매커니즘

  • X축(시간)과 Y축(지연시간) 매핑: 가로축은 트랜잭션이 수행된 절대 시간, 세로축은 전체 응답 시간(Latency) 또는 첫 번째 토큰이 수신되기까지 걸린 시간(First Chunk Latency)을 매핑하여 분산도를 플로팅합니다.
  • 선형 / 로그 스케일링 필터: 짧은 호출(100ms)과 긴 호출(60s)이 극명히 나뉘는 LLM 통신 특성을 보완하기 위해 세로축 스케일을 log 스케일로 압축하여 가독성을 강화할 수 있습니다.
  • 트랜잭션 카테고리 색상 구분: 사용된 토큰 및 연산 비용의 수준에 따라 complex (임계치 4000토큰 초과 상위 10% 트랜잭션), standard, light 상태로 점의 컬러를 다르게 마킹하여 이상 현상을 한눈에 파악합니다.

3.2 XView 설명성 보기 (Explainability View - Values)

특정 트랜잭션이 유독 긴 처리 시간을 보였거나, 비정상적 경로로 라우팅되었을 경우 담당자가 이에 대해 **합리적인 추적 해설(Explainability)**을 얻을 수 있습니다.

[기술 설계] XView 설명 모달 (internal/proxy/admin_explain.go)

특정 닷(Dot)을 클릭했을 때 호출되는 설명 엔진은 해당 요청의 상세 기록을 분석하여 다음을 자연어로 설명합니다:
- 캐시 처리 여부: 임베딩 캐시 히트로 인한 지연 시간 절감 내역.
- 라우팅 이유(RouteReason): 클라이언트 헤더 주입으로 고정되었는지, 혹은 모델 패턴 와일드카드 매칭에 따라 게이트웨이가 동적 결정을 내렸는지 기술.
- Failover 이력: 어떤 백업 프로바이더를 타고 최종 응답을 획득했는지와 장애 런타임 추적 데이터 해설.
- 보안 검출 사항: MCP 정책 매칭 이력, 툴 루프 차단 기록 등 통제 근거 명시.

6.2 운영 통제 및 이중화 구성

Gateway를 사내 이중화 서비스로 구성하여 무장애 운영을 실현하기 위한 구성 기준입니다.

프로덕션 고가용성 요건
